# `grep` 用搜索的索引；agent 的写与搜索

M8/P5 加了工作区的全文搜索（`searchWorkspace`，[M8/P5 文档](../../M8-history-search/05-P5-search.md)，[M8 总设计](../../M8-history-search/00-M8-design.md) 4.12）：应用算的词存在侧表 `page_search` 里（`tsvector`，GIN），单元在事务里只把碰过的节点放进 `page_search_queue`，page 的后台任务在请求之外重建行；读时候选是索引的命中并上队列里准确的节点，对当前的名称与正文复查。M9 的 `grep` 用这个索引（总体设计 12.3）。留给 M9 的：

1. **`grep` 的键与候选**：
   - 索引里有什么（[M8/P5](../../M8-history-search/05-P5-search.md) 3.3）：每个活着的节点一行；标题是名称的 CJK 单字与二元组、字母与数字 3 个起的三元组、1–2 个的整词，正文是名称加正文的 CJK 二元组、三元组与整词（不收单字）；都按 `searchFold`（`shared.TitleKey` 加切罗基文的小写换成大写）折叠之后取。字母文字是 P5A 按实测定下的三元组：字母与数字的任意子串（3 个起）都取得出键，`api` 找得到 `rapid`。
   - 从正则的字面片段取键：用 `regexp/syntax` 解析，取每段必须出现的字面串（拼接里的字面量；选择、可选、可以重复零次的部分不取）：CJK 2 个字起给二元组，字母与数字 3 个起给三元组，1–2 个的只在两边必是边界时给整词；不区分大小写时折叠之后取，区分时也取折叠的键（键是超集），由正则复查。
   - 候选与读法照搜索的正文层（P5 3.5）：`page_search_hits(body_keys, title_keys)`（迁移里的函数，只读 GIN 的位图）的命中，以同一快照里数出的命中数作 `LIMIT`，并上队列里准确的节点；只带笔记本的条件连 `nodes` 与 `page_contents`，别的检查放在 `OFFSET 0` 之上：照写的连接与规划器自己的读法在 30 万页上有 5–40 秒的整表扫描。之后在 SQL 里以正则复查（正文按它的 NFC 读），路径的 glob 再筛。批量的节点（导入、后台的恢复与撤销、升级的补入、reindex 之后，建好之前）不当候选，`building` 时同样说明结果可能不全。
   - 取不出键的正则只能有界地扫：同 `MaxSearchWalk`（500 页的正文）的走查，答"继续"的游标。
   - 不进索引的部分（超过 64 个的 ASCII 字母与数字的连续串、长的 `data:` 串、一页超出约 1 MB 的词）只在节点排队时找得到；`grep` 要找它们只能不经索引地扫。
   - PostgreSQL 的正则（ARE）与 Go 的 RE2 不同：搜索的模式由同一个构造器写成两种（大小写写成简单折叠的轨道的方括号，P5 3.3）；用户写的正则在 SQL 里以哪种语义执行、怎样拒绝两边不同的写法，M9 定。
2. **agent 写完即搜**：经单元的写（含 MCP 的）以准确入队，读时当作候选、对当前的状态复查，写完立即搜得到。agent 以 `batch` 大量新建时（导入与后台的恢复、撤销以外的单元是准确的），准确的积压大过 `MaxSearchWalk` 会让罕见词的第一页为空而带游标，直到任务追上（从空建约 300 页/秒；准确的积压 1,000 页时 92 个第一页里 17 个为空，平时 7 个）。看任务的吞吐跟不跟得上，必要时让大的 `batch` 的单元以批量入队（`UnitSpec.Background`，之后带 `building`）。
3. **MCP 的 `search`**（若加）：调用同一个 `Search` 用例（动作 `page.search`、看得到的笔记本、两层、约数、`building`）。agent 要读 `count` 的种类（`exact`、`about`、`at_least`）与 `next_cursor`：第一页可能少于 `limit` 个、甚至一个也没有而带游标（走查的界线）；被隔开的单字的词（`中·国`）在没有正文键的查询里只找名称。
4. **上限**：`q` 1–256 字节、至多 8 个词、至多 64 个连续的 ASCII 字母与数字；`grep` 的正则另定上限并在上限处测试（总体设计 13.1 第 31 条）。
