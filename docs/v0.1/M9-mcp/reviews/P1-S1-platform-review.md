## 主持者的决定

负责人可以改判：

1. **`POST /register` 答 OAuth 的错误，说明是 PAT 的提示**（试用的发现，选项 b）：会走 OAuth 的客户端（Claude Code 一类）找不到元数据之后照 MCP 2025-03-26 的默认端点去源站注册，`/register` 答 400 `invalid_client_metadata`，`error_description` 就是 `/.well-known/` 的 404 的那句；只服务 POST，别的方法仍是网页的；`register` 进 `[server]`。负责人要撤回时：去掉 `e40142e8` 的处理函数、挂载、公开的模式与保留名，接受 OAuth 客户端显示网页的 405、写进文档。
2. **`/mcp` 没有令牌的 401 带同一句提示**（A 对附加问题的回答）：经按路由的 `APIConfig.NoTokenDetails`，只给没有令牌的 401；失败的令牌、REST 的 401 与 `WWW-Authenticate: Bearer` 不变。这样不走 OAuth 的客户端从 401 的说明、会走 OAuth 的从注册的错误读到同一句（试用第 4 次运行核对）。
3. **只有 `tools/call` 可以长到路由的上限**（A-M1、修复核对第一轮 F1、F2 与可选的一条）：超过 64 KiB 的请求体只在它是这个入口（照 `entryOf` 的读法：查询串解析不了时取笔记本入口的名字，`entryOf` 的 404 仍在 SDK 之前）登记了的工具的 `tools/call`，`jsonrpc` 恰好是 `"2.0"`、`id` 照写的至多 256 字节、`params._meta` 的数 float64 放得下时才过，别的答 413 `payload_too_large`，在会话令牌的 403 之前；`params` 的形状在 SDK 之前查。没有工具服务的名字超过 64 KiB 也是 413，不再是 SDK 的不认识的工具。读法用 `encoding/json/v2`（名字的大小写同 SDK 的解码），go1.27.1 里它在默认打开的 GOEXPERIMENT `jsonv2` 之后，升级工具链时要核对它仍打开或已离开实验（`sizeError` 的注释写明）。
4. **00-M9 第 10 节的内存的估算不对，界线给 P2**：第 10 节接受每个请求"36 MiB 时约 150 MiB"。A 量的：一个上限处的合法调用峰值约 +532 MB、分配约 1.4 GB，四个同时峰值 +1.4 GB、分配 5.7 GB；实施者在同一进程里量的 1,381 MB 分配、+298 MB 峰值（客户端的 36 MiB 也在进程里）。读法：bodyshape 读完并走一遍（每层的成员复制进 map），SDK 再读一遍（`io.ReadAll`）并解消息与参数，工具的表检查走参数，处理函数再解；形状的规则多走一层约多 72 MB，`_meta` 的解码对大头在 `_meta` 里的调用多 54 MB。P2 照 A 的界线做：整个服务同时至多两个超过 64 KiB 的请求体，在 httpserver 里、bodyshape 读之前取（按 `Content-Length`，没有它的读过 64 KiB 时），别的答 503 `server_busy` 带 `Retry-After`；峰值约 1 GB。REST 的正文路由（约 31 MiB）同一类，可以共用这份预算。
5. **`id` 的 1 倍回显也限住**（F2）：超过 64 KiB 时 `id` 超过 256 字节或别的 `jsonrpc` 答 413；64 KiB 之内的回显至多约 4 × 64 KiB。
6. **修复一轮的几条照留或不做**：S3 的槽（`Options.Account`、`ClientNames.Recorded` 与 `Record`、`Notebooks.Instructions`）lint 与 knip 都过、S3 照设计要用，留着；prompt 的错误的分类与上限是 M10 的（注释写明）；B 的"一个一个地丢字段"不做（只有开头一句已说清错在哪里，回退只有 16 条转义的路径到得了）；`BOOTSTRAP_FIRST` 不再移（C 的建议），S2 重量。
7. **合并之后的摆动只改测试**（run 39053755609）：`TestAnUnwrittenAnswerIsAProblem` 问一个停在自己 ctx 上的工具、等 `ServeHTTP` 记"没写"，SDK 可能先把那个工具的错误写进已关的连接，就没有"没写"。改为两个工具：一个活过客户端，它的答复总是没写、记 debug；一个停下，它的调用记客户端走了；两个都不记 error（`c87caad7`，分支的 CI run 39054910759 全绿，两个变异都被抓到）。合并之前已有迹象：S2 的实施者在 S2 第一次的门禁里见它在竞态下失败一次（等日志的 3 秒用完），单独跑 34 次里又一次，报给主持者；变基到 `da48b92a` 之后单独 50 次没有失败，就没有在 S1 里改。

## 接受与推后的

- **接受**：
  - 上限处合法的大调用的内存（主持者的决定 4），到 P2 的界线为止；`_meta` 的解码多出的 54 MB。
  - 64 KiB 之内的回显至多约 4 × 64 KiB（主持者的决定 5）。
