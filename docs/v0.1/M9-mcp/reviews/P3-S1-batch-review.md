## 主持者的决定

负责人可以改判（[00 号文档](../00-M9-design.md)第 11 节记为第 44–55 条）：

1. **搜索批量入队，答复带 `building`**（审查 C-I2）：第 0 步照 batch 的积压重量，每格入队的页设为最新：两种可见范围里为空而带游标的第一页在 n = 0、100、1,600、2,200 时是 5、5、21、21，n = 2,200 多 16 个，过了 3.10.1 的规则的 10 个，所以规则说改：`UnitSpec.BulkSearch`、`Outcome.Building` 与答复的 `building`。由规则决定，不另问负责人。00 号文档 4.11 的"搜索"一条与"移交的落实"里 M8/P5 的一行（第 2 条，"batch 准确入队，P3 重量"）跟着改，[03-P3](../03-P3-batch-revert.md) 第 8 节给 P4 的一条现在适用（`grep` 与 `search` 说刚写的可能还没进索引）。
2. **冻住的节点的链接从不改写**（审查 B-M1，修复核对第一轮 B1-N1）：4.11 的"一个节点只要有一个操作的 `update_links` 为假，它就整个不改写"照字面成立：通向这样的节点的链接在每一页里都照原样留着，不论它的祖先怎样改；冻住的节点的改名、移动另交给"之前"的路径，只为它们的名称与原来的父节点，不跟随。
3. **改写的页的数法**（审查 B-M3，修复核对第一轮 B1-M2、B1-N3）：`MaxBatchRewrites` 照旧 400；写了的页只在 batch 的触及碰到它的一条链接时才数，算 2 页。权重是写了的页在单元里的整个代价，它的编辑在内（约是索引里的一页的 1.4–1.9 倍；改写单独约 0.7–0.8 页）。
4. **三个新的界线与一个精确的检查**，都在过界的那一项答 422 `page.batch_too_large`：
   - **带着走的节点**（审查 A-I2，修复核对第一轮 A 的 N2、N4）：一个 batch 不止一次移到别的父节点下时，这些移动带着走的节点（每次移动的子树各算一次）合计至多 `MaxUnitNodes`（10,000），在那次移动自己的检查之后查；只有一次移动时不限，同 P2 的单个 `move`。
   - **碰到的链接**，`MaxBatchRewriteLinks` = 120,000（修复核对第一轮 B1-M3）：照 M8 的规则由 `BenchmarkBatchRewrites` 新加的链接密的一档定，在读树之前数。单个 `move` 照 M6 留下的样子不限；M12 拿到曲线，考虑一个共用的界线。
   - **改写的页的字节**，`MaxBatchRewriteBytes` = 400 × 84 KiB = 34,406,400 字节（修复核对第二轮 B2-M1，修复五轮）：数过链接之后、读树之前，从页的头数（`PageSizes`，一条语句）；写了的页按它最后的大小算一次。由预算的规则定，不由时间定（只看时间会给每页 128 KiB）：在 8 MiB 的解析预算里要给最后解析的一页 5 MiB 留出地方。曲线：76–96 KiB 3.4–3.5 秒，128 KiB 4.0–4.3 秒，192 KiB 5.2–5.8 秒；256 KiB 起 batch 答 `server_busy`，重试也一样。
   - **次序**：页数、链接、字节，三个都在读树之前（修复核对第二轮 F2-2、F2-3）。
   - **精确的检查**（修复核对第三轮 B3-M1，修复六轮）：在 linking 的参与者里（`keptShares`），只对 batch：改写要的一次解析在同一次改写留着的份额旁放不下时，立即答 422，不答 `server_busy`（什么都不写，单元回滚）；别人的份额挡着的照旧 `server_busy`。它管字节的数照设计看不到的：长路径上变长的写出、前置元数据、配置得小于 8 MiB 的预算。
   - **接受的**：字节的界线是固定的常量（配置的预算更小时余地变窄，由精确的检查管）；链接与字节的提示照旧说 "or in separate calls"，一个只有一次重的移动的 batch 照它走到不受限的单个 `move`（修复核对第三轮 F3-2）。单个 `move`（REST 与 MCP）照 M6、P2 留下的样子，M6 起对重的页就答 `server_busy`；请 M12 考虑单个 `move` 与 batch 共用一个界线（页数、链接、字节），由配置的预算推出。
5. **改名或移动碰到它的页之后的 `write` 读整页**（审查 A-I1 = B-M2，修复核对第一轮 A 的 N3）：它的"相同的字节"与 `changed` 照之前的改名之后的页判，同分开调用。读的界线的 422 说为什么，提示把改名、移动另发一个 batch。
6. **新建的节点在被跟随的操作的触及之外**（修复核对第一轮 B1-M1）：batch 在一个被改名、移动的节点最后一次这样的操作之后新建的节点，不进它的子树的展开，计划与参与者里各按自己的窗口；4.11 的"新建看不见"成立。
7. **改名的改写碰到正被编辑的页只在单元里查到**（审查 A-M1）：照设计留着，4.11 与工具的说明写明。锁的预检按项的次序取每个删除的子树里的页。
8. **计划一次只留一棵树的读**（修复三轮，修复核对第一轮 A 的 N1）；新建既不让读也不让触及重来（修复核对第二轮 F2-1，修复五轮：`readsAt` 只在移动与删除之后重来，`CreatedAfterMoves` 只列新建在那个节点下面的；A 的形状从 3.75 秒、15.2 GB 到约 1.0 秒、1.22 GB）。触及随它的树留着，计划过了那棵树就丢掉；堆的峰值从修复二轮的 +1.1–1.45 GB 回到 S1 的约 +0.25 GB。
9. **v0.1 接受、记进 [M12 的性能移交](../../M12-release/handoffs/M4-performance.md)第 18 项的**（修复一、三、四轮），都在 15 秒的期限之内、batch 有界：
   - 50 次改名一个 10 万个节点的文件夹、每次之后 `write` 一个带链接的页：决定时 3.1–3.4 秒（S1 0.8 秒），修复三轮之后回收器更勤、3.45–3.78 秒，分配 15.2 GB；路径链接让正文的一遍再展开一次时 6.8–7.1 秒、分配 31 GB（修复二轮 3.8 秒、16.7 GB）。不做：照大小建触及、按链接查找、把碰到的链接交给正文的一遍。M12 拿到 (a) 与 (c) 两个改法（照修复三、四轮给的文字）。
   - 两个界线之内的重的页：400 页约 76 KB、各 100 条碰到的链接，4.2–5.2 秒。
   - 单个链接密的移动，不受限，连同曲线。
10. **M8 的清理测试的摆动在 S1 里改**（修复四轮），同 P2 S2 的 web 的摆动（[00 号文档](../00-M9-design.md)第 11 节第 42 条）：原因不靠时间显出：启动时的清理的 `PurgeTrimmedChangesets` 能落在测试的清理与它的检查之间。测试现在等启动时的清理（`awaitJob`）；只有那两种情形有这个窗口（修复四轮的调查）。任何分支都可能碰上，不记为接受的摆动。
11. **不在这一步**：
    - 成本那一份的时限：约 6–10 分钟对它的 20 分钟（S1 没有加成本的行；下一个往里加的 Step 提高时限）。守卫那一份则在修复七轮由 25 分钟提到 30 分钟（修复核对第四轮 C 的 N3-f4）：修复五、六轮给 batch 那一行加了三个测试（一共五个，本机约 48–51 秒），作业在 run 39429275198 上 12:47。
