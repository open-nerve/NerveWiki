## 主持者的决定

负责人可以改判：

1. **组合根照规则撤回挪动、分出第三份**（实施的第 9 步，审查 C 的 N2、M4）：挪到 `^Test[A-N]` 之后 CI 的三次运行里第一、第二份是 7:25 与 7:54、5:25 与 5:27、7:25 与 7:45。第二次（B2）看作 runner 的离群：两份都快，别的作业照常（竞态 6:10、守卫 10:06）；照常的运行里第二份过了线、第一份就在线上，这次挪动不成立。所以照规则（00 号文档第 11 节第 28 条）撤回，以设计 6.5 的 `BOOTSTRAP_THIRD` 把原来的第二份再分一份，不提高 `-timeout`；`make test-go` 照重量同时跑。数见"门禁"。负责人要把 B2 算进去时，挪动照规则的两次的平均成立（B1、B2：6:25 与 6:40.5）；那时 S2 的 `TestTheMCPHistory…` 与 78 个读的格落在第二份，实施者估计 S2 多半要分。
2. **`move` 的父页写成页的路径答 `write` 那样的 422**（审查 B-N2）：`to: "B.md/x.md"` 的缺的段以 `.md` 结尾（不论大小写）时，不答 `page.not_found` 与"先写父页"的提示（照它写会建一页叫 `B.md`），答 `to` 的 422 "segment N ends with .md: an ancestor is written by its title, without .md"；`domain.MissingAncestors` 由 `CreationOf` 与 `move` 的父页链共用，P3 的 `batch` 照用。一页就叫 `B.md` 时它按标题找到、是父页。设计 3.8.3 没有要求它。
3. **422 的字段名的写法交 P3**（审查 B-N3）：每一步的规则怎样写 `ops[i].*` 一类的字段，在 P3 的设计里定（每条规则收字段，或一个改写字段的函数），一条规则不写两份；S1 照设计的签名，不改。
4. **样例 047 的 README 一句随样例提交**：实施的规则"不提交 README"说的只是仓库顶层的 `README.md`；`tools/md-fixtures/README.md` 的"两者都变的不是一次操作"改为"两者都变的是 MCP 的 `move` 的一步（M9/P2 设计 3.5.3，样例 047），Obsidian 与 REST 里是两次操作，这样的样例是 `nerve-defined`"（`0c6d0f47`）。
5. **请求体的 JSON 值的上限**（审查 A2-I1）：bodyshape 的第一遍扫描数 JSON 值，过了路由的上限就停，在任何解码之前；`/mcp` 一个上限 10,000，不论方法与大小，远在 P3 最大的 `batch`（约 715 个值）之上；拒绝照 bodyshape 别的拒绝（400 `bad_request`，请求体本身 `too_long`，消息写出上限），契约里写明；REST 也有上限（1,000）：它的最坏不小（1 MiB 的许多小成员 +23.6 MiB，一个凭证同时 200 个约 4.7 GiB）。全部形状重量（A2-M1）。
6. **A2-M1 最高的一次读作在"约 1 GB"之内**：路由链的一次性测试的一次 +961 MiB（1.008 × 10⁹ 字节；同一形状的三次是 +771、+929、+961）。设计 3.2.4 的单位是"各约 +0.5 GB"（量出是 496 MiB），整个程序这一轮最高 +924.2 MiB（一个长字符串），同一形状的几次可差约 190 MiB，比上限处的形状与一个长字符串之差还大；所以 00 号文档第 10 节的那一行不改写，各个数记下（修复核对第一轮 A2 同意）。负责人把 1 GB 读作严格的 10⁹ 字节时，那一次过了 0.8%，整个程序没有一次过。
7. **全是 CRLF 的页上 `new_string` 的单独的 LF 照 CRLF 写**（修复核对第一轮 B2-M1，B 的 (a)）：`old_string` 里没有 CR 时，`new_string` 的单独的 LF 不论 `old_string` 有没有 LF 都写成 CRLF，它里面的 CR 照留；`old_string` 带 CR 时两个都照原样。三个理由：00 号文档 4.10 的规则自己的理由（模型常丢掉 `\r`）对 `new_string` 一样；工具的说明本来就这样答应；这样全是 CRLF 的页在不带 CR 的编辑之下一直全是 CRLF，只要还留着一个换行（修复核对第二轮 B3-N1）。B 的 (b)（规则照旧、把说明写准）是另一条路。
8. **`go test -short ./...` 有自己的门禁**（修复核对第一轮 C2-M1、第二轮 C3-M1）：README 答应贡献者的这个命令由 `make test-go-short` 与 CI 的 `short` 一份守着，不进组合根的份（那几份的规则读它们的测试一步）。它的第二次 CI 运行（D2）在一个时间的界线上失败（`go test -short ./...` 的各包同时跑，`TestTheWorstGlobsStopWithinTheirWork` 2.62 秒对 2 秒），实施者的回答与偏离照收：按耗时判定、不要数据库的测试在 `-short` 下跳过（第 33 个提交，`-short` 本来的意思；`test-go-costs` 与 `test-go-guards` 照旧不带它、单独一行跑）；目标就是 README 的写法、不带 `-timeout`（第 34 个提交）；时限不是作业的两倍：Go 默认的每个测试二进制 10 分钟要先到、打出卡住的测试，同别的各份；修复二轮定 15 分钟，修复三轮照 C 的观察（Go 的缓存冷时各个二进制开始得晚）改为 20 分钟。第 29 个提交的 `-timeout 15m` 已去掉。`make check` 也跑它（`check: lint knip test test-go-short build-web`，修复三轮，C3-M1），所以 `README.md:24`、`Makefile:4-5` 与 v0.1 总体设计 13.5 第 1 条照原文成立；M0 收尾的 M8 同样把 `build-web` 加进 `check`。
