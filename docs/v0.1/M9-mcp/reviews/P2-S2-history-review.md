## 主持者的决定

负责人可以改判：

1. **按页面的日志的代价，v0.1 不改代码**（审查 B-M1）：`log {path}` 每次调用读这一页的全部历史，带 `revision` 的 `versions` 读整个版本（同 `read`）。B 测得一页 40,000 个变更集时 35–47 毫秒、300,000 个时 225–452 毫秒，线性，离调用的 15 秒的期限很远。M12 的压测加一页由 agent 写出的长历史；B 的数、实施者提的结构的改法与修复核对一轮 B 对它的看法写进 [M12 的性能移交](../../M12-release/handoffs/M4-performance.md)第 18 项，作为 M12 要考虑的改法：把变更集的时刻抄进条目与版本、两张表各按节点建索引，一页取每张表游标之下的 limit+1 行再合并。B 以原型在一页 300,000 个变更集上试过，答复与今天的语句逐页相同，一页至多 6.0 毫秒（今天 551 毫秒），插入的代价量不出差别；真正的代价是迁移的回填，每一百万个版本约 7–8 秒、2.3 GB 的 WAL，另有版本的行数据在 vacuum 之前多一份。B 没有找到更简单的、既准确又有界的改法，提了四处细化：列由子查询填、条目的新索引替换原来的按节点的索引、压测也量 `log {path, actor}` 与 `{path, client}`、加一个逐页比较的测试。今天每 1,000 个变更集约 0.8–1.5 毫秒，约 130,000–250,000 个时过 M8 的读的 200 毫秒。
2. **`log {path: ""}` 答 "path is required" 留给 v0.1 之后的打磨**（审查 A-N2 的后一半）：一个可选的参数上的拒绝，照负责人对小的体验问题的规则，写进 [M12 的打磨移交](../../M12-release/handoffs/M5-polish.md)第 30 项（两种改法：当作没有筛选，或说明 `path` 指一页或一个附件）。
3. **web 的那个摆动在 S2 里改，虽然在它的范围之外**（审查 C-M1）：原因是假的事件服务器在一个没有谁持有的 Request 上等中止，一次垃圾回收就丢掉标签页的中止；任何分支都可能碰上，改法只有两行（`ff8858bf`，自己的 `test(web)` 提交），所以不记为接受的摆动。
4. **`versions` 对不以 `.md` 结尾的路径的提示不带路径**（修复一轮 B-N1 的偏离）：字段的说明在 MCP 的答复里出现三次，最长的路径会让答复过 48 KiB；只写规则（`domain.PageRule`："A page's path ends with .md."）。要带上这一页自己的路径，就得像 `read` 与 `log` 那样先查找，[02-P2](../02-P2-writes-history.md) 3.16.1 的次序（这个 422 在笔记本之前）与 3.17.1 的调用都要变。
