## 主持者的决定

负责人可以改判（[00 号文档](../00-M9-design.md)第 11 节记为第 96–104 条）：

1. **P5 的四处可改判的取舍都维持**（P5 的设计审查的主持者的决定第 1 条；[05-P5](../05-P5-stories-docs.md) 2.2）：PG14 (MCP) 就是挪来的 MC3 的活动测试，不另写一遍；C7 (MCP) 以事件流的帧断言，不开浏览器；PG7、PG8 以 `expectVersions` 代会话的两个断言，另断言"agent 的写不留编辑会话"（`sessionsOf` 为空）；README 的反向代理的样例按路由（nginx 的四个 `location`，Caddy 的 `request_buffers` 只给三个路由）。建成的就是这样，审查没有找到推翻它们的事实。
2. **Caddy 在 P5 定下，不留给清单**（P5 的设计审查的主持者的决定第 2、12 条）：README 的 Caddy 样例在本机已有的 `caddy:2.10-alpine`（Caddy 2.10.2）里核对过，隔离（`--rm --pull=never --network none`，没有映射端口），什么都没下载：合并之前实施者照同一份脚本重跑，B 以 README 自己的样例再跑一次，缓冲的三个路由在毫秒级、上传与导入约 3.84–3.85 秒。Caddy 把缓冲的请求体放在内存里（设计审查 B 量的：30 MiB 约 +66 MB，接近 `/mcp` 的上限约 +116 MB，没有临时文件）。经 Caddy 时服务端在读请求体之前的拒绝，对大的请求体到客户端成了光秃的 502、没有 `Retry-After`：以替身量的（不读请求体就答 503 与 `Retry-After: 1` 的 Go `net/http` 的上游，不是 nervewiki 本身），合并之前的探测在缓冲的两个路由上 2–30 MiB 24 次都是 502。交 M12（[M12 的性能移交](../../M12-release/handoffs/M4-performance.md)第 18 项），P5 不改服务端（5.1、5.2）。
3. **清单在 v0.1 的最后之前不跑**（负责人的规则：v0.1 的最后只验收一次，00 号文档第 11 节的取舍第 12 条；P5 的设计审查的主持者的决定第 4 条）：在它跑过之前，README 里客户端的每一句在样例里、标着"照文档"或"未核对"，或由仓库的记录核对过，各在设计 4.2 的表里有一行；清单的预期同样标着。修复各轮加的客户端的说法（"不再问"存在哪里、`~/.claude.json` 的形状、`claude mcp remove`、会话的目录怎样起名、`host.docker.internal` 到不到主机的回环）都标"未核对"。
4. **清单里 Codex 的登录**（P5 的设计审查的主持者的决定第 5 条）：先用 API 密钥（`printenv OPENAI_API_KEY | codex login --with-api-key`，凭证在临时的 `CODEX_HOME` 里）；其次在临时的 `CODEX_HOME` 里另 `codex login` 一次，做完在没有设 `CODEX_HOME` 的终端里记下负责人自己的 Codex 是否照常可用（第二次登录会不会让第一次失效未核对）；最后才复制 `auth.json`：复制时记下原来的那一份的 `shasum`，其间不在别处用 Codex，做完时（删临时目录之前）只在原来的指纹没变、临时的变了时才复制回去，原来的变了时不复制，两份都变了时在自己的环境里重新 `codex login`。
5. **清单自己的安全**（审查 C 的存疑 1、B 的存疑 1、B-M1；修复核对一轮 B2-M1 = C2-M1、B2-N1、B2-N2）：清单不给删除 Claude Code 在 `~/.claude/projects/` 下的会话的命令：它们可以留着，要删的人先核对名字、自己手动删那一个目录，命名未核对；D1、D2、D3 各在一个新的临时目录里做，各有自己的一份 `mcp.json`，前面答的"不再问"与 D2 的放行不论 Claude Code 记在哪里都带不进下一步，D 做完以 `${VAR:?}` 守着删掉这三个目录、回到 `$CC`；A3 在命令之前与会话之后各数一次 `~/.claude.json` 里的 `"nervewiki"`，多了时记下、以 `claude mcp remove nervewiki --scope local`（未核对）去掉。清单里唯一的 `rm` 是 D 的那一条（[05-P5](../05-P5-stories-docs.md) 6.1、6.2）。
