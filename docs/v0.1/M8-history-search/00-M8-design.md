## 1. 目标

1. **版本**：一页的正文版本可以列出、查看（阅读视图）、两两比较，还原到任意一个版本；还原是一次新的写，产生新的变更集。
2. **日志与整组撤销**：笔记本的变更集按时间列出，可按人、客户端、页面筛选（M9 的 `log` 用同一个用例）；每个变更集看得到它改了哪些节点、怎么改的；整个变更集可以撤销，前提是其中每个节点的当前状态仍是它写出的，否则整体拒绝并列出冲突的节点（总体设计 3.8）。
3. **回收站**：删除的子树进笔记本的回收站，列出、预览、恢复；原父节点已不在时放到根下，标题冲突时加序号；清理期（60 天）之后不能再恢复（总体设计 3.10）。恢复带回附件的文件与链接索引（M6、M7 的移交）。
4. **搜索**：在工作区里按标题与正文搜索，中文可用，只列出调用者看得到的笔记本里的页与附件，正文命中给出摘要片段；搜索的方案经真实中文语料的实测定下（M0/P1 的移交）。
5. **接到后面的 M**：日志、撤销与搜索的用例可由 M9 的 MCP 适配器直接调用（`log`、`grep`），撤销可由 M11 的回滚按变更集逐个调用。

## 2. 范围

**做**：

- page 模块：版本的读（列表、内容、阅读视图）；还原版本（类型为 `restore` 的变更集）；变更集的日志与变更的明细；整组撤销（类型为 `revert`，记下撤销的是哪一个）；回收站的列表与恢复（树的写入单元里的新操作 `OpRestore`）；清理之后被截掉一部分的变更集的标记；恢复的期限；搜索的索引与用例；迁移（变更集的类型与列、日志与回收站的索引、版本的唯一索引、搜索的索引）。
- asset 模块：恢复节点时恢复附件的行（经页面领域事件的观察者，同一事务）。
- linking：恢复的页经观察者进索引（与新建相同），不经改写的参与者；撤销同样不经参与者（4.8）。
- transfer 模块：大的恢复作为后台任务（类型 `restore`），沿用导入的分批、预算与报告（4.6）。
- notebook 模块：给 page 的"看得到的笔记本"端口（工作区搜索的过滤）。
- 平台与实例：`InstanceInfo.trash_retention_seconds`（回收站显示清除的日期）。
- 前端：右栏"页面信息"的版本列表；版本页（阅读、与上一版或当前比较、还原）；笔记本的历史页（日志、明细、撤销）；回收站页（列表、预览、恢复）；工作区的搜索框与结果页；页面树在恢复之后重新显示（`removedTo`）；删除确认框写明回收站。

**不做**：

- 版本的保留策略、合并或删除单个版本（总体设计 1.2：留给 v0.2）；永久删除回收站里的一项、清空回收站：只由清理任务在 60 天后清除。
- 编辑会话之内的中间版本：一次会话每页一个版本（M4 的决定），自动保存的中间状态没有存，不能列出。
- 附件的版本（M7：附件写入之后不变）。
- 撤销笔记本、工作区的删除：它们不是写入单元，没有变更集（总体设计 3.8 的表只列页面的写）；删除笔记本之后它的页随之不可见，恢复笔记本不在 v0.1。
- 搜索的相关度排序、分词、同义词、拼音、模糊（错别字）匹配；搜索附件的内容；正则搜索（M9 的 `grep` 在 M9 做，用 M8 建的索引）。
- 跨工作区的搜索。
- 历史与搜索的实时推送：列表随 `pages` 事件重读，不加新的事件类型。

## 3. 完成标准

总体设计 12.5 的通用标准之外：

1. **版本**：一页的版本列表按版本号倒序分页，每个版本带变更集的类型、客户端、执行者（显示名）与时刻；版本的内容与按当前树解析链接的阅读视图；回收站里的页同样读得到；中间版本（没有行的版本号）答 404。还原版本以 `base_revision` 防覆盖，经编辑锁（有人编辑时 409 `page.locked`），产生类型 `restore` 的变更集；与当前相同时不写。
2. **日志**：按变更集的创建时刻倒序的游标分页，按人、客户端、页面筛选；每条带变更的摘要（数量与前几个节点）；明细按节点分页，列出新建、删除、恢复、改名、移动与正文（前后的版本号）。清理截掉过的变更集带标记。
3. **整组撤销**：表格测试覆盖每种条目的撤销（新建、删除、改名、移动、正文、恢复、还原、撤销的撤销）与每种冲突（之后又改过、标题被占、父页不在、太深、新建的节点下有别的变更集建的子节点、已被清理截掉、超过恢复的期限、页被锁）；冲突整体拒绝、列出全部冲突的节点，什么都不写；撤销一次导入；撤销之后链接索引与重建的一致（`checkLinks`），`links` 事件到达。
4. **回收站**：列出被删除子树的根（分页），带原位置、删除者与时刻、清除的日期、子树里页与附件的数目；恢复子树（同一时刻删除的）连同正文、版本、条目、附件的行与链接索引；父页不在时放到根下、太深时同样放到根下，标题冲突加序号；超过期限答 409；大的子树作为后台任务分批恢复，进度与报告照导入。
5. **搜索**：第 4.11 节的方案在实测的语料规模下达到它的目标（标题、正文、各类查询的 p99）；只列出调用者看得到的笔记本（"列表的结果"等于"逐项判定读取"的集成测试，照 `TestTheNotebookListIsWhatEachReadAllows`）；附件只按名称列出；摘要片段在命中处；LIKE 的通配符照字面匹配。
6. **并发与权限**：4.13 的交错各有确定性的测试，结束时核对不变式（`checkPages`、`checkLinks`）；权限矩阵覆盖新操作的每一格。
7. **最后一跳**（总体设计 13.1 第 21 条）：恢复经观察者带回附件的行与索引、搜索经端口得到看得到的笔记本，组合根交空时整个程序上的测试失败。
8. **前端**：版本列表、版本页（比较、还原）、历史页（撤销与冲突的说明）、回收站页、搜索各有 vitest，经组合根到达；e2e 的 H、T、S 系列故事（第 9 节）通过。

## 4. 关键决定

### 4.1 模块与端口

| 项 | 决定 | 放弃的方案 |
|---|---|---|
| 归属 | 版本、日志、撤销、回收站、搜索都在 page 模块：它们读写的都是 page 的表（`nodes`、`page_contents`、`changesets`、`changeset_items`、`page_revisions`）；搜索的索引迁移归 page（总体设计 7.2 末句） | 新的 `history`、`search` 模块：要经端口读 page 的全部表，跨模块的 SQL 不能 join（`sqlc.yaml` 按模块列迁移），只多出一层转发 |
| 看得到的笔记本 | 工作区搜索要"调用者看得到的笔记本"：notebook 模块已有的 `VisibleNotebooks.VisibleIn`（今天只接给事件流），由组合根交给 page 的新端口；page 以 `notebook_id = ANY($ids)` 过滤 | page 自己判定每一本：要读笔记本与成员，越过模块的边界 |
| 显示名 | 版本、日志、回收站带执行者的显示名：page 已有的 `Names` 端口（M5 的锁持有人用它）；总体设计 6.1 的"内嵌账户资料"的例外加上这三处（与审计记录同理：v0.1 没有读别的用户的接口） | 只给 id、前端另读：没有这样的接口 |
| 附件的行 | 恢复时由 asset 的观察者在同一事务里恢复（`asset/app/follow.go` 加 `NodesRestored`），与删除对称；观察者从 `Change.Restored` 认出恢复（新建的附件节点同样 `Before == nil`，它的行由单元写） | 恢复的用例直接写 `asset_blobs`：越过 asset 的边界 |
| 链接索引 | 恢复的页与新建一样：变更带 `Revision` 与 `Facts`，linking 的观察者 `ReplacePage` 并重新解析受影响的键（M6 的移交第 1、2 项：只重新解析，不改写别的页）；`Relocation` 要求 `Before` 不空，恢复因此不触发改写的参与者 | 回收站里保留索引行、恢复时直接启用：所有的索引读都要排除回收站里的来源，改动 M6 的每条查询与不变式 |
| 大的恢复 | 超过一个写入单元上限（100 个节点、8 MiB 正文、20,000 条链接，总体设计 13.1 第 31 条）的恢复作为 transfer 的后台任务（类型 `restore`），分批写入、并入同一个变更集，照导入（4.6） | 一个单元恢复：几千页要在笔记本的锁下解析，超过请求的期限（15 秒）；请求里分批：用户离开页面就停在一半，没有进度与报告 |

page 模块的新用例与端口：

- 读：`ListVersions`、`GetVersion`、`GetVersionView`、`ListChangesets`、`ListChanges`、`ListTrash`、`Search`；它们经 `Authorizer` 的笔记本级判定（4.13），回收站里的节点由新的"读得到已删节点"的读出（今天的 `readable` 只认活着的节点）。
- 写：`RestoreVersion`（正文的写，类型 `restore`）、`RestoreNode`（树的写入单元，`OpRestore`）、`Revert`（一个写入单元里的多个操作，类型 `revert`）。
- 给 transfer 的：`TreeWrites` 加 `Restore`（一批节点的恢复，照 `Import`）与回收站一组的读（节点、正文，未加锁），4.6。
- 端口：`VisibleNotebooks`（notebook）、`Retention`（配置 `jobs.purge_retention`，经 `Deps`）。

### 4.2 数据：迁移

都归 page 模块（搜索的见 4.11）：

| 表 | 改动 | 为什么 |
|---|---|---|
| `changesets` | `kind` 加 `restore`、`revert`；加 `reverts_id uuid`（不建外键，`CHECK ((kind = 'revert') = (reverts_id IS NOT NULL))`）；加 `trimmed_at timestamptz` | 3.8 的类型；撤销记下撤销的是哪一个（日志显示"撤销了…"，再撤销时同样可以撤）；外键会让清理器先后受制（被撤销的变更集先被清理时） |
| `changesets` | 索引 `(notebook_id, created_at DESC, id DESC) WHERE deleted_at IS NULL` | 日志的游标分页（13.1 第 27 条：与次序相同的索引） |
| `changeset_items` | 加 `revision integer`：新建与恢复一页时，这一页在变更集之后的版本号（附件、删除、改名与移动为空） | 撤销一次恢复要核对恢复之后正文没再写过：恢复不写版本行，别处没有这个数（4.8） |
| `page_revisions` | 唯一索引 `(node_id, revision)` | 按版本号寻址与倒序列出；同时钉住"一页的每个版本号至多一行"（今天由写入的方式保证，没有约束） |
| `nodes` | 索引 `(notebook_id, deleted_at DESC, id DESC) WHERE deleted_at IS NOT NULL` | 回收站的游标分页；今天只有全局的 `nodes_deleted_at_idx` |

不加的：条目不记"排在哪个兄弟之后"（4.8 的位置）；不另记中间版本；不给 `changeset_items` 加操作的类型（恢复与新建都是"前"为空，日志按节点的 `created_at` 早于变更集区分，4.7）。

**清理截掉的变更集**：清理器只删已删节点的行，所以一个活着的笔记本里的变更集，只有它碰过、后来被删除并过了 60 天的节点的条目与版本会被删。被截掉一部分的变更集不能再整组撤销（只撤销剩下的部分违反"整组"）：`changeset_items`、`page_revisions` 的清理语句在同一条语句里给这些行所属的变更集设上 `trimmed_at`（CTE 的 `RETURNING changeset_id`）；条目与版本都被删光的变更集由 `changesets` 的清理器删掉（今天只删笔记本已删的，改为"没有条目与版本、`updated_at` 早于保留期"的也删）。

### 4.3 版本：列表、查看、比较

- **版本就是 `page_revisions` 的一行**，以它写出的版本号（`revision`）寻址：`/pages/{page_id}/versions/{revision}`。编辑会话的一行覆盖 `(base_revision, revision]`，其间的版本号没有行，答 404。
- **列表**：一页的版本按 `revision` 倒序，游标是版本号；每项带 `base_revision`、字节数、写出的时刻（行的 `updated_at`）与变更集（id、类型、客户端、执行者的 id 与显示名、创建与最后写入的时刻）。不列树的变化（改名、移动在日志里）。
- **内容**：原样的正文（至多 5 MiB），供比较与"复制旧版本"。
- **阅读视图**：照 `getPageView` 的形状，用已有的渲染路径（`PageRef{Revision}`）；旧版本的链接按当前的树即时解析（M6 4.7、总体设计 4.3；M6 的移交第 3 项，已经是这样）。
- **回收站里的页**同样读得到（M4 的移交第 2 项："回收站里的页面照样有历史"）：版本的读认已删的页面节点（笔记本活着），权限与活着的页相同。
- **比较在前端**：`@codemirror/merge` 已是依赖（M5 的冲突对比，随编辑器懒加载），版本页以只读的统一视图显示"与上一版"（`base_revision` 那一行）或"与当前"的差异。大的正文：比较给 `diffConfig` 的 `scanLimit` 与 `timeout`，超时时退为按行的粗比较并说明。服务端不做 diff（Go 侧没有 diff 的依赖，也不需要）。

### 4.4 还原版本

- `POST /pages/{page_id}/versions/{revision}/restore`，请求体 `{base_revision}`：调用者看到的当前版本号，不一致答 409 `page.revision_mismatch`（与 `putPageContent` 相同，防止覆盖没看到的改动）。
- 是一次正文的写：新的变更集，类型 `restore`；单元之前按 `Take` 取预算解析（与正文的写相同，总体设计 13.1 第 19 条）；经写入守卫：这一页有活着的编辑会话时答 409 `page.locked`（调用者自己在别处编辑同样被拒，与不带会话的瞬时写入相同，总体设计 3.9）；与当前正文相同时不写，答当前的版本号。
- 权限：写者（编辑者与管理员），与写正文相同。
- 还原之后被还原的那个版本不变；新版本的"前"是还原之前的当前版本，所以还原本身同样可以撤销或再还原。

### 4.5 回收站：列表

- `GET /notebooks/{notebook_id}/trash`：被删除子树的根，即已删、且父节点为空（根下）或父节点的 `deleted_at` 与它不同（父节点活着，或另一次删除的）的节点；按 `deleted_at` 倒序、id 倒序分页（4.2 的索引）。
- 每项：节点（id、类型、名称）、原位置（祖先的名称，读已删的祖先；`Ancestors` 不过滤已删）、删除者（`nodes.updated_by_id`，删除时写的）与显示名、删除的时刻、清除的日期（删除时刻加保留期）、这一组里的页数与附件数。
- 只列出还能恢复的（4.10 的期限之内）。
- 能读这本笔记本的人都看得到回收站（他们删除之前就读得到这些页）；恢复要写者。
- 预览：回收站里的页打开为它最后一个版本的阅读视图（4.3），附件显示名称、类型与大小（不签发下载地址：恢复之后再下载）。

### 4.6 从回收站恢复

- `POST /nodes/{node_id}/restore`：恢复一个回收站的根与同一时刻删除的子孙（同一个 `deleted_at`）；不是根（父节点同一时刻删除）答 409 `page.not_trash_root`，带它的根的 id。
- **放在哪里**：父节点活着、且放回去不超过 10 层时放回原父节点下，按原来的次序值插在兄弟之间（`sort_order` 删除时保留；插在次序值小于它的最后一个兄弟之后）；否则放到根下的末尾。标题与活着的兄弟冲突时加序号（`page/domain.Numbered`，附件加在扩展名之前，同导入的 `children.free`）；只有被恢复的根可能冲突：它的子孙的兄弟要么一起恢复，要么仍在回收站。
- **单元**：树的写入单元（`Tree: true`，笔记本行 `FOR NO KEY UPDATE`），操作 `OpRestore`，类型 `edit` 的新变更集（与删除相同；日志显示为"恢复"，4.7）。每个恢复的节点一项变更：`Before == nil`、`After` 是恢复后的状态、页面带当前的 `Revision` 与 `Facts`、`Restored: true`；条目照新建写（"前"为空）。在锁下：清空这一组的 `deleted_at`（`nodes`、`page_contents`，以及这些节点在所有变更集里 `deleted_at` 等于这一时刻的版本与条目，包括删除它们的那个变更集的条目），重算 `name_key`（`reindex` 只重算活着的节点，回收站里的可能是旧的），根的父节点、名称与次序照上面，`updated_by_id`、`updated_at` 记恢复者与时刻。
- **解析在单元之前**：未加锁地读出这一组的正文，按 `Take` 取预算解析（总体设计 4.3、13.1 第 19 条；M7 设计审查 A-I2 去掉了锁下的 `TakeNow`，M6 的移交第 1 项写的 `TakeNow` 照此改）；单元里核对这一组仍是同一时刻删除、每页的版本号未变，不然答 409 `page.trash_changed` 让调用者重试。
- **观察者**：linking 为每页建索引、重新解析受影响的键（M6 的移交第 1、2 项）；asset 恢复附件的行（M7 的移交第 1 项），行数与附件节点数不符时让单元失败（4.10 之后不应发生，作为防线）；事件的 `pages` 照常（树变了）。
- **大的子树**：这一组的页数、正文字节数超过一个单元（100 个节点、8 MiB）时，答 202 与一个 transfer 的任务（类型 `restore`，`root_id` 是这个根），由任务分批恢复：先恢复根（决定位置与名称），之后按层，每批的父节点都已恢复；各批并入第一批的变更集（`UnitSpec.Changeset`）；批之间放开笔记本的锁；解析、预算与退避、`ANALYZE`、心跳、取消、报告都沿用导入（`transfer/app/import_write.go`）。一本笔记本同时一个导入或恢复的任务（与导入共用这一条限制与队列）。途中失败或取消：已恢复的部分留着，剩下的仍在回收站（作为各自的根列出，可以再恢复），报告写明。
- **权限**：写者（与删除相同）。
- **前端的树**：恢复之后从 `PageTreeStore` 的 `removed` 去掉这一组（M4 的移交第 4 项），否则本标签页看不到它们。

### 4.7 日志

- `GET /notebooks/{notebook_id}/changesets`：按 `created_at` 倒序、id 倒序（`created_at` 是第一次写入的时刻，不随会话的后续保存与导入的后续批次移动；`updated_at` 会移动，不适合作游标），游标照审计记录（`[created_at, id]`）。筛选：`actor`（账户 id）、`client`（`web`、`api`、`cli`、`mcp:<名>` 或前缀 `mcp`）、`page_id`（碰过这一页的：它的条目或版本行所属的变更集）。
- 每条：id、类型、客户端、执行者（id、显示名）、创建与最后写入的时刻、说明（`message`，M9 的 `batch` 会写）、`reverts_id`、是否被截掉过（`trimmed_at`）、变更的摘要：新建、删除、恢复、改名或移动、正文各有几个节点，与前三个节点的名称与变化。
- **明细**：`GET /changesets/{changeset_id}/changes`，按节点 id 分页：节点（id、类型、现在的名称、是否已删）、变化（新建、恢复、删除、改名、移动、仅次序，可兼有正文）、前后的父节点与名称、正文前后的版本号（链到版本页的比较）。"恢复"与"新建"都是"前"为空：节点的 `created_at` 早于变更集的创建时刻的是恢复。
- 一次导入的变更集可能有几万个节点：摘要按数量给出，明细分页。
- 权限：能读这本笔记本的人（与审计记录不同，日志是页面的历史，读者能读页面就能读它的历史）。

### 4.8 整组撤销

`POST /changesets/{changeset_id}/revert`（请求体可带 `message`）：在一个写入单元里把变更集 C 写出的每个节点恢复到 C 之前的状态，产生类型 `revert`、`reverts_id = C` 的新变更集 R。

**能撤销的前提**（在锁下逐个核对，全部不满足的一次列出，答 409 `page.revert_conflict`，problem 带 `conflicts`：每项节点 id、名称与原因；什么都不写）：

| C 对节点做的 | 当前必须是 | 撤销 | 冲突的原因 |
|---|---|---|---|
| 新建（含恢复） | 活着，父节点与名称等于 C 的"后"；页面的版本号等于条目记下的（`revision`，4.2）；活着的子节点都是 C 新建或恢复的 | 删除（进回收站） | `changed`、`children_added` |
| 删除 | 仍在回收站，`deleted_at` 等于 C 的时刻；在恢复的期限之内 | 恢复（照 4.6，但放回 C 的"前"的父节点与名称：父节点不在、标题被占、太深时冲突，不像回收站那样改放根下或加序号） | `changed`、`expired`、`parent_gone`、`title_taken`、`too_deep` |
| 改名、移动 | 活着，父节点与名称等于 C 的"后" | 改回 C 的"前"的父节点与名称；次序按"前"的次序值插回兄弟之间 | `changed`、`parent_gone`、`title_taken`、`too_deep` |
| 写正文 | 活着，版本号等于 C 写出的 | 写回 C 的 `base_revision` 那一版的正文（上一行版本；同一页的版本链是连续的） | `changed` |

另：C 被截掉过（`trimmed_at`）答 409 `page.changeset_trimmed`；超过 4.8 末的大小答 422 `page.revert_too_large`。

- **次序不比较**：条目只记次序的原始值，兄弟的重新编号（M4：间隔小于阈值时）不记条目（M4 的移交第 1 项），原始值之间无法判断"位置是否仍是 C 写的"。所以冲突只看父节点、名称、是否删除与正文的版本号；撤销移动时按"前"的次序值插回（插在次序值小于它的最后一个兄弟之后），兄弟被重新编号过时位置可能不精确。今后要精确，条目要记"排在哪个兄弟之后"，写进 10 的风险，不在 v0.1 做。
- **不经改写的参与者**：C 若是改名、移动并改写了别的页的链接，那些正文的写就在 C 的版本行里，撤销把它们一并写回，链接因此逐字节回到原样；再经参与者改写会改两次。所以撤销的单元以 `participate=false` 应用（M6 的移交第 4 项：定为不经参与者，因此也不会答 `linking.pages_locked`）。链接索引经观察者照常更新（撤销写的正文在单元之前解析）。
- **锁**：撤销里的正文写与删除经编辑锁的守卫：有一页被人编辑就整个拒绝，答 409 `page.locked`，带第一页的持锁人（M5 的移交第 1 项：与 M5 的码一致，最简单；跳过被锁的页违反"整组"，不做）。
- **次序**：在一个单元里依次：恢复 C 删除的（父节点在前）、改回改名与移动、写回正文、删除 C 新建的（只删最上层，子孙随之）。两个节点在 C 里互换了名称这类在应用途中会撞名的，按 `title_taken` 冲突报出，不做两步改名。
- **大小**：撤销在一个单元里完成，要解析的正文（写回的正文与恢复的页）在单元之前按 `Take` 解析，合计不超过 1,000 页、64 MiB，不然 422 `page.revert_too_large`（日志里一个删除大子树的变更集，前端改为指向回收站的恢复，那里有后台任务）。只删除不解析的撤销（一次导入的撤销：删掉导入的最上层节点）没有这个上限，与手动删除一个大子树的代价相同（M12 的移交，删除 5 万个节点约 10–13 秒）。
- **撤销的撤销**：R 本身是普通的变更集，可以再撤销（核对的是 R 写出的状态）。
- **一次导入**（M7 的移交第 4 项）：导入的变更集只有新建；撤销删除它建的最上层节点，进回收站；导入之后被人改过的节点让撤销冲突。不分批：删除不解析，一个单元就是一条软删除的语句加观察者，比 M7 移交设想的"分批撤销"简单，且整组。M7 的导入任务不存变更集的 id：任务的报告加上 `changeset_id`，导入的任务行给出"在历史里查看"。

### 4.9 后台任务：恢复

transfer 的 `transfer_jobs` 加类型 `restore`（迁移归 transfer）：`root_id` 是回收站的根，`notebook_id`；状态机、心跳、启动时的收拾、取消、报告、清理都沿用（M7 4.9、4.12）。报告：恢复的页数与附件数、放在哪里（父节点、名称）、途中停下时剩下的数目。任务列表在笔记本设置的"导入导出"里一并列出（前端照类型显示）。权限与导入相同：发起人是写者，失去写权限时任务停下。

### 4.10 清理与恢复、撤销的先后

清理按墙上的时钟删 `deleted_at` 早于"现在减去保留期"（`jobs.purge_retention`，默认 60 天）的行，附件先删文件、页面的表逐表各自提交（survey：条目 → 版本 → 正文 → 节点）。恢复与撤销里的恢复只认 `deleted_at` 晚于"现在减去保留期再加 1 小时"的组：清理与它们从不碰同一批行，不用在每张表上锁行、数行（M7 的移交第 2 项设想的 `FOR UPDATE` 由这一条时间的间隔代替，交错的测试照样做）。超过的答 409 `page.restore_expired`；回收站只列期限之内的。asset 的观察者在恢复时仍核对行数（防线）。保留期经 `Deps` 交给 page，经 `InstanceInfo.trash_retention_seconds` 交给前端。

### 4.11 搜索

（待 M0/P1 移交要求的真实中文语料实测完成后写定：方案、索引的 DDL、查询的 SQL、目标与实测的数字、最短的查询长度、结果的形状与排序、附件的名称、摘要片段。实测正在进行，见第 10 节第一行。）

已定的部分：

- `GET /workspaces/{slug}/search?q=&notebook_id=&cursor=&limit=`：调用者在这个工作区里看得到的笔记本（4.1 的端口），可限定一本；只列活着的节点。
- 结果：节点（id、笔记本、类型、名称）、路径（祖先的名称）、是否标题命中、正文命中的摘要片段（命中处前后的文字与命中的位置）、最后写入的时刻；附件带类型与大小，打开即下载（签名地址由附件的接口给）。
- 正文只搜页面；附件只按名称（M7 的移交第 6 项）。
- `q` 里的 `%`、`_`、`\` 照字面匹配；空白分开的几个词都要命中（标题或正文）。
- `Ctrl+O` 的快速切换不变（前端已加载的树上的标题）。

### 4.12 前端

- **右栏"页面信息"**：加"版本"一节：最近的版本（时刻、执行者、类型），"更多"读下一页；点开进版本页。锁的状态仍在中栏的提示里（总体设计 9.2 写在右栏，与 M5 以来的实际不符，随这份设计改 9.2）。
- **版本页** `/:slug/notebooks/:id/pages/:pageId/versions/:revision`：版本的信息；"阅读"（阅读视图）、"与上一版比较"、"与当前比较"三种显示；写者有"还原到这个版本"（确认框；`base_revision` 用页面当前的版本号；409 的版本不一致与被锁照编辑器的写法说明）。
- **历史页** `/:slug/notebooks/:id/history`：日志（游标列表照 `AuditStore`，13.2 第 19 条），按人与页面筛选（从页面的"查看这一页的历史"带上 `page_id`）；每条展开为明细（分页）；写者有"撤销"（确认框；冲突时列出每个节点与原因；大的删除指向回收站）。
- **回收站页** `/:slug/notebooks/:id/trash`：列表、预览（页的最后版本、附件的信息）、"恢复"（同步的恢复之后打开恢复的页；202 时说明已开始、进度在设置的"导入导出"里）。笔记本的左栏加"历史"与"回收站"两个入口。
- **搜索**：工作区左栏顶部的搜索框（`Ctrl+Shift+F` 聚焦），回车进结果页 `/:slug/search?q=`；结果按笔记本筛选，命中处高亮（只高亮服务端给的位置，不把用户的输入当作正则）；附件显示类型与大小。
- **事件**：`pages` 事件让这本笔记本的历史、回收站列表与版本列表重读（经 `refresher`，照 M7 的整树重读），连上时重读已缓存的这些键（`refreshedOnConnect`）。
- **删除确认框**写明"可在回收站恢复，N 天后清除"（N 由 `InstanceInfo`）。

### 4.13 权限、加锁与交错

- **新的动作**（access 的规则表，矩阵各加一行，`boot/actions_test.go` 的"规则 = 动作"）：`page.history`（版本、日志、明细、回收站的读）给读者；`page.restore_version` 给写者；`node.restore` 给写者；`changeset.revert` 给写者；搜索按笔记本的 `page.read`（只读者以上的笔记本进入过滤的集合）。撤销别人的变更集不另要管理员：写者本来就能改这些页。
- **加锁**：还原版本是正文的写（`FOR SHARE` 笔记本，正文行 `FOR NO KEY UPDATE`）；恢复与撤销是树的单元（笔记本行 `FOR NO KEY UPDATE`，同一笔记本的树写串行），撤销里的正文写按页 id 的次序锁正文行（13.1 第 5 条）。读不加锁。
- **交错**（确定性的测试，结束时 `checkPages`、`checkLinks`）：恢复与删除它原来的父节点；恢复与在原位置新建同名的页（序号）；撤销与对其中一页的并发写（冲突或先写完）；撤销时其中一页被锁（M5 的移交第 3 项）；恢复与清理（期限两侧，墙上的时钟由测试的时钟给）；恢复附件的行与附件的清理（M7 的移交第 2 项）；恢复的任务与在已恢复的部分里删除；还原版本与编辑会话的保存。

## 10. 风险

| 风险 | 缓解 |
|---|---|
| 中文搜索的延迟与索引体积（总体设计 14） | M0/P1 的移交要求的真实语料实测在写设计时进行（4.11 写定）；方案达不到目标时用实测里的备选 |
| 撤销移动时位置不精确：兄弟被重新编号过、条目只有次序的原始值 | 冲突不看次序，按原始值插回；重新编号要连续约 30 次插在同一个间隔里才发生，罕见；精确的做法（条目记前一个兄弟）写进 M12 的移交 |
| 很大的变更集的撤销（几千页的正文） | 一个单元之前解析，合计上限 1,000 页、64 MiB，超过答 422；删除大子树的撤销改走回收站的后台任务 |
| 回收站的大子树恢复要解析全部正文 | 后台任务分批，照导入；途中停下时剩下的仍在回收站 |
| 清理期的边界上恢复与清理相遇 | 期限之内留 1 小时的间隔，清理与恢复从不碰同一批行；asset 的观察者核对行数作为防线 |
| 恢复之后链接的指向变化（恢复的页与别处同名） | 照新建：只重新解析，不改写别的页（M6 4.4）；文档写明 |

## 11. 负责人可以改判的决定

M8 开工时负责人确认进入 M8（2026-10-13："可以了，开始 M8 吧"，输入法清单留到最后统一验收）。下面是设计里的取舍，负责人可以改判：

1. 回收站与历史对读者可见（读者删除之前就读得到这些页）；恢复、还原、撤销要写者，撤销别人的变更集不另要管理员。
2. 整组撤销碰上被编辑的页整体拒绝（`page.locked`，只列第一页），不跳过。
3. 撤销不经链接改写的参与者：被改写的链接从变更集自己的版本行逐字节写回。
4. 撤销的冲突不比较次序；撤销移动时按原始次序值插回，可能不精确。
5. 撤销删除时放回原位置，放不回（父节点不在、标题被占、太深）就冲突；回收站的恢复则改放根下或加序号。
6. 撤销的大小上限 1,000 页、64 MiB 要解析的正文；只删除的撤销（导入的撤销）没有上限，一个单元。
7. 大的回收站恢复是后台任务（与导入共用每本笔记本一个任务的限制），小的在请求里完成。
8. 清理期最后 1 小时之内的回收站项目不再列出、不能恢复。
9. 回收站里的附件预览不给下载地址，恢复之后再下载。
10. 不能永久删除单项、不能清空回收站；不能撤销笔记本、工作区的删除。
11. 搜索只按词的子串匹配（空白分开的词都要命中），不做相关度排序。
