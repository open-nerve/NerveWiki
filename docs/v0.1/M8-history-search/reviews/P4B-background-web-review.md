## 接受与推后的

- **接受**：
  - 不是管理员的写者看不到别的账户的任务，那种冲突不带 A-M2 的那一句（A-N1）：网页没有服务端的提示做不到；04 号文档 4.2 写明。
  - A 的两条存疑（冲突等任务列表读完；同一项的同步与后台的按下同时在途）、B 的两条存疑（被取代的 `load()`；"在历史里查看"在什么都没写时）、C 的存疑（没有客户端的时限）。
  - 修复核对第一轮的两条存疑：服务端的时钟比浏览器快过一分钟时，这个账户在同一目标上、按下之前（时钟差加一分钟）之内结束而 store 没有持有的任务会被当作这次的；慢过一分钟、而这次的任务在查找之前就结束（如计划时就 `revert_conflict`）时说"没有开始"。都要很大的时钟差，旧的规则同样。
  - 等价或走不到的变异：B 的 B8、B9、B14（只有撤销有目标与持锁人，恢复与撤销没有问题列表）；C 的 C2（观察者）；撤销的 `tree_changed` 一例去掉之后它上面的变异（服务端不发）。
  - vitest 输出里约 21 行 `TimeoutNaNWarning`：来自共用的 `test/page-panel.ts`，不是这一阶段的。
  - 流程：TB2（页面）的不稳定从 `aaab10a2` 起就有，实施者连跑三次与整套各一次、审查 C 一次都没碰上，修复核对第一轮在负载下碰上；之后照规则（4.5）改了故事，没有声明 404。
- **推后**：
  - 在请求里撤销正在写的撤销任务的变更集答 409：服务端照旧，见 [P4A 审查](P4A-background-server-review.md) A-M2；网页只在冲突之前加那一句。

  - 同一账户的两个标签页：一个标签页的查找可以取到另一个的进行中的任务（照规则说"已开始"对用户仍对）；按下之前一分钟之内结束、store 没有持有的任务（另一个标签页的、很快结束的）可以被当作这次的（实施者、A）。
