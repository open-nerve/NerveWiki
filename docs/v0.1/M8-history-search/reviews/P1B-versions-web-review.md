## 接受与推后的

- **接受**：
  - 同一对文字在两个视图里各比较一次（A 细节）：每个视图同时至多一个比较，文字变了、重试、卸载时中止；两个都有上限、都会结束，只是重复的工作。01 号文档 4.2 写明。
  - 没有 e2e 走 Worker 的路径（A 存疑，实施者的决定）：构建出的 Worker 由 A 在 Chromium 里以 Worker 的 CSP（`default-src 'none'`）跑过，修复核对第一轮在有 Worker 的全局、没有 DOM 的 `vm` 里跑过；应用里 `new Worker(new URL(…))` 的一行与失败的路径只经假的 Worker 测到。补上要一页超过 32K 个码元的 e2e。
  - 版本页重读右栏读过的每一页版本（B 细节）：随 `readPages`（13.2 第 19 条）而来，代价小。
  - 确认框的 `onCloseAutoFocus` 没有测试（C 细节）：成功之后版本页随即卸载，焦点由页面的标题取得。
  - 假的服务端的 `editing` 不由会话推出、保存不移动会话的版本（C 细节）：测试经 `withVersions` 手设。
  - 细分的 `scanLimit: 500` 没有测试（N3）：只影响细分的质量与时间。
  - `readEnded` 偶尔多读一次列表（N4）：SWR 不给出一次读开始的时刻，分不出在途的读是在见到持锁之前还是之后发出的；多一次读无害。
- **推到 v0.1 之后的打磨**（负责人的决定：小的体验问题在 v0.1 结束之后一并处理；已写进 [M12 的打磨移交](../../M12-release/handoffs/M5-polish.md) 第 21 条）：
  - 相对时间不走，只在列表重读时更新（实施者）。
  - 同一句"没有改动"连说两次不再播报：附件一节交替加不换行空格的做法没用在这里（实施者）。
  - "已还原到版本 N"在这一条历史里：刷新、返回时再说一次，同一次访问里之后的编辑也还留着（实施者、B）。
  - 版本列表读不到时版本页没有"还原"，也不说为什么（实施者）。
  - 版本页没有上一个、下一个版本的导航，面包屑回到页面（实施者）。
  - 确认框里的比较随焦点与事件的重读刷新，没有播报（实施者；N1 之后刷新期间"还原"不可用、写着"正在比较…"）。
  - "显示未改动的行"在没有改动、只差换行、并排时也显示，按了不起作用（A）。
  - 只差最后一行的换行时显示 `−x`、`+x`，看不出差别；可以说明"只差最后的换行"（A；HI1 的方向断言钉住了这种画法）。
  - "N 处改动"数的是视图的块：只隔一个空行的两处算一处，整页改写是"1 处改动"，上一处、下一处没用（A；库的语义）。
  - 同一页的两个版本之间后退、前进时，按页挂载的 `VersionShell` 留着选的标签页与上一个版本说的话（B）；"与上一版"开着时它的基版本可能正是去掉的键，重读、闪一下"加载中"（修复核对第一轮）。
  - A-M5 的并排写"+0 −5000 行，太大，不能逐行比较"，行数却在上限之内：太大的是画出的那一块（修复核对第一轮）。
  - 升级去掉旧的 Worker 脚本之后"重试"一直失败，说"重新加载页面"才有用（修复核对第一轮）。
