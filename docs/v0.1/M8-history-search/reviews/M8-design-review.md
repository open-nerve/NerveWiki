### Important

| # | 发现 | 处置 |
|---|---|---|
| A-I1、C-I2 | 撤销按版本号比较正文：撤销把旧字节写成新版本，"撤销 C2 再撤销 C1"永远冲突，M11 的按时间倒序回滚做不到；树按状态、正文按版本号，两种含义；M8 之前的新建条目没有 `revision` | 一律按状态比较：正文比 `content_hash` 与 C 留下的正文的哈希，树比活着与否、父节点、名称、次序值；`revision` 只记恢复时的版本，迁移给已有的新建条目补上；性质测试改为从新到旧连续撤销 k 个（4.2、4.8、第 9 节） |
| A-I2、C-I4、B-M13 | 撤销的上限 1,000 页、64 MiB 与解析预算不合：提取结果留到单元结束，第 8 个 5 MiB 的页永远拿不到预算，其间全实例的阅读与保存排在它之后；没有链接与节点的上限；同一次恢复走撤销是一个单元、走回收站是后台任务，界线不一 | 恢复与撤销用同一条界线：要解析的不超过 100 页、8 MiB、20,000 条链接（与导入的一批相同），树的操作数由 P2 实测；从大到小解析；超过答 422，网页问是否在后台进行（4.9） |
| A-I3、C-I3 | 一次导入的撤销"一个单元、不设上限"：5 万个节点的删除已接近 15 秒的期限，平铺在根下的导入是 5 万次删除，再加核对，都在笔记本的锁下；推翻了 M7 移交第 4 项的分批，理由不成立 | 取消这个例外：超过界线的撤销是后台任务，分批、并入一个变更集、每批重新核对、报告（4.9、4.10，P4）；删除与恢复用整组的语句 |
| A-I4、C-I1 | `restoreNode` 答 202 要开 transfer 的任务，page 没有到 transfer 的端口，构建次序是 page → asset → transfer，依赖会成环 | page 超过界线时答 422；网页再请 transfer 的 `startTrashRestore`、`startRevert`；依赖仍是 transfer → page；一本笔记本一个写入任务的索引覆盖三种任务（4.1、4.10、第 5 节） |
| A-I5 | 后台恢复的批与批之间没有定义：恢复了的父节点被再删、被移深、被人建了同名的兄弟，剩下的成了一个个根，期限不再核对；"只有根会撞名"对任务不成立 | 每批在锁下核对父节点、层级、名称（加序号）、只恢复仍是同一时刻删除的、期限；剩下的设上 `trash_root`（4.10）；"只有根会撞名"限于一个单元（4.6） |
| A-I6、C-M9 | 撤销的次序与冲突规则只对单一操作的变更集成立：建文件夹再移入，误报 `children_added`；删除再建同名、连环改名，误报 `title_taken`；`Change.Then` 会丢掉新的标志；`item.revision` 会过时 | 先算目标状态 S\* 一次核对全部（含 `cycle`），再按依赖逐个应用，只剩名称的环时用临时名称；`Then` 保留 `Restored`；正文按 C 的版本行优先（4.8） |
| B-I1 | 比较的设置不对：`scanLimit` 把超过约 16,000 码元的改动合成一整块（3 万字的页改 8 个词显示为整页重写，现有的冲突对比已经如此）；`timeout` 管不住全部算法（20 万字的重复行 90 秒算不完）；删除的大段是一整块 DOM | Web Worker 里按行比较、硬性期限、经 `diffConfig.override` 交给只读视图；超过上限给摘要与并排；`ConflictDiff` 一并改；上限处的测试（4.3） |
| B-I2、A-M5、C-M6 | 回收站里的页渲染时每条链接都成了未解析：来源页的路径只读活着的节点；预览与版本页都在页面的外壳之下，外壳对不在树里的页答 404 | 来源已删时按它原来的路径解析（page 的 `Paths` 的来源变体）；预览有回收站自己的路由（4.1、4.5） |
| B-I3、C-M5 | `removed` 只在本标签页自己恢复之后去掉：撤销删除、后台任务、别的标签页与别人的恢复之后，页仍藏着、打开就被转走 | 一次开始于删除答复之后的树的读把它列为活着时去掉；撤销里的删除照 `remove` 记下；恢复与撤销经树的写入队列（4.13） |
| B-I4、C-M15 | 没有读单个变更集的接口："在历史里查看"、"撤销了…"、指向回收站都做不出来 | `getChangeset`，带 `reverts` 与 `reverted_by`；单个变更集页（4.7、4.13） |
| B-I5、A-M8、C-M7 | 附件在搜索结果与回收站预览里的类型与大小在 asset 的表里，page 读不到；点开之后再取签名地址打开新标签页会被浏览器拦下 | 只凭连接池的 `asset.NewMeta`（含已删的）经 `Deps` 交给 page；搜索结果打开附件所在的位置，不签发地址（4.1、4.12） |
