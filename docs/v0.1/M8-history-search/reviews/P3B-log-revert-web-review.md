## 接受与推后的

- **接受**：
  - 撤销答 404、整页换成 `NotFoundPage` 时焦点落到 `body`，原因听不到（A-N2）：设计要的流程，要变更集整个被清理或笔记本没了，罕见；改法写进打磨。
  - 撤销在途时回到它要删的那一页，先显示"页面不存在"再去笔记本首页（A-N3）：只在途中回到那一页时有；改法写进打磨。
  - 确认框开着时角色被拿走或变更集被截掉，确认框随按钮卸载（A 存疑一）：没有复现。
  - "结果未知"的 `before` 比别人的撤销旧时说的是别人的撤销（A 存疑二）：说的是实情。
  - `idPattern` 不认服务端也认的几种 UUID 写法（B 存疑）：应用里的链接不会有。
  - 不算发现的存活变异：实施者的 `st-after-zero`（等价：只在开始于答复之后、被保留的读之后才记，之后保留的读更新）与 `cp-found-unmounted`（等价，守卫去掉）；B 的 `hp-only-other-filter`（客户端筛选也在时"只看此人"出现在这个人自己的行上，太窄）、两个等价（`st-before-unfiltered`、`cp-findout-data`）与 e2e 的 `ew-revert-not-queued`（撤销不经树的队列：HI4 的树的轮询经事件的读也满足，队列由 vitest 钉住）；C 的 `rd-reread-any-notebook`（没挂着的键只丢掉 SWR 的去重项，无害）；修复之后的 `rd-cancel-prevent`、`cp-more-list-unnamed`、`pv-list-unnamed`（等价，代码去掉）；核对者的 `rn-last-undefined`（等价，打磨）。
  - vitest 输出里约 20 行 Node 的 `TimeoutNaNWarning`：不是这一阶段的（P2B 的门禁里同样有）。
- **推后**：
  - 日志的读是两条语句、不开事务（C 的存疑）：读跨过一次撤销的提交时，可能列出"已撤销"的改动而没有那条撤销，到下次重读为止；服务端上没有复现；作为读的一致性待查的一项写进 [03 号文档](../03-P3-log-revert.md)第 8 节 M12。
  - 422 改为问是否在后台进行，任务的"在历史里查看"：P4（03 号文档第 8 节）。
- **推到 v0.1 之后的打磨**（负责人的决定：小的体验问题在 v0.1 结束之后一并处理；已写进 [M12 的打磨移交](../../M12-release/handoffs/M5-polish.md) 第 23 条）：
  - "撤销"在英文里一个词：P3A 加的 problem 文字说 "reverted"（"it can no longer be reverted"），网页说 "undo"；`page.changeset_trimmed` 说"这次改动的一部分…"，清理拿走全部时也答它（实施者、C）。
  - 撤销自己的页英文标题 "Undo change · Ada"，按钮也是 "Undo change"；按钮写 "Undo this change" 更好读（实施者）。
  - 根下：历史与回收站写"笔记本首页"，移动的对话框写"笔记本的顶层"（实施者，偏离 9）。
  - `parent_gone` 的"回收站"链到列表、不链到那一项（冲突不点名上级）；英文 "The page “X” was under is gone" 读来含糊，中文清楚（实施者、C）。
  - "谁"列出工作区的全部成员，不只这本笔记本里有角色的（实施者）。
  - 历史没有总数（服务端没有）："列出 50 条，还有更多"只说读到的（实施者）。
  - 撤销之后回到历史页，撤销之前的列表先显示一个往返：确认框的重读只让没挂着的日志的键丢掉去重项（实施者、C）。

  - 版本页的链接写"Ada · 编辑"（执行者在前），去的页标题是"编辑 · Ada"（C）。
  - 撤销在途时后退再前进，重新挂载的变更集页不知道在途的撤销：没有状态行，"撤销"不忙，再按得到冲突（同 P2B 修复核对 N4，同一个改法：在途的写与结果放进 store）（A）。
