# 中文搜索方案的复核

M0/P1 的实验 ①（[结果](../../M0-foundation/01-P1-spikes.md) 第 7 节）用随机拼出的中文测了 pg_trgm。随机文本的三元组几乎不重复，结论只代表罕见词：

- 3 个字以上走 GIN 索引，罕见词 0.4 ms；每一行都包含的词复查 5 万行，约 220 ms。
- 1–2 个字只能顺序扫描，5 万行约 250 ms，随数据量线性增长。2 个字是中文最常见的查询长度；工作区全局搜索跨多个笔记本，无法靠"限定笔记本"兜底。
- GIN 索引最坏是表的 5.3 倍。

M8 写设计之前：

1. 用真实的中文语料实测，例如中文维基百科的一个子集，按一个团队几年的笔记量级，数十万页、数 GB。测量：
   - 常见与罕见的 2 字、3 字、4 字词，以及中英混合词的延迟（p50 / p99）；
   - 索引体积与构建时间；
   - 写入时维护索引的开销。

   造数与查询的写法可以参考 P1 文档第 8 节。
2. 不达标时评估备选方案：由应用计算 CJK 二元组，存成 `tsvector('simple')` 列，建 GIN 索引，查询拆成二元组做 `@@`，再用 `ILIKE` 复查。它仍然只需要 PostgreSQL。
3. 把结论写进 M8 的设计，并更新总体设计的 1.3（中文搜索）与 14（风险表）。
