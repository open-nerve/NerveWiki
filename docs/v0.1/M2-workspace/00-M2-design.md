## 1. 目标

M2 结束时：

1. **工作区**：创建（`workspace.creation_enabled` 为开关，关闭时由服务器管理员用 `nervewiki workspaces create` 创建）、列表、读取、改名、删除（软删除，60 天后物理清除）；slug 规则与保留名单。
2. **成员与角色**：三种角色 `admin`、`member`、`guest`；成员列表、改角色、移出、离开；唯一管理员的两条规则；停用账户会结束他的工作区成员身份，由 `nervewiki workspaces reactivate-member` 恢复。
3. **邀请**：管理员按邮箱邀请，复制链接后自己发给对方，可以删除邀请。被邀请人在邀请页预览并接受；注册关闭时，持有效邀请、邮箱一致的人仍可注册。系统不发邮件。
4. **access 模块**：权限规则表与判定，实现 `shared.Authorizer`；权限矩阵测试框架。M2 的每个需要判定的工作区操作在规则表里占一行；只涉及调用者自己的、不指向某个工作区的操作不判定，矩阵仍有它们的行。
5. **扩展点**（总体设计 12.4）：
   - 注册 M1 建立的三个：停用的否决者与事件、新手引导的工作区一步、注册策略。
   - 建立四个：工作区成员身份结束（否决者与事件）、成员身份恢复（事件）、工作区删除（事件）、软删除的清理注册表。
   - 建立权限规则表与判定级别。
6. **应用外壳**：
   - `/:slug` 的工作区布局；左栏骨架带工作区切换，笔记本的位置留给 M3。
   - 登录后的落点。
   - 工作区设置：常规页、成员与邀请页。
   - 公开的邀请页。
7. **平台**：组合根的拆分、接口测试的构造辅助、软删除的清理任务。M1 移交的 10 项，每一项落实或说明理由转出（第 7 节）。

## 2. 范围

**做**：第 1 节各项，以及它们的接口描述、页面与端到端故事。

**不做**：

| 事项 | 理由与去处 |
|---|---|
| 笔记本、无主笔记本、工作区的审计记录 | M3。审计记录随"接管、删除无主笔记本"一起到来（总体设计 3.4） |
| 邀请的"忽略" | 被邀请人不理会即可，管理员可以删除邀请。去掉它，就少了"已回应"这种状态，也少了一类并发 |
| 一次邀请多个邮箱 | 每份邀请一个链接，管理员要逐个复制。批量插入两批重叠的邮箱时，必须按键排序才不会死锁（Nerve 的约定五）；单个插入不需要这条约定 |
| 修改邀请的角色 | 删除后重新邀请即可 |
| 邀请的有效期 | 接受要求登录邮箱与邀请邮箱一致，链接本身不给任何访问；管理员删除即失效（与 Nerve 相同） |
| 工作区图标、时区、组织规模；工作区的个人显示设置 | 没有使用者。最后访问的工作区记在设备上（第 4 节） |
| 列出已结束的成员关系 | 成员页只列有效成员。已结束的行保留下来，供恢复（`reactivate-member`、再次接受邀请）与 M3 的无主笔记本使用 |
| 恢复已删除的工作区 | v0.1 没有这个操作。软删除是为了让物理清除与附件文件的删除按顺序完成（第 4 节）；60 天内运维可以从数据库恢复 |
| 由请求投递的后台任务 | M2 只有定时的清理任务。M1 移交第 10 项（只投递的 River 客户端）转给 M7 的导入导出 |
| 成员角色变化的事件 | 第 4 节 |

## 3. 完成标准

- 本 M 的故事全部通过（本地 `make e2e` 与持续集成），之前各 M 的故事仍然通过。S2 随首页调整；用到 `registerOnboarded` 的故事随引导的新步骤调整：

  | 故事 | 内容 | 版本 |
  |---|---|---|
  | W1 创建工作区 | 创建者成为管理员并进入工作区。slug 的格式、保留与占用，由检查接口和创建同时把关。落库：工作区与成员行 | 页面、PAT 接口 |
  | W2 创建开关与命令 | `creation_enabled = false` 时接口答 403，页面没有入口。`nervewiki workspaces create` 创建工作区并指定管理员；账户不存在或已停用时退出码 1，数据库不变 | 页面、PAT 接口、命令行 |
  | W3 外壳与切换 | 左栏切换工作区。`/` 依次落到：最后访问的工作区；不在列表里时，按名称排第一的；一个都没有时，创建页或"等待邀请"。不是成员的 slug 答 404 | 页面、PAT 接口 |
  | W4 改名与删除 | 管理员改名。删除需要输入 slug 确认，之后所有成员都看不到它，slug 可以再用。落库：软删除连带成员与邀请。非管理员答 403 | 页面、PAT 接口 |
  | W5 邀请 | 管理员邀请邮箱、复制链接、删除邀请。邮箱已是成员或已有邀请，答 422；非管理员答 403。数据库里没有令牌 | 页面、PAT 接口 |
  | W6 接受邀请 | 已有账户的被邀请人打开链接，看到预览，接受后进入工作区。登录邮箱不符答 403；已是成员时角色不变；邀请已删除、令牌不对答 404。页面发出的请求，地址里都没有令牌 | 页面、接口 |
  | W7 带邀请注册 | 注册关闭时，在邀请页用被邀请的邮箱注册并接受；用别的邮箱注册答 403 `identity.signup_disabled` | 页面、接口 |
  | W8 成员与角色 | 成员列表（访客看不到邮箱）；管理员改角色，但不能改自己的 | 页面、PAT 接口 |
  | W9 移出与离开 | 管理员移出成员；成员离开；唯一管理员不能离开。成员关系结束时，删除发给他的待接受邀请。之后他看不到这个工作区 | 页面、PAT 接口 |
  | W10 停用与恢复 | 他是某个还有别的成员的工作区唯一的管理员时，停用被拒：页面的对话框与 `users deactivate` 都给出原因。停用结束他的成员关系；`users activate` 加 `workspaces reactivate-member` 恢复 | 页面、PAT 接口、命令行 |
  | W11 引导的工作区一步 | 新账户在引导中创建工作区；已经经邀请加入了工作区的，直接继续；创建关闭又没有工作区的，看到说明后继续 | 页面、PAT 接口 |
  | W12 软删除的清理 | 删除超过保留期的工作区，由后台任务连带成员与邀请物理删除；保留期内的不动 | 后台任务 |

- **对等验收的例外**（总体设计 10.1）：
  - 邀请的预览与带邀请的注册发生在取得令牌之前：W6、W7 的接口版本直接调用公开的预览与注册接口。
  - W2、W10 的命令行部分与 W12 只能由命令行或后台任务完成，只有那一个版本。
- 本 M 建立的扩展点已建好，并有测试证明注册者能挂上去（第 8 节）。M1 的三个扩展点已注册，有经接口与经命令行的行为测试（总体设计 13.1 第 21 条）。
- 权限矩阵覆盖每个需要判定的操作（第 9 节）。
- 满足总体设计 12.5 的其余各项；M1 移交的 10 项全部处理（第 7 节）。

## 4. 关键决定

| 决定 | 选择 | 放弃的方案及原因 |
|---|---|---|
| 模块 | 两个模块：`workspace` 管工作区、成员、邀请；`access` 管规则表与判定，没有表。access 经端口读成员关系，端口由 `workspace` 用只凭连接池的构造（`workspace.NewMemberships(pool)`）实现，组合根接上 | 用例自己判断角色：M3 加笔记本级之后每个模块各写一遍，矩阵也无处统一。access 直接查 workspace 的表：要在 sqlc 的模块范围上开例外 |
| 角色的表示 | 接口与数据库都用字符串 `admin`、`member`、`guest`，数据库用 CHECK 约束。规则按集合比较；需要比较高低时（M3 的有效角色）经显式的次序表。修订总体设计 3.2、3.3 | Nerve 与 Plane 的 20/15/5：数值诱导按大小比较，而总体设计本来就禁止；字符串在接口、日志与数据库里一看就懂 |
| 判定 | `shared.Authorizer.Authorize(ctx, actor, action, target) (Grant, error)`。规则表以操作名为键；操作名在各模块的 `domain/actions.go` 中声明，组合根的测试核对各模块操作名的并集等于规则表的键。拒绝有两种：看不到的是 `shared.ErrNotVisible`，由用例换成自己的 404 码；看得到而不能做的是 403 `forbidden`。写操作锁住工作区行之后才判定 | 操作名放进 `shared`：每加一个操作都要改 `shared`。先判定、后加锁：两位管理员互相降级时，双方的判定都在对方提交之前读到"管理员"，结果一个管理员都不剩（Nerve 的实验） |
| 判定级别 | M2 只有工作区级。M3 加笔记本级，带它自己的事实端口与判定，不改工作区级的代码。修订总体设计 12.4 | — |
| 成员关系的行 | 每对（工作区，账户）在 `workspace_members` 中只有一行。`ended_at` 记成员关系结束的时刻（移出、离开、停用），恢复即清空。工作区删除时整行软删除 | Nerve 的 `is_active`：丢了结束的时刻，排查问题与 `reactivate-member` 的输出都需要它 |
| 唯一管理员 | 规则一：唯一的有效管理员不能离开，哪怕只有他一人（409 `workspace.sole_admin`）。规则二：停用账户时，他是某个还有别的有效成员的工作区唯一的有效管理员，就拒绝；那里只有他一人时允许（恢复见 W10）。改角色不能改自己的（409 `workspace.own_membership`），也不能移出自己。这些判定都在锁下进行，所以改完之后，至少还剩发起操作的那位管理员 | Plane 在四处检查唯一管理员，写法各不相同，其中三处有缺陷（Nerve M3 设计 3.7） |
| 扩展点的形状 | 照 M1 的停用：否决者在锁住相关的工作区行之后、写入之前同步调用，返回 `*shared.Error` 就整体回滚；订阅者在写入之后、同一事务内调用。"成员身份结束"这个值带：一组工作区 id（停用一次结束多个）、原因（移出、离开、停用）、账户与时刻。M2 在自己的停用注册者里转调成员身份结束的否决者与订阅者，所以 M3 只注册一处，就覆盖了移出、离开、停用三条路 | Nerve 的同步端口 `ProjectCascade`：只能接一个接收方，而 M3 之后还有可见性变化（M5）。M3 直接注册到 identity 的停用：移出与离开还要再注册一次 |
| 工作区删除只有事件 | 删除是管理员显式的破坏性操作，v0.1 没有应当阻止它的规则。修订总体设计 12.4 | 照 12.4 的原文同时建否决者：既没有注册者，也想不出一个 |
| 角色变化没有事件 | 有效角色在读取时计算（总体设计 3.3），"访客不享受默认权限"随读取即时生效 | 现在就建：没有使用者。M3 若需要在降为访客时改笔记本的行，按 12.1 第 6 条的例外修订（第 10 节） |
| 邀请令牌 | `nwk_inv_` 加上对邀请 id 的 MAC（截断）。MAC 密钥由签名私钥经 HKDF 派生（info `nervewiki workspace-invitation mac v1`）：identity 以 `DerivedKey(用途)` 交给组合根，组合根再交给 workspace。令牌不存库，列出邀请时重新计算，管理员随时可以复制。代价：换签名密钥之后，待接受的链接全部失效 | 存随机令牌的哈希：只能在创建时显示一次，与"随时复制链接"冲突。存原文：数据库泄露，链接也就泄露 |
| 令牌只在地址的片段里 | 链接是 `/invitations/<id>#<令牌>`。预览与接受都把令牌放在请求体里；预览因此是 `POST …/preview`，属于 6.1 的方法例外：携带秘密的读取。片段不发给服务器，也不进 Referer，所以不会出现在反向代理的访问日志里 | Nerve 的 `?token=` 查询参数：nginx 的默认日志格式记录完整的请求行 |
| 邀请页公开 | `/invitations/:id` 在登录守卫之外，是 13.2 第 10 条的例外。页面先显示预览：未登录时在页内登录或注册（注册带上邀请），已登录时接受。页面始终停留在带片段的地址上，所以令牌从不进入 `next` | 放在 `SignedIn` 之下：守卫会把带片段的地址编进 `next` 查询参数，令牌又回到地址里；而且注册关闭时，登录页还得认识邀请 |
| 带邀请注册 | 注册策略扩展为 `SignupPolicy.AllowSignup(ctx, attempt)`，`attempt` 带注册邮箱与可选的邀请；`register` 的请求体加可选的 `invitation {id, token}`。注册打开时照旧；关闭时，只有邀请有效、注册邮箱（规范化后）等于邀请邮箱才允许。邀请无效的各种情况一律答 403 `identity.signup_disabled`。注册不替用户接受，页面接着调用接受。组合根组合"配置开关"与 workspace 提供的邀请检查，identity 不认识邀请 | 另加一个端口：注册的判断分散到两处 |
| 接受与已有的成员关系 | 邀请从不改变有效的成员关系。已是有效成员时只消费邀请，角色不变；成员关系已结束时恢复那一行，角色取邀请的，并发布"成员身份恢复"；没有行时插入。结束成员关系的事务同时删除这个工作区里发给他邮箱的待接受邀请 | 让接受覆盖有效成员的角色：Nerve 的 Codex 审查（S2）由此让工作区一个管理员都不剩 |
| 账户行与增长 | 创建工作区、接受邀请、`reactivate-member` 的第一条语句都是 `ShareActiveAccount`。它改为在没有事务时报错（M1 移交第 3 项），并交回锁下读到的邮箱，供接受与邀请比较。`reactivate-member` 要求账户可用，所以要先 `users activate` | Nerve 照 Plane 允许恢复停用账户的成员关系：在两步之间，这个成员关系计入管理员人数，而他还不能登录 |
| 最后访问的工作区 | 记在设备上：localStorage 的 `nwiki.workspace`，只存 slug。落点是一个纯函数，取它与工作区列表的交集 | 服务端的 `last_workspace_id`（Nerve 的 `profiles` 列）：要多一列、一个写接口，只换来跨设备的同一个落点 |
| 清理注册表 | `platform/jobs` 提供定时的清理任务：按注册的顺序调用各模块的清理器（`Purgers()`），每个清理器按批物理删除 `deleted_at` 早于保留期（60 天）的行。组合根从叶到根排列各模块，数据库测试核对每条外键的子表排在父表之前 | 每个模块各一个定时任务：顺序无从保证，而 M7 的附件文件必须在它的行消失之前删掉 |
| 删除工作区的后果 | 连带工作区里所有的笔记本（M3 起），包括成员的私密笔记本。页面要求输入 slug 确认，文案写明这一点 | 要求先移出其他成员：被移出者的私密笔记本成为无主，删除工作区时照样被删除，只是多了几步 |

## 5. 接口

新增 15 个操作，都在 `api/modules/workspace.yaml`：

| 方法与路径 | 认证 | 成功响应 |
|---|---|---|
| `GET /api/v0/workspaces` | Bearer | 200 `{data: Workspace[]}`（调用者有效成员关系所在的，按名称） |
| `POST /api/v0/workspaces` | Bearer | 201 `Workspace` |
| `GET /api/v0/workspaces/{slug}` | Bearer | 200 `Workspace` |
| `PATCH /api/v0/workspaces/{slug}` | Bearer | 200 `Workspace` |
| `DELETE /api/v0/workspaces/{slug}` | Bearer | 204 |
| `GET /api/v0/workspace-slugs/{slug}` | Bearer | 200 `{available, reason?: taken \| reserved \| invalid}` |
| `GET /api/v0/workspaces/{slug}/members` | Bearer | 200 `{data: WorkspaceMember[]}`（有效成员，按加入时间） |
| `PATCH /api/v0/workspace-members/{workspace_member_id}` | Bearer | 200 `WorkspaceMember` |
| `DELETE /api/v0/workspace-members/{workspace_member_id}` | Bearer | 204 |
| `POST /api/v0/workspaces/{slug}/leave` | Bearer | 204 |
| `GET /api/v0/workspaces/{slug}/invitations` | Bearer | 200 `{data: WorkspaceInvitation[]}`（新的在前，含令牌） |
| `POST /api/v0/workspaces/{slug}/invitations` | Bearer | 201 `WorkspaceInvitation` |
| `DELETE /api/v0/workspace-invitations/{invitation_id}` | Bearer | 204 |
| `POST /api/v0/workspace-invitations/{invitation_id}/preview` | 公开 | 200 `InvitationPreview`（工作区的名称与 slug、邀请的角色；不含邀请的邮箱） |
| `POST /api/v0/workspace-invitations/{invitation_id}/accept` | Bearer | 200 `Workspace` |

- **别的模块的修改**：
  - `register` 的请求体加可选的 `invitation`。
  - `deactivateMe` 的 `x-problem-codes` 加 `workspace.sole_admin`。
  - `GET /instance` 加 `workspace_creation_enabled`。
- **结构**：
  - `Workspace` 带调用者的 `role`。
  - `WorkspaceMember` 内嵌对方的公开资料（显示名；邮箱只给管理员与成员，访客看到 `null`）。这是"关联字段只给 id"的例外：v0.1 没有读取别的用户的接口，成员列表是看到同事名字的唯一来源。
  - 公开资料由 identity 提供的不加锁端口读出。
- **模块码**：

  | 码 | 状态 |
  |---|---|
  | `workspace.not_found` | 404 |
  | `workspace.creation_disabled` | 403 |
  | `workspace.slug_taken` | 409 |
  | `workspace.member_not_found` | 404 |
  | `workspace.own_membership` | 409 |
  | `workspace.sole_admin` | 409 |
  | `workspace.invitation_not_found` | 404 |
  | `workspace.invitation_email_mismatch` | 403 |

  另外：
  - 规则表的拒绝是平台码 `forbidden`。
  - 保留的 slug 是字段错误 `slug: not_allowed`。
  - 邀请已是成员的邮箱是 `email: not_allowed`，已有邀请是 `email: duplicate`。
  - 创建工作区与接受邀请声明 identity 的 403 `identity.account_deactivated`（`ShareActiveAccount` 在锁下发现账户已停用）。
- **限流**：不加新的桶。公开的预览按 IP 计数（`anonymous`）：令牌是 128 位的 MAC，没有可猜的空间。

## 8. 本 M 建立的扩展点与约定

**工作区成员身份结束：否决者与事件**（M3 注册：笔记本唯一管理员的否决、结束笔记本成员身份、无主处理）：

- 注册者在 `bootstrap/registrants.go` 组合，交给 workspace 的 `Deps` 与它的停用注册者。移出、离开、停用三条路调用同一组注册者。
- 否决者与订阅者收到同一个值：账户、一组工作区 id、原因（`removed`、`left`、`deactivated`）、时刻。
- 否决者在这些工作区行锁住之后（`FOR NO KEY UPDATE`，按 `id` 升序）、任何写入之前调用。返回 `*shared.Error` 时整体回滚；注册者把这个码写进 `removeWorkspaceMember`、`leaveWorkspace`、`deactivateMe` 的 `x-problem-codes`。`deactivateMe` 的码在 identity 的 HTTP 测试中答出（13.1 第 21 条）。
- 订阅者在成员行写入 `ended_at` 之后、同一事务内调用。
- 调用期间，他的成员关系集合不会再变大：停用持有账户行，移出与离开持有工作区行。所以订阅者在调用时列举自己的行即可，不必接收事先列好的清单。

**工作区成员身份恢复：事件**（M3 注册：归还无主笔记本）：

- 接受邀请恢复一个已结束的行，或 `reactivate-member` 恢复时触发。
- 值：工作区、账户、角色、时刻。在恢复的写入之后、同一事务内调用。

**工作区删除：事件**（M3 注册：软删除笔记本；M4、M7 再经 M3 的笔记本删除事件处理各自的行）：

- 值：工作区、删除者、时刻。
- 订阅者以这个时刻作为 `deleted_at`，与工作区一侧相同，清理任务按同一时刻把它们一起清掉。

**权限规则表与判定级别**（M3–M11 注册）：

- 每个操作在 `access/domain` 的规则表里占一行：级别加允许的角色集合。
- 操作名在模块的 `domain/actions.go` 声明，组合根的测试核对并集等于规则表的键。
- 矩阵测试覆盖每个需要判定的操作。
- M3 加笔记本级：事实端口在 `access/app` 声明，由 notebook 模块以只凭连接池的构造提供实现。

**软删除的清理注册表**（M3、M4、M7 注册）：

- 模块经 `Purgers()` 提供清理器（名称，加上"删除早于某个时刻的一批行"）。
- 组合根按从叶到根的顺序排列，由外键顺序的数据库测试守住。
- 保留期在配置中设定，默认 60 天。

**注册 M1 的扩展点**：

- 停用的否决者与订阅者：规则二、结束成员关系、转调上面的成员身份结束。
- 引导的工作区一步（id `workspace`）。
- 注册策略。

**全局加锁顺序**（修订总体设计 13.1 第 5 条）：

- 账户行之后分两支：
  - 凭证：`users → auth_sessions → api_tokens`；
  - 工作区：`users → workspaces → workspace_invitations → workspace_members`。
- 同一张表的多行按 `id` 升序取锁。
- 凭证一支的行，只由先锁了同一账户行的事务、或只碰一行的单条语句锁住。所以停用在两支之间交替（账户行 → 工作区 → 会话 → 邀请与成员）也不会成环：凡是要等它所持会话行的事务，都先要它已持有的账户行。
- 写成员关系与邀请的事务先锁工作区行：
  - `FOR NO KEY UPDATE`：成员与角色的一切变化（含接受邀请），改、删工作区；
  - `FOR SHARE`：创建、删除邀请。
- 锁工作区的语句带 `deleted_at IS NULL`：等锁之后读到 0 行，就答 404。
- 增长路径的第一条语句是账户行的 `FOR SHARE`。
- 插入引用别的账户的行时，外键检查只对那一行取 `FOR KEY SHARE`，与停用的 `FOR NO KEY UPDATE` 不冲突。

**横切约定**：本 M 新建的约定（权限与矩阵、加锁顺序、扩展点的注册、公开页面的例外、清理），收尾时经审查对照代码核实，补进总体设计第 13 节。
