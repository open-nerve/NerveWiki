## 主持者的决定

负责人可以改判；写进 [00 号文档](../00-M12-design.md)第 11 节"2026-11-19：P2/S6 的决定 625–632 "。625 在实施之后、审查之前定，放在修复第 1 轮做；626–628 在修复第 1 轮；629–632 是实施与修复里改了设计写法的几处，照 S4 的先例收窄编号，其余写在"实施中定的"、不编号。

- **625 "移到……"对话框的子树与高度在循环外算一次**（实施报告 5.1；审查 C 的 Q1）：`MoveForm` 对每一页调 `canHold`，每次重算被移的页的子树与高度。`page-tree.ts` 加 `holdersOf(tree, id)`，答一个判断函数；`canHold` 不改（拖放仍用它，测试拿它作参照）。那一格在深与平两种形状里对根与每一页比两者，另把答"能"的页按名字整列写出。深的形状一轮，同一会话各自构建：改前中位数 1,008 ms，改后 190 ms。
- **626 27.2 设计原文的两处在 S6 修**（审查 A 的 M1、M2、Q1）：卸下时没读过的树也标未确认；`PageLayout`、`VersionPage` 挂上时未确认就记下缓存里的错误，`NotLoaded` 只说别的，已确认时挂上不记。设计 4.6.7 的 27.2 随之改。
- **627 macOS 上方向键等不算一步**（审查 B 的 Q1，取甲）：`onMac()` 时方向键、Home、End、PageUp、PageDown 不算一步，只有打字找选项的单个字符算。理由：方向键在 Mac 上若真是逐项换，照甲也只是立即用，与今天相同；照乙，方向键打开的列表里的选择要等离开，比今天更坏。测试 mock 平台；macOS 上真的 Safari 与 Chrome 进发布之后的人工清单。
- **628 22.2 的 `merged` 留在外壳**（审查 C 的 M2）：项离开回收站又回来时照旧说；设计放在外壳本就为了这一种。代码不变，补一格；设计 22.2 的变异一条改成"不等价，由某格抓"。
- **629 24.8 的表项读完并显示才删**（实施；审查 B、C 核过）：设计写"读函数开始时取出并删掉"；刷新器在键最近没读过时当场开始读，照字面写，紧接着的 `links` 事件就看不到它。表项带 `started`，读开始时标上，读完并显示之后 `settle`、是同一项才删；读的途中又来树变了的 `pages` 事件，放一个新的。修复第 1 轮另让 `afterTree` 等过之后先看这一代停了没有（审查 B 的 N2）。
- **630 26.5 `useChoice` 的按键**（实施；审查 B 的 M1、M2、N4）：每次按键都重设"下一个 `change` 是不是一步"（设计只在一步的键上设真）：之前一次没换值的方向键不让下一次列表里的选择也等着；`stepping` 另排除 Ctrl、Meta；有等着的选择时回车 `preventDefault`，不让 Chromium 打开列表；用的值已在用时不再读。
- **631 22.19 的面包屑与跟随的 `not_trash_root`**（审查 A 的 M3、N2、N3）：外壳给面包屑包一层带 `useFocusLeaving` 的 `Trail`（另一种"`NotInTrash`、`Gone` 也画面包屑"不取：说明页的标题是"回收站"，单项可能还没读到）；面包屑 `mb-2`、alert `mb-4`，到标题 0.5rem；`refusedOf` 的 `item` 可缺，带 `root_id` 的 `not_trash_root` 不等单项，别的拒绝在单项没读到时照旧不说。
- **632 21.10 另一个版本显示时清掉说的话**（实施；审查 C 核过）：设计写"只在 `said.of === data?.id` 时显示"，只比 `of` 时前进回到 4 又说，设计自己的格红；显示仍比 `of`，管另一版本还在读的那一段。
