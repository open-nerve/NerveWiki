## 设施的问题

决定 641：S3 不改服务端的代码，这几件都不在 v0.1 修，进 v0.2 的移交（`M12-performance.md`，收尾时写）；第 7、8 条是修复第 1、2 轮加的：

1. **升级批准守卫在规模开关下的计划断言**：`NW_SCALE_PAGES=100000` 只放大被量的那一本（1,053 个文件夹各 4 个附件），旁边四本各 2,000 个，这一本取到约三分之一的行，`plans_alone` 的 `AttachmentInfos` 走 Seq Scan，两轮与 30 万的两次都红在这里（计时完整）。该随规模放宽，还是附件也随规模放大。
2. **按页的日志 10⁶ 的撤销数组测试的播种**：`history_cost_test.go:334` 一带的 `UPDATE … WHERE id NOT IN (SELECT changeset_id FROM changeset_items)` 在 10⁶ 个变更集、849,999 个条目上是不哈希的 SubPlan（`EXPLAIN` 核过），29 分钟没做完；`NOT EXISTS` 或先建临时表就是哈希的反连接。
