# 推迟到 v0.1 收官之后统一打磨的体验事项

负责人在 2026-10-03 决定：体验上的小问题不在各 M 里停下来，v0.1 全部收官之后统一打磨。M5 推迟的几项记在这里，免得关掉移交之后丢失（之后的 M 推迟的同样追加：第 7 条是 M4–M5 的 Codex 评审，第 8–14 条 M6，第 15–20 条 M7，第 21–29 条 M8，第 30 条 M9）：

1. **"某某正在编辑"的其余位置**：M5 只在页面本身显示；页面树、笔记本首页上的标记，在线状态（[M5 总设计](../../M5-collab-editing/00-M5-design.md)第 2 节）。
2. **删除与新建之后的导航**：删除之后的去向由旧位置渲染的 `<Navigate>` 决定，可能覆盖用户刚发起的导航；新建的答复只看已提交的地址（[M4/P6 编辑器移交](../../M5-collab-editing/handoffs/M4-P6-editor.md)第 7 项，[P5 审查](../../M4-pages/reviews/P5-tree-reading-review.md) Q3）。
3. **阅读视图更新时的闪动**：实时更新整个替换 HTML，代码高亮闪一下、焦点丢失（任务复选框的焦点回到同一位置上的同一项，M5 总设计第 10 节）。
4. **输入法始终不确认时的提示**：浏览器始终不发 `compositionend` 时，状态栏只显示"未保存"，不另做提示（M5 总设计第 4.8 节）。
5. **自动保存的播报**：状态栏每次自动保存都礼貌地播报一次，算不算吵（[P5 文档](../../M5-collab-editing/05-P5-autosave-idle.md)第 7 节）。
6. **任务项勾选的几处**（[P6 文档](../../M5-collab-editing/06-P6-task-items.md)第 7 节，[P6 审查](../../M5-collab-editing/reviews/P6-task-items-review.md)）：
   - 勾了会让任务项消失的（`- [ ]: /u`）被拒时只说"有些值无效"；
   - 失去角色的编辑者在笔记本列表重读之前复选框仍可点（服务端答 403，与"编辑"按钮相同）；
   - 阅读者禁用的复选框没有名称；
   - 勾选开始时清掉页面的提示，可能连带清掉之前"编辑"被拒的提示。
7. **退出登录时保存不了的文字**（[M4–M5 Codex 评审](../../M5-collab-editing/reviews/M4-M5-codex-review.md) D1）：退出登录先保存各标签页未保存的编辑：每个保存至多等 1.5 秒，整个退出至多等 2 秒。处于冲突、已失锁、保存没成功或 1.5 秒内没答复的，以及收到请求时主线程被占住、100 毫秒内没答复的标签页的，文字随退出丢失（最后这种见 [M4–M5 修复的核对](../../M5-collab-editing/reviews/M4-M5-codex-review.md)第 9 节 Q-1）。作者的建议：退出之前，有这样的编辑（本标签页的，以及别的标签页经频道报告的）就先问"仍要退出吗"，与离开编辑时的提醒一致；负责人可改判。要守住忙碌的标签页，可以让有编辑的标签页事先登记，退出的标签页只等登记了的（有 Web Locks 时各持一把共享锁，退出的标签页以独占请求等它们释放；非安全上下文没有 Web Locks，退回现在的答复窗口）。
8. **阅读视图里锚点与焦点的几处**（[M6/P3 文档](../../M6-links/03-P3-index.md) 6.7，[P3B 审查](../../M6-links/reviews/P3B-render-review.md)）：
   - 后退、前进到带锚点的地址时，浏览器恢复的滚动位置盖过视图的滚动，拿到焦点的标题可能不在视口里；
   - 重读之后，没有 id 的元素（链接）失去焦点；带 id 的回到原来的元素，但同名标题因前面新加了一个而换了 id 时，落到拿到原来 id 的那个；
   - 打开页面时为锚点重读的那次失败（网络、503），不再等那个元素；
   - 那次重读期间，读屏软件的虚拟光标、语音控制的滚动等不给页面输入事件的移动不算读者的输入，元素读回来时仍会滚过去；Firefox 里拖动窗口的滚动条算不算没能验证（Chromium、WebKit 里算）。
9. **改名、移动因链接被锁而被拒时**（[M6/P4 文档](../../M6-links/04-P4-rewrite.md)第 6 节，[P4 审查](../../M6-links/reviews/P4-rewrite-review.md)）：
   - 只有横幅的拒绝之后焦点落到 `<body>`（P4 之前就有：对话框的表单没有字段错误时）；
   - 列表按页 id 排，不按树的次序；
   - 列出的页之后离开了树（删掉、移出）时，整个列表退回通用的文案；
   - 笔记本首页的"新建页"不清掉树上拖动被拒的说明；
   - 树给同名的页的叫法（总体设计 13.2 第 17 条，`distinctName`）在一处仍会重名：根下的页写作"Notes（在 Plans 里）"，标题恰是笔记本名 Plans 的根下页的子页 Notes 也是；被拒的列表、删除对话框与树的菜单都用它（P4 修复核对 c4-1，P4 之前就有）。根下的页可以另用一种说法（"在 Plans 的顶层"）。
10. **阅读视图里标签、标题与属性的几处**（[M6/P6 文档](../../M6-links/06-P6-reading-view.md)第 3、4、18 节，[P6A 审查](../../M6-links/reviews/P6A-reading-server-review.md)）：
    - 标签 `/`（`#//`）在页里是文字：`getTag` 的路径叫不到它（单独的 `%2F` 被读成末尾的斜杠），`listTags` 却列出它。做全部标签的总览时（P6 交给 M12）可以改用通配的路由（`{tag...}`）一并解决；
    - 标题的 id 丢了自动链接与原始 HTML 的文字，`[[#See https://a.example now]]` 指向没有的 id（P6A 修复核对 f3-2，M6 之前就有）。改它会改动已有的 id；
    - 属性链接的文字不经净化：Markdown 链接文字里原始 HTML 的标签不写，标签之间的文字照样显示（`<script>b</script>` 显示 `b`），正文里净化连文字一起去掉（P6A 修复核对 f2-L2）。

11. **阅读视图里公式、图与未建链接的几处**（[M6/P6 文档](../../M6-links/06-P6-reading-view.md)第 7、10 节，[P6B 审查](../../M6-links/reviews/P6B-reading-front-review.md)）：
    - mermaid 的时序图、桑基图有几个 id 不以图的 id 开头（`actor0`、`root-0`、`linearGradient-N`），同一页两张这样的图 id 重复，渐变可能指到另一张；
    - KaTeX 对没有字形度量的字符（€、希伯来文、emoji）往控制台写警告（`strict: false` 管不到）；
    - 打印不受公式布局的预算限制：绘制重的公式（成串的 `\boxed{\cancel{x}}`、`\pmb` 的阴影）在预算之内让打印多 2–5 秒；慢的 CPU 上公式很多的页有些显示原文；
    - 图在 20,000 字节之内可以在主线程画几秒（block 5.7 秒，architecture 4.1 秒，state 3.0 秒；`maxEdges` 只限流程图的边，mindmap 另限 150 行）：要更快只能按类型限得更小；
    - 定义宏的公式显示原文（负责人可以改判：放进带时限的 worker 才能安全地支持）；
    - 换语言时整个视图重新增强：文章里没有 id 的元素失去焦点，宽内容的滚动归零；
    - 未建链接的对话框开着时视图被重读，新的那条链接没有 `aria-busy`；链接因重读已解析时，对话框关闭后焦点落在文章上；按住 Enter 反复打开对话框；
    - mermaid 画图时往 `<body>` 里放临时元素（没有核对是否闪一下）；
    - 用户的样式表设了 `scroll-behavior: smooth` 时，锚点之后窗口滚不够：`scrollRegions` 复原视图的滚动、让窗口滚同样的距离，打断了还在进行的平滑滚动。

12. **编辑器的补全与右栏的几处**（[M6/P7 文档](../../M6-links/07-P7-editor-panel.md)第 4、9、10、15、18 节，[P7 审查](../../M6-links/reviews/P7-editor-panel-review.md)）：
    - 中文标点模式下输入的 `【【` 不触发补全（要切到英文标点）；
    - 右栏的 `<details>` 的开合不随页记住；阅读视图重读时各 callout 的开合不保留（只有拿着焦点的元素所在的那个重新打开）；callout 的 `summary` 拿着焦点时重读，焦点落到 body（P7 修复核对 fc3-c2-5）；
    - 子页列表等的链接点击之后焦点落到 body（右栏的链接用 `arrived`）；
    - 焦点环在白底上淡（全局）；补全选中项的说明文字对比度 4.34:1（与菜单、快速切换同一组颜色）；
    - 右栏里解析不到的属性链接只是文字，不能新建页面（属性表里能）；
    - `PropertyLink` 加 `text` 与值的序号：右栏的 Markdown 属性链接文字与属性表一致（不再照写转义、字符引用、强调），共用路径的链接不再按形状对齐；
    - 编辑器认出 frontmatter：YAML 的高亮；块标量里没闭合的围栏或 `<!--` 不再让之后的整篇正文当代码（正文不补全、高亮也错）；块标量正文里的引号之后不再补全（服务端把整个值读成文字）。只用 CR 换行的内容编辑器认出 frontmatter、服务端不认；粘贴到开头的 BOM 服务端认、编辑器不认（都极少）；
    - 补全的"表格"与服务端对齐：lezer 要表头与分隔行格数相等，goldmark 宽一些，这时表格里选别名写出不转义的 `|`（P7 修复核对 fc3-c1-2）；
    - 代价：反链的长列表逐项 memo（读了上万项之后每按一次"更多"约 0.5 秒）；补全的选项每次读取只建一次（百万个选项、查询没有匹配时每键 100–200 毫秒）；
    - 大纲的长标题撑高右栏（截断）；"……另有 N 个标题"等计数的千分位（全应用一致）；
    - 读屏（NVDA、JAWS、VoiceOver）激活"更多反向链接"之后焦点的去向，人工确认（P7 修复核对 fc3-c2-6）；
    - 页面树 `stores/page-tree.ts` 的 `Math.max(0, ...subtreeOf(...))`（M4）：一棵子树超过约 12.5 万页时参数超出上限而抛错，改成 `reduce`（P7 修复核对 fc6-c2，没有确认能否触发）。

14. **前端的几处结构**（[M6 收尾审查](../../M6-links/reviews/M6-closeout-review.md) B Nit 8；右栏的测试收尾时已按节拆开）：`page-properties.tsx` 里约 170 行属性链接的配对与判断移成纯模块单独测；`PageTreeStore` 转发 6 个与树无关的 linking 读，改由 linking 自己的 store；`guardLabels` 从 `math.ts` 移到图与公式共用的地方；`reading-view.tsx` 一个文件管四件事，按职责拆开。
15. **阅读视图里附件的几处**（[M7/P3](../../M7-assets-transfer/03-P3-assets-links.md)第 9.2 节，[P3B 审查](../../M7-assets-transfer/reviews/P3B-render-review.md) C10、B3）：
    - 写下的高度不起作用：CSS 的 `height: auto` 保持图片自己的比例，只写高度的（`|0x200`）、宽高都写的（`|300x200`）加载之后照图片的比例；
    - 折叠的 callout 的标题（`<summary>`）里的音视频控件：点控件也会开合 callout。
    - 解析不到的、写法是附件的链接（`x.png`）点开之后的说明仍按页面说话（"没有这个名称的页"，嵌入"显示一页"）；服务端的落点答 `target_is_asset` 时才换成附件的说法。按写法一开始就说"没有这个附件"（[P3A 审查](../../M7-assets-transfer/reviews/P3A-assets-links-review.md) C9、C11 的余项，M7 收尾审查 C-Q2）。
16. **附件一节的几处**（[M7/P4A 审查](../../M7-assets-transfer/reviews/P4A-assets-web-review.md)"接受与推后的"）：
    - 菜单开着时它的行被重读拿走，焦点丢失；
    - Safari 的拖放高亮靠 `dragleave.relatedTarget`，会闪；
    - 服务端挂住时上传一直"正在完成…"，没有超时，离开页面的提醒一直开着；
    - 复制的字段没有关闭的办法，附件改名之后仍是旧的嵌入；区域里留着上一句播报；
    - 一行移除或取消之后焦点总回到上传按钮，而不是下一行；
    - 改名的 `too_long` 没说扩展名也计算在内；
    - 不内联的附件在列表里没有"下载"的提示（名称就是下载的链接）；
    - 陆续完成的上传各说一句、相隔几十毫秒，读屏可能只读到最后一句："已上传"可以等 0.5–1 秒再合成一句；
    - 上传读到最后一页时"更多"带着焦点消失，焦点交给这一节的标题，长列表里标题不在视野里，也不滚过去：可以交给列表的最后一行；
    - 同一个上传在一轮里开始又离开时（真实网络几乎遇不到），合成的句子里还数着它："正在上传"可以只数这一轮开始、仍在途的；
    - 临近结尾的"取消"可能晚于服务端：请求体已全部到了服务端之后才取消，附件照样建成（未限速的本机 48 MiB 一次 201），或单元因取消失败、文件留给孤儿清扫（M7/P2 的设计；[M7 收尾审查](../../M7-assets-transfer/reviews/M7-closeout-review.md) B-M7）。取消之后 store 已重读树与列表（`stores/asset.store.ts`），建成的附件会出现在列表里，上传的行却已随取消离开：要补的是告诉用户取消晚了（核实修复 FB-N3）；
    - 待人工确认：从访达拖文件到附件一节与阅读视图（Chromium、Safari、Firefox），从访达把一个文件夹拖到导入对话框的文件输入框（Safari、Firefox：Chromium 里不收、说明先打成 zip，M7 收尾 FB-M2），页内拖一张图片按 Esc 取消之后再拖文件进来，Firefox 里用键盘打开"打开"，不经 HTTPS 的部署里用读屏复制嵌入。
17. **阅读视图里附件的几处**（[M7/P4B 审查](../../M7-assets-transfer/reviews/P4B-assets-web-review.md)"接受与推后的"）：
    - 每小时整篇替换文章（到期的重读）：选区丢失、展开的 callout 合上（在里面播放的媒体的控件随之藏起来）、图片重新下载、没写尺寸的图片跳动。改法：同一 `revision`、HTML 只在附件地址上不同时就地更新地址（图片改 `src`，旧图显示到新图加载完；链接改 `href`；还没开始的媒体改 `src`；已开始的照旧在失败时重签）。负责人可以改判为 v0.1 内做；
    - 新标签页的提示前，链接里的空格看得见、带下划线，大小写在它之后时总会露出，带提示的链接仍在那里折行；复制正文带上提示：提示与空格放进同一个 `span`、加 `user-select: none`，在真实浏览器里核对可访问名称，右栏与附件一节的行一起改；
    - 右栏的附件链接不显示大小（`PropertyLink` 没有字节数）；
    - 地址过期之后点下载链接静默失败：点击时比较 `assetsExpire`，过期就先重读；
    - 视图卸载之后增强仍引用旧文章的 DOM（`kept`），直到下一个阅读视图运行；
    - 系统休眠之后定时器晚到：SWR 的 focus 与 reconnect 兜住大部分，可以在 `visibilitychange`、`pageshow`、`online` 时比较到期；
    - 重签被拒之后的恢复：Firefox、Safari 的原生控件在出错时多半不重新加载，重签被拒而视图没过期时（断网、503）元素坏到下一次替换；Chromium 的控件重试先重新加载，丢掉失败时的位置。改法：被拒时记下失败时的位置，下一次重签与出错分支用它；`online` 时或隔一段时间再签一次；
    - 已知的限制：替换时原生全屏退出；
    - 待人工确认：见审查记录"接受与推后的"末条（PDF 在 CSP `sandbox` 下、各引擎出错之后的媒体状态、控件的重试、折叠 callout 里的焦点、复制的提示）。

18. **编辑器的粘贴与拖入的几处**（[M7/P4C 审查](../../M7-assets-transfer/reviews/P4C-paste-upload-review.md)"接受与推后的"）：
    - 站内跳转（不经 Done）离开时上传在途：附件照常落下，嵌入不插入，编辑器说的没人看到（关闭标签页有 `beforeunload` 的提醒）。改法：`UnsavedGuard` 也看编辑器在途的上传，或把告知交给附件一节；
    - 同步被拒（`.md`、超过上限）时选区已删（可撤销）：先看能不能发再删；frontmatter 里同样：选中带引号的整个值（`'old.png'`）再粘贴，选区先删，嵌入在那里不插，属性成了空值（[M7 Codex 评审](../../M7-assets-transfer/reviews/M7-codex-review.md)修复核对 A2-Q1）：粘贴时就判断落点会不会被拒，那时保留选区；

    - 搜索框按工作区 id 换新没有测试（C 的 C21）：没有什么核对换工作区时清掉框的文字与问题，设计也没写（C）。

27. **M8 收尾找到的几处**（[M8 收尾审查](../../M8-history-search/reviews/M8-closeout-review.md)"接受与推后"；B 另找到的历史页的"谁"在 375 px 上比屏幕宽、从撤销的状态行后退再显示"撤销"，已在第 26 条末项与第 23 条）：
    - 本标签页在搜索的结果显示之后删掉的页，后退回结果再点开时去它的父页、`h1` 取得焦点，不说为什么（`PageGone` 的 `removedTo`）；别的标签页或别人删掉的说"页面不存在"：两者都可以，但不一致（B 的探针 1b）。
    - 别处删掉的页从搜索的结果（或从工作区级的页后退）打开时，过时的树先显示这一页的外壳、发出五个答 404 的读（控制台五条错误），外壳的四个面板（阅读视图、属性、反链、附件）的 `NotLoaded` 插入四个 `role="alert"`"这个页面不存在，或者你无权访问它。"（约 20 ms 之后去掉，读屏可能在"页面不存在"之前念到四次；核实修复第一轮 K1-2），再换成"页面不存在"（B-M1 的这一半；收尾修了它的焦点："页面不存在"取得焦点，附件的行只在新读回之后取得焦点）。收尾没改这一闪：没有小的改动分得开事件维持的树（这本笔记本的树挂着时）与没挂时缓存的树（SWR 对没挂的键的 `mutate` 只丢掉去重的记录，`PageTreeStore` 听不到事件）；`PageLayout` 每次到达都等树的读会拖慢平常的导航（还要越过 SWR 2 秒的去重），从事件里标过时又会让开着的页每次远端改动都空白、导入的事件流里每次导航都等。改法：点搜索的结果（与从笔记本外后退或前进进来）时把那本笔记本的 `PageTreeStore` 标为未确认并开始一次读；`PageLayout` 在未确认时挂上就显示 `NotLoaded`，直到标记之后开始的一次读答复（SWR 挂上时自己的读随之去重）；要动搜索的结果、store、根 store 按 id 的查找与 `PageLayout`，带自己的测试与一个 e2e 的安静页检查（[M8 收尾审查](../../M8-history-search/reviews/M8-closeout-review.md) B-M1）。较窄的另一种（核实修复第一轮的建议，没有试过）：树还列着这一页时，外壳的面板对 `page.not_found` 不警示、显示加载中，等树的读来定；要另核对面板不会一直停在加载中。
    - 输入法清单只在桌面浏览器上；Android（Gboard）的回车（第 26 条末项）可以加一步手机上的检查（B 的存疑）。
28. **M8 收尾的核实修复找到的几处**（[M8 收尾审查](../../M8-history-search/reviews/M8-closeout-review.md)"核实修复"第一至三轮）：

    - "还原到这个版本"发送中"取消"是 `aria-disabled`，但不变暗（撤销的确认框同样）。
    - 那条说明是 `<output>`（礼貌的状态），又描述取得焦点的这一节的标题，有的读屏可能念两次。
    - 来到一页（`arrived`）而它的第一个标题迟挂上时（例如笔记本的树还在读），这个标题照样从读者手里取得焦点：读者其间在搜索框里打字，按键就丢了。同 K1-1 一类，只是在一次导航的第一次挂上；M8 之前就有（第二轮）。

29. **M8 Codex 评审的修复核对找到的一处**（[M8 Codex 评审](../../M8-history-search/reviews/M8-codex-review.md)第 9 节，R2、R3 的修复核对第一轮）：
    - 版本页的阅读视图与回收站的预览重读之后 HTML 变了时，`useLayoutEffect` 整篇换掉文章的 `innerHTML`（`version-view.tsx`）：键盘的读者焦点在其中的一个链接上时落到 `body`（读代码推出）。树的变化本来就会这样，R3 让一次写增删了别名也触发它（别名很少改）。改法：换之前记下拿着焦点的链接（按 `href` 与它在文章里的次序），换之后把焦点放回同一个链接。
30. **MCP 的几处**（[M9/P1 S3 审查](../../M9-mcp/reviews/P1-S3-account-review.md)主持者的决定 3、5、9；[M9/P1](../../M9-mcp/01-P1-platform-reads.md) 3.15.3、3.16.1、3.16.4；[M9/P2 S2 审查](../../M9-mcp/reviews/P2-S2-history-review.md)主持者的决定 2、A-N2）：
    - `AGENTS` 的说明截在 32 KiB 之内最后一个换行处，最后的换行离界线远时留下的远少于 32 KiB：一行 7,000 字节（按答复的量 12,002 字节）之后一行 20,766 字节跨过界线，说明只留 12,085 字节，本可以 32,768（S3 审查 A 的存疑 1）。一种改法是最后的换行离界线太远时退回字符的边界，是设计的问题。
    - 只由看不见的字符组成的客户端名称照样记下：`CleanClientName` 留下 U+200B、U+2060、标签字符（U+E0041 U+E0042）、U+00AD、U+FEFF、U+180E、U+3164、U+115F、U+2800，日志里显示为空，P2 起是 `mcp:` 后面看不见的东西，标签字符还能把看不见的文字带进网页的变更集（S3 审查 B-N2）。`CheckName` 对显示名同样留下：shared 的 `unshowable` 是 Cc、Zl、Zp 与 Bidi_Control。两处一条规则：没有图形字符的名称算空，也许另去掉 U+E0000–U+E007F 的标签块。
    - 客户端在名称的语句（记下或读）运行时走了，记 warn（"MCP client name not recorded" 或 "not read"，带 `context canceled`），S1 对客户端走了记 debug；还不知道名称在行里时不报名称的调用也记下，所以比修复之前常见，一直失败的记下每次调用一行 warn（S3 审查 B 的存疑，修复核对第一轮 B）。只是日志的级别与数量。
    - `log` 的 `path` 是可选的，`log {path: ""}` 或 `{path: "/"}` 却答 422 "path is required"（`ParsePath` 的空路径）：说明教 agent 以 `""` 与 `"/"` 表示 `list` 的根，agent 可能以它们表示"整本笔记本"（M9/P2 的 S2 审查 A-N2 的后一半）。两种改法：当作没有筛选，或在说明与文字里说 `path` 指一页或一个附件。
