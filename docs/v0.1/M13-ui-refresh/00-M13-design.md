## 1. 目标

v0.1 的功能做完了，界面能用但简陋。M13 只改网页的外观与交互，让它"简约而不简陋"，视觉参照是 Codex 桌面客户端：中性色有层次、圆角与阴影克制、主次分明、设置页区块清楚、交互顺。具体是：

1. **新外框**：去掉顶栏；侧栏顶部是工作区切换，其下是"搜索 ⌘K"一行；当前笔记本在笔记本列表里就地展开成页面树；语言、主题、账号收进左下角的头像菜单；侧栏底色深一档、固定在原位自己滚动（4.2）。
2. **一套设计基础**：亮、暗两套分层的中性色，琥珀色只标状态；圆角、阴影、间距、字号、动效各有一套值；按钮、输入框、原生控件、菜单、弹窗统一换装（4.1、4.3）。
3. **独立的设置界面**：进入设置时侧栏换成设置目录，个人、工作区、当前笔记本三组放在一起；设置页是分组卡片，每行左边标题与说明、右边控件（4.4）。
4. **阅读与编辑**：正文的字号、行宽与各种块的样式重做；属性收成标题下的一排小标签；右栏可收起；编辑器与阅读同宽同位、正文用比例字体，编辑时保留大纲（4.5）。
5. **其余页面**：工作区首页、笔记本首页、搜索、历史、回收站、目录、健康、升级、导入导出、版本、附件、登录、引导、邀请与空状态，照同一套基础重排（4.6）。
6. **无障碍规则按"视觉优先"改写**：影响外观的规则（对比度门槛、焦点框的粗细、链接下划线）让位于美观；键盘操作、可访问名称、焦点去向照旧（负责人第 1 问，4.7）。

## 2. 范围

**做**：`web/apps/web/` 的样式、组件、外框与设置的布局、阅读视图的样式与前端增强、编辑器的主题；随之改的 vitest 与 e2e；总体设计 13.2 的有关条目；README 与发布说明里描述界面的文字。

**不做**：

- 新功能。不加接口、不改服务端、不改数据库。"搜索 ⌘K"只是现有搜索框的新样子加一个聚焦它的快捷键（4.2.4）；属性小标签读已有的属性接口（4.5.2）。
- 服务端渲染的 HTML 不改形状（`nw-props`、`nw-callout`、`nw-scroll` 等类名照旧），阅读视图的新样子全由前端的 CSS 与增强做出。
- 搜索摘要里露出 Markdown 原文（`--- tags:`、`**`、`[[…]]`）：要改服务端的摘要，不在 M13，写进 v0.2 的移交（第 7 节"写给后面的 M"）。
- 富文本（所见即所得）编辑：编辑器仍是源码编辑，只换主题与字体。
- 网页字体：只用系统字体（主持者的决定 722）。
- v0.2 打磨清单里与外观无关的项（第 7 节"移交的落实"）。

## 3. 完成标准

1. 第 1 节六条在亮、暗两种主题、1440 px 与 375 px 两种宽度下做到；每个 Phase 的审查附这四种组合的截图，对照样稿看过。
2. 现有的全部 vitest 与 e2e 故事通过（受外框、设置与控件改动影响的，改定位与断言，不删覆盖）；新加的交互（⌘K 跳转、设置界面的进出、即时生效与失败退回、右栏收起、编辑时的大纲）有 vitest，跨页面的有 e2e。
3. 门禁照旧为绿：tsc、knip、oxlint、oxfmt、`make lint-web` 的各项检查、`make test`、`make e2e`（含 `webkit-narrow` 与三种浏览器的格）。
4. 13.2 第 31 条（及第 4.7 节列出的其他条目）照负责人第 1 问改写；e2e 的对比度夹具改成新配色的回归守卫（4.7）。
5. 没有服务端与契约的改动：`git diff --stat main -- server api` 在 M13 的范围里为空（发布用的版本号等 M12 的改动不算）。
6. 本 M 没有 `open` 的移交；v0.2 的打磨清单里 M13 做掉的项写进它的"处理进展"。
7. M13 收尾之后，`m13-ui-refresh` 合并进 `main`、`main` 的 CI 绿；M12 的发布照 00-M12 第 7 节继续（推 tag 之前问负责人）。

## 4. 关键决定

### 4.0 取舍过的做法

负责人在 2026-11-22 的对话里逐项看过样稿后选定（原话在第 11 节）：

| 问题 | 考虑过的做法 | 选定 | 理由 |
|---|---|---|---|
| 外框改多少 | A 保留顶栏与侧栏的顺序，只换外观；B 照 Codex 改外框 | **B** | 顶栏只放了产品名与三个图标，占 56 px；侧栏一长串、页面树被挤到下半屏；只换皮解决不了层次 |
| 配色 | 素（纯中性）；琥珀（中性加暖金，暖金只标状态）；钴蓝（中性加冷蓝，蓝色担任主色） | **琥珀** | 大面积仍是灰阶，保留克制；"当前页、已勾选、已开启"一眼认得出 |
| 设置放在哪 | A 独立的设置界面（侧栏换成设置目录）；B 留在原侧栏、内容区自带小目录 | **A** | 三处设置收到一处；主题与语言有归宿；内容区不再多一列导航 |
| 阅读与编辑 | 主持者照样稿提议，负责人认可 | **样稿** | — |
| 与 v0.1.0 发布的先后 | A 先发 v0.1.0、美容进 v0.2；B 先美容、做完再发 | **B** | 第一个正式版本就是新界面；读屏验收查的焦点与区块正是新外框要改的，先美容只验一次 |

### 4.1 设计基础（token）

全部是 CSS 变量，定义在 `W/styles.css`，经 Tailwind 的 `@theme inline` 映射成工具类；组件只用语义名，不写色值（13.2 照此加一条，4.7）。

**颜色**：亮、暗各一套，值取自样稿：

| 名 | 亮 | 暗 | 用在 |
|---|---|---|---|
| `--background` | `#ffffff` | `#1a1b1e` | 内容区 |
| `--sidebar` | `#f5f5f6` | `#141517` | 侧栏、设置目录、控件区的底 |
| `--surface` | `#ffffff` | `#212226` | 卡片、弹出层 |
| `--surface-2` | `#f4f4f5` | `#25262a` | 次一级的面：行内代码、标签、输入框、表头 |
| `--hover` / `--active` | 墨色 4.5% / 7.5% | 白 4.5% / 8% | 悬停、选中的底 |
| `--border` / `--border-strong` | `#e7e7ea` / `#d4d4d9` | `#2b2c31` / `#3a3b41` | 分隔、控件边框 |
| `--foreground` / `--muted-foreground` / `--faint` | `#18191c` / `#5f6168` / `#91939b` | `#e8e8ea` / `#a4a5ac` / `#74767e` | 正文 / 次要文字 / 说明与占位 |
| `--primary`（墨色） | `#18191c` | `#ececee` | 主按钮、工作区头像 |
| `--accent` / `--accent-soft` | `#c58a22` / 12% | `#d9a84e` / 14% | 只标状态：开关打开、勾选、单选、当前页、大纲当前节、链接下划线、聚焦框、"当前"徽记 |
| `--destructive` | `#d64545` | `#ff7b7b` | 删除类：描边按钮与菜单项的字，不用实心红块 |

现有的 `--accent`（shadcn 的"悬停底"）改名为 `--hover`，`accent` 一词留给琥珀；组件里的 `bg-accent` 随之换成 `bg-hover`（P1/S1 机械替换）。

**形状与层次**：行（导航、菜单项）7 px；输入框、下拉 8–9 px；卡片、设置分组 14 px；弹出层 12 px；弹窗 16 px；工具栏按钮与搜索行是胶囊（999 px）。阴影只给弹出层与弹窗（亮：两层，近处 1 px、远处 10/28 px；暗：1 px 的白色描边加深阴影），卡片不加阴影、只用边框。

**字**：系统字体（`-apple-system`、`PingFang SC`、`Microsoft YaHei` 等，等宽用 `SF Mono`、`Menlo`）。字号：界面 13–14 px，侧栏行 13.5 px，正文 16 px、行高 1.8，页面标题 32 px，设置页标题 26 px，分组标题 13 px。不用全大写的标签。

**动效**：颜色与底色 150–180 ms；菜单、弹窗出现时淡入加轻微缩放（150 ms），收起更快；`prefers-reduced-motion` 时关掉位移与缩放，只留淡入。

### 4.2 外框

#### 4.2.1 结构

```
┌───────────┬──────────────────────────────────────┐
│ 产品研发 ▾ │ 工程手册 / 系统架构     …  ◫  ⋯  编辑 │
│ ⌕ 搜索  ⌘K│                                      │
│ ⌂ 首页     │  （页面）                             │
│ ⚙ 工作区设置│                                      │
│ 笔记本     │                                      │
│ ▾ 工程手册 │                                      │
│    页面树… │                                      │
│ ▸ 设计规范 │                                      │
│ ＋ 新建笔记本│                                     │
│ ───────── │                                      │
│ ◉ UI Dev ⋯ │                                      │
└───────────┴──────────────────────────────────────┘
```

- **顶栏去掉**（`W/app/layout.tsx` 的 `header`）。产品名出现在登录、注册、引导与头像菜单的"关于"里。
- **侧栏**宽 252 px，`position: sticky; top: 0; height: 100svh; overflow: auto`，底色 `--sidebar`。窗口照旧整页滚动：M6 为阅读视图的滚动锚定与"后退到锚点时标题在视口里"选的就是窗口滚动，换成内容区自己滚动要重做那一串，不值（主持者的决定 717）。侧栏现有的 `overflow-anchor: none` 照旧。
- **地标**：侧栏仍不是 `main` 的一部分，`nav` 照旧带名称；顶栏去掉之后没有 `banner`，与读屏清单有关的地方在收尾改写清单（第 7 节"总体设计的修订"）。

#### 4.2.2 侧栏的内容（自上而下）

1. **工作区切换**：方形头像（工作区名的首字）+ 名称 + ⇕，菜单照旧列出别的工作区与"新建工作区"（`W/pages/workspace/workspace-switcher.tsx:42,58`）。`[data-shell]` 留在侧栏的根上（w3 以它数侧栏在 `main` 之外，`e2e/stories/workspace/w3-shell-switch.spec.ts:18-22,78`）。
2. **搜索 ⌘K**：就是现有的搜索框（`W/pages/workspace/search-box.tsx`），换成一行胶囊：放大镜、占位"搜索"、右端的 `⌘K` 提示；输入回车进搜索结果页，照旧。可见的范围说明（"在「X」里搜索。"）改成只给读屏的描述（`aria-describedby` 照旧，se2 以 `toHaveAccessibleDescription` 核对它）；⌘K（其他系统 Ctrl+K）聚焦它，与现有的 Mod+Shift+F 并存（4.2.4）。
3. **首页**、**工作区设置**（图标加文字）。
4. **笔记本**：分组标题（小号灰字），"我的""团队"两组照旧（列表名取自分组标题，`W/pages/workspace/notebook-groups.tsx:67-70`），每本笔记本一行（书本图标）。当前笔记本的那一项展开，项里依次是：
   - 它的页面树，仍是单独命名的 `nav`（"X 的页面"，`W/pages/notebook/page-tree.tsx:157`）；M12/P4/S4 的分批画行与一棵树一个菜单照旧，只换样子；当前页一行用 `--accent-soft` 底、图标为琥珀色。现在树的标题（`h2`，笔记本名，`page-tree.tsx:159-165`）是移动、删除之后焦点的去处（`page-tree.tsx:98`、`page-tree-item.tsx:594`）：它变成笔记本那一行本身的标题，仍可取焦点（`tabIndex={-1}`），视觉上就是那一行。
   - 树下面一排图标链接：目录、健康、历史、回收站，仍是单独命名的 `nav`（"X 的更多"，`W/pages/notebook/notebook-places.tsx:20`），放在树的 `nav` 之外；图标带可访问名称与悬停提示（主持者的决定 727）。
   - 笔记本行悬停或键盘聚焦时显出"⋯"，菜单是新建页面、笔记本设置。
   - 树进了笔记本列表的项里，e2e 的 `notebookGroups`（`e2e/fixtures/notebook-pages.ts:17-26`，17 处调用）会把树里的链接一起数进去：夹具改成只取每一项的第一层链接，调用处不动。
5. **新建笔记本**。
6. 底部：**头像行**（头像 + 显示名 + ⋯），就是现在的账户菜单（`W/app/user-menu.tsx`，按钮名照旧是显示名，`e2e/fixtures/auth-pages.ts:46-54` 照旧找得到）：个人设置、外观（主题三选一、语言二选一，子菜单里就地切换）、关于 Nerve Wiki（现在菜单里的版本行，`e2e/stories/smoke/s2-web-app.spec.ts:60` 核对它的文字）、退出登录。

**没有侧栏的页面**（引导、新建工作区、邀请、工作区之外的 404 与出错页）也要有账户菜单：a6、s2 在这些页上打开它（`e2e/stories/identity/a6-sign-out.spec.ts:31-38,82-96`、`s2-web-app.spec.ts:57-60`）。这些页在右上角放同一个头像按钮（主持者的决定 726）。

#### 4.2.3 窄屏（< 768 px）

侧栏收成抽屉：页面顶部一条 44 px 的细栏（菜单按钮、当前位置的标题、⋯），点菜单按钮从左侧滑出侧栏，遮罩点按或 Esc 关闭，焦点进出照 Radix 的对话框。375 px 的 `expectFits` 照旧要过（主持者的决定 720）。

今天窄屏时侧栏堆在页面上方，故事在 375 px 下直接用得到它；改成抽屉之后，375 px 下要碰侧栏的步骤先开抽屉。已知的：se1 的 `@narrow` 格（`se1-search.spec.ts:387-407`）、lw3 的 375 px 段（`e2e/stories/wiki/lw3-source-duplicates.spec.ts:310-317,346-380`）；pg2、lw3 用树的菜单之前先切到 1280 px（`pg2-rename-page.spec.ts:172-180`），照旧。P2/S3 的设计逐个列全。

#### 4.2.4 搜索与快速切换

- **搜索框**留在侧栏、换成胶囊（4.2.2 第 2 项），仍是 `role=search` 里名为"搜索词"的 `searchbox`：se1、se2、lw8 的 20 处定位（`e2e/fixtures/wiki-search.ts:8-22`、`e2e/stories/wiki/lw8-health.spec.ts:710-722`）照旧。
- **⌘K**（其他系统 Ctrl+K）是聚焦搜索框的新快捷键，经 `isMod`（`W/app/shortcuts.ts`），对话框开着时让路；Mod+Shift+F 照旧（13.2 第 20 条：它在一些输入法里是切换键，所以可见的框才是主入口，⌘K 补上一个不冲突的键）。窄屏时先打开抽屉再聚焦。
- **快速切换**（Mod+O，`W/pages/notebook/quick-switch.tsx`）照旧是单独的对话框（"前往页面"），照 4.3 换装：选项带页面图标、上级位置灰字、底部一行键盘提示。
- 不合并两者，不改搜索的语义与接口（主持者的决定 719）。初稿曾提议把两者并进一个 ⌘K 跳转框，代码调查之后放弃：搜索框的定位、`aria-invalid`、范围描述与 lw8 的"读者动过"的点按目标都在它上面，合并要改 20 处以上的定位与 13.2 第 20 条，而好处只是少一个入口。

### 4.3 控件

- **原生控件就地换装，不换成自定义组件**（主持者的决定 718）：`select` 用 `appearance: none` 加自带的箭头，`radio`、`checkbox` 用 `appearance: none` 画成样稿的样子（琥珀为选中色）。键盘、读屏与 e2e 的 `selectOption`、`check()` 都不变；M5-polish 33.1 为 WebKit 加的 `contain-paint` 照旧。
- **开关**（switch）是新加的组件（Radix 的 Switch 或 `button role="switch"`），只用在设置页"开 / 关"的项。
- **按钮**：主（墨色实心）、次（描边）、幽灵（无底）、危险（红字描边）、图标；工具栏与卡片里用胶囊形，表单底部用 8 px 圆角；高度 30 px（紧凑）与 36 px（表单）两种。
- **菜单**：每项可带图标与快捷键；分隔线；危险项红字；选中项打勾；子菜单带箭头。
- **弹窗**：圆角 16 px、阴影、遮罩更淡；标题 18 px、说明 13.5 px 灰字、按钮右对齐。
- **空状态**：图标 + 一句说明 + 主操作（如果有），替代现在的一行灰字。
- **加载**：短的保持现状（文字），列表与卡片首次加载用骨架占位（`W/components/loading.tsx` 扩展）。

### 4.4 独立的设置界面

#### 4.4.1 结构

#### 4.4.3 保存方式

（主持者的决定 715，负责人可以改判）

- **开关**：点按即生效。
- **下拉**：即生效，但照 `useChoice` 的做法（`W/components/ui/native-select.tsx:57-105`）：鼠标选中即发，键盘用方向键逐项走时等失焦或回车才发，不会一路走一路发。
- **写到服务端的单选组不做即生效**：13.2 第 12 条的理由（方向键就会改选中项）照旧成立。要即生效的，改成下拉；留着单选的，照旧"保存"。只存在本机的偏好（主题、语言，`W/pages/settings/profile-page.tsx:59-86`）今天就是单选即生效，照旧。
- 生效之后旁边显示"✓ 已保存"（13.2 第 12 条的常驻 `<output>`，1.5 秒后淡出）；被拒时退回原值，原因显示在这一行下面（`useForm` 的横幅照旧可用）。
- **文字输入**（名称、显示名）：改动之后才出现"保存"按钮，回车也保存；失焦不自动保存。改密码、新建令牌、邀请、加成员这些"提交一份表单"的照旧有按钮。
- **危险与不可逆的操作**（删除、离开、停用、升级、降级）照旧先确认。
- 例：笔记本常规页今天有名称与开放程度两个"保存"（`W/pages/notebook/general-page.tsx:44-54,89-135`，测试以 `getAllByRole(...)[0/1]` 区分）。开放程度改为即生效的下拉（三项，说明随选中项变），名称照上面的文字输入；e2e 的 `changeAccessWith`（`e2e/fixtures/notebook-pages.ts:84-91`，以"工作区里的开放程度"一组找控件）随之改成选下拉，n3 的两处调用不动。
- 13.2 第 12 条随之补一句"设置页的下拉即生效，照 `useChoice`；写到服务端的单选组仍经保存"（P3/S2 改写；主持者的决定 729）。

### 4.7 无障碍规则的改写（视觉优先）

负责人第 1 问的原话："影响视觉审美的无障碍规则可以打破，视觉美观为主。"主持者据此划的界线（主持者的决定 716，负责人可以改判）：

- **可以为美观让步**：
  - 对比度：次要文字（`--muted-foreground`）与说明文字（`--faint`）不再要求 4.5:1；正文字照旧远高于 4.5:1（新配色里是 17:1 左右）。
  - 焦点指示：仍然只在键盘操作时出现（`:focus-visible`），但改成 2 px 的琥珀色柔和外圈，不再要求对相邻颜色 3:1。
  - 链接：正文里用琥珀细下划线；导航、右栏、列表里的链接不加下划线。
  - destructive：改成红字描边的按钮，不再是白字红底，原来"白字对底 4.5:1"的要求随之作废。
- **照旧保留**（看不见、不影响外观）：键盘能完成全部操作；可访问名称与 `aria-*`；焦点的去向（13.2 第 17、26 条等）；`bdi`；375 px 不溢出；读屏的区域名称。
- **13.2 第 31 条**改写成上面两段，改写在 P1/S1，与新配色同一个 Step。
- **e2e 的对比度**：夹具 `e2e/fixtures/contrast.ts` 只量、不带门槛（`textContrast`、`focusContrast`、`indicatorContrast`），门槛写在三个故事里，都只在 Chromium：
  - pg4（`e2e/stories/page/pg4-delete-subtree.spec.ts:192-205`）：确认框"删除"按钮的字，亮暗、静止与悬停，≥ 4.5；
  - se1（`e2e/stories/search/se1-search.spec.ts:286-305,327-329,375-377`）：命中高亮的字 ≥ 4.5；搜索框、提交按钮、范围下拉、命中链接、无效的框的焦点 ≥ 3，命中链接的指示是 `outline solid`（:305）；
  - l5（`e2e/stories/links/l5-completion.spec.ts:132-137,171-178`）：补全说明的字 ≥ 4.5；编辑器聚焦框、补全选中项、阅读视图链接的焦点、菜单项的指示 ≥ 3。

  这些门槛改成"新配色的回归守卫"：正文与按钮字至少 7:1；次要文字、说明文字、焦点与选中的指示各按新配色量出的值减 0.1 设下限，防止以后无意中变淡。指示的形状照旧可断言（链接仍是 `outline solid`，2 px 琥珀色）。夹具本身不改。

### 提交说明

照 M12（`docs/README.md` "Git 工作方式"）：

- **代码**：`<范围>: <说明> (M13/P<n>/S<m>)`，范围是部件（`web`、`e2e`、`docs`，多个用逗号），例如 `web: the design tokens and the amber accent (M13/P1/S1)`。
- **文档**：直接进 `m13-ui-refresh` 的写 `docs: <说明> (M13/P<n>)`，M 级的写 `(M13)`；Step 的分支上的每个提交写 `(M13/P<n>/S<m>)`。

- **合并**：Step 合并回 `m13-ui-refresh`：`Merge branch 'm13-p<n>-s<m>': <说明> (M13/P<n>/S<m>)`；M13 收尾之后合并进 `main`：`Merge branch 'm13-ui-refresh': <说明> (M13)`。正文都经 `git merge --no-ff -F <文件>`。`Merge main into <分支>: <一句说明>` 不带后缀。
- **旁支**：分支 `m13-<slug>`；修的是更早的 M 的故事时写 `(M<k> story, found in M13)`。
