## 1. 目标

v0.1 的功能做完了，界面能用但简陋。M13 只改网页的外观与交互，让它"简约而不简陋"，视觉参照是 Codex 桌面客户端：中性色有层次、圆角与阴影克制、主次分明、设置页区块清楚、交互顺。具体是：

1. **新外框**：去掉顶栏；侧栏顶部是工作区切换，其下是胶囊形的搜索框（⌘K 聚焦）；当前笔记本在笔记本列表里就地展开成页面树；语言、主题、账号收进左下角的头像菜单；侧栏底色深一档、在宽屏上固定在原位自己滚动，窄屏是抽屉（4.2）。
2. **一套设计基础**：亮、暗两套分层的中性色，琥珀色只标状态；圆角、阴影、间距、字号、动效各有一套值；按钮、输入框、原生控件、菜单、弹窗统一换装（4.1、4.3）。
3. **独立的设置界面**：进入设置时侧栏换成设置目录，个人、工作区（与在笔记本设置里时的那本笔记本）分组放在一起；设置页是分组卡片，每行左边标题与说明、右边控件（4.4）。
4. **阅读与编辑**：正文的字号、行宽与各种块的样式重做；属性收成标题下的一条紧凑的属性条；右栏可收起；编辑器与阅读同宽同位、正文用比例字体，编辑时保留大纲（4.5）。
5. **其余页面**：工作区首页、笔记本首页、搜索、历史、回收站、目录、健康、升级、导入导出、版本、附件、登录、引导、邀请与空状态，照同一套基础重排（4.6）。
6. **无障碍规则按"视觉优先"改写**：影响外观的规则（对比度门槛、焦点框的粗细、链接下划线）让位于美观；键盘操作、可访问名称、焦点去向照旧（负责人第 1 问，4.7）。

## 2. 范围

**做**：`web/apps/web/` 的样式、组件、外框与设置的布局、阅读视图的样式与前端增强、编辑器的主题；随之改的 vitest 与 e2e；总体设计第 9、12、13.2、13.4 节的有关段落与 `docs/README.md`；README、`CHANGELOG.md` 0.1.0 一节与三份人工清单里描述界面的文字。

**不做**：

- 新功能。不加接口、不改服务端、不改数据库。胶囊搜索框是现有搜索框的新样子加一个聚焦它的快捷键（4.2.4）；属性条是服务端已渲染的属性表的新样式（4.5.2）。
- 服务端渲染的 HTML 不改形状（`nw-props`、`nw-callout`、`nw-scroll` 等类名照旧），阅读视图的新样子由前端的 CSS 与增强做出。
- 搜索摘要里露出 Markdown 原文（`--- tags:`、`**`、`[[…]]`）：要改服务端的摘要，不在 M13，写进 v0.2 的移交（第 7 节"写给后面的 M"）。
- 富文本（所见即所得）编辑：编辑器仍是源码编辑，只换主题与字体。
- 网页字体：只用系统字体（主持者的决定 722）。
- v0.2 打磨清单里与外观无关的项（第 7 节"移交的落实"）。

- 编辑器的选区 → `--accent-soft`（`W/editor/theme.ts:34`）；对比视图折叠的行 → `--surface-2`（`W/editor/text-diff.tsx:417`）。

**形状与层次**：行（导航、菜单项）7 px；输入框、下拉 8–9 px；卡片、设置分组 14 px；弹出层 12 px；弹窗 16 px；工具栏按钮与搜索框是胶囊（999 px）。阴影只给弹出层与弹窗（亮：两层，近处 1 px、远处 10/28 px；暗：1 px 的白色描边加深阴影），卡片不加阴影、只用边框。

**字**：系统字体（`-apple-system`、`PingFang SC`、`Microsoft YaHei` 等，等宽用 `SF Mono`、`Menlo`）。字号：界面 13–14 px，侧栏行 13.5 px，正文 16 px、行高 1.8，页面标题 32 px，设置页标题 26 px，分组标题 13 px。界面上反复用的两个是变量：`--text-compact`（13 px：紧凑的按钮、标签、分组标题）、`--text-row`（13.5 px：侧栏行、菜单项、对话框的说明）；标题的字号由用到它们的 Step 定（[01-P1](01-P1-foundation.md) 2.1 第 4 条）。不用全大写的标签。

**动效**：颜色与底色 150–180 ms；菜单、弹窗、抽屉出现时淡入加轻微缩放或滑入（150 ms），**收起不加动画**（Radix 的退场动画让收起中的内容留在 DOM 里，紧接着打开另一个菜单时会短暂有两个 `menu`，主持者的决定 737）；`prefers-reduced-motion` 时只留淡入。

**语义名的例外**（写进 13.2 的新条目）：mermaid 的 `themeVariables` 只收十六进制色值，在 `W/reading/diagrams.ts` 里重写一份亮暗色值；`reading.css` 的 hljs 与 callout 各色、`W/editor/theme.ts` 里的语法色可以写色值，但要与本节的表同源（注释写明出处）。

#### 4.2.5 窄屏（< 768 px）

（主持者的决定 731，补全初稿的 720。）

- 页面顶部一条 44 px 的细栏，随页面滚走（不粘住，免得 `reading.css:80` 的 `scroll-margin-top` 让锚点落到它下面）：菜单按钮与当前位置的文字（不是标题元素：很多测试要求页上只有一个 `h1`）。账户在抽屉底部的账户行里，细栏上不再放一个同名的账户按钮（`accountMenu` 按名称精确匹配，两个同名会撞）。
- **侧栏在所有宽度下是同一个元素**，从不因断点卸下或挪位：窄屏时用 CSS 移到画面之外，关着时带 `inert`；打开时滑入，盖一层遮罩，焦点困在侧栏里（Radix 的 `FocusScope`），Esc 或点遮罩关闭。这样，宽屏下在树的行上打开的对话框，窗口缩到 375 px 之后照旧开着（pg2、lw3 正是这样做的：`e2e/stories/page/pg2-rename-page.spec.ts:179-185,214-235`、`e2e/stories/wiki/lw3-source-duplicates.spec.ts:346-380`；pg2 是 `webkit-narrow` 的必需格，`tools/e2e-projects/check.mjs:27`）。不用 Radix 的 Dialog 做抽屉：它关着时卸下内容。
- `dialogOpen()`（`W/app/shortcuts.ts:39-41`）明确处理抽屉：抽屉开着时别的快捷键让路，⌘K 与 Mod+Shift+F 照旧聚焦抽屉里的搜索框；关着时不算对话框。
- 在抽屉里点了链接或提交了搜索：抽屉随地址的变化关上，焦点在这次提交里离开抽屉；只改查询参数的 `replace`（筛选的待用选择在失焦时用掉）是页面自己的，不算离开，抽屉留着。树里打开别的页的链接（平时 `opened`，连同"目录""历史"两行与"更多"的图标）在抽屉开着时带 `arrived`，去向页的 `h1` 取焦点；点的是当前的地址时照旧 `opened`（同一页不重新挂载：标题取不取焦点要看原来那一条的路由状态，给菜单按钮才一致）。去向是 `arrived`、带附件的定位（`Located`），或后退、前进到带 `opened` 的一条时，焦点由去向页的标题或附件行取（13.2 第 17 条）；其余的导航（首页、设置、切换工作区、当前的地址、在结果页上再提交）与 Esc、点遮罩关上时，焦点给菜单按钮。被"未保存"拦下、选了"留下"时抽屉关上，焦点留在确认框还给的地方（编辑器、横幅或冲突的标题）。Esc 让给输入法的组字与有字的搜索框（浏览器先清空它；不清空的浏览器里照常关上）（[02-P2](02-P2-shell.md) 决定 782、790、797、799、807、808）。

#### 4.4.3 保存方式

（主持者的决定 715、729、735。）

- **下拉即生效**，照 `useChoice`（`W/components/ui/native-select.tsx:57-105`）：鼠标选中即发，键盘逐项走时等失焦或回车才发。另持一份草稿（照 `W/pages/notebook/general-page.tsx:91-113` 的 `AccessForm`）：发出之后下拉显示新值直到服务端答复，被拒时退回原值；发送中不禁用下拉（禁用会丢焦点）；键盘走到的一项还没发出时，说明照显示的那一项，Esc 退回已生效的值（[03-P3](03-P3-settings.md) 决定 840）。`useChoice` 自己在发出后清掉待定值、显示已生效的值（`native-select.tsx:67-74`），而 `NotebookStore.update` 不是乐观的（`W/stores/notebook.store.ts:108-114`），所以要这份草稿。
- **写到服务端的单选组不做即生效**：13.2 第 12 条的理由（方向键就会改选中项）照旧。要即生效的改成下拉，留着单选的照旧"保存"。只存在本机的偏好（主题、语言）今天就是单选即生效，照旧。
- 生效之后显示"已保存。"：仍是 13.2 第 12 条那个常驻的 `<output>`，文字一直在（n3:77-78、n6:79、w4:115 以精确的"Saved."读它），前面的 ✓ 只用 CSS 的 `::before` 画，不进文字；1.5 秒后只把透明度降下来；被拒时原因显示在这一行下面（`useForm` 的横幅照旧）。
- **文字输入**（名称、显示名）：改动之后才出现"保存"，回车也保存，失焦不自动保存。保存成功、按钮随之消失时，焦点交给输入框（`useFocusLeaving`，13.2 第 17 条），不落到 `body`。改密码、新建令牌、邀请、加成员这些"提交一份表单"的照旧有按钮。
- **危险与不可逆的操作**（删除、离开、停用、升级、降级）照旧先确认。
- 例：笔记本常规页今天有名称与开放程度两个"保存"（`W/pages/notebook/general-page.tsx:44-54,89-135`，测试以 `getAllByRole(...)[0/1]` 区分）。开放程度改为即生效的下拉（三项，说明随选中项变），名称照上面的文字输入；e2e 的 `changeAccessWith`（`e2e/fixtures/notebook-pages.ts:84-91`，以"工作区里的开放程度"一组找控件）随之改成选下拉，n3 的两处调用不动。
- 13.2 第 12 条补一句"设置页的下拉即生效，照 `useChoice` 并持草稿；写到服务端的单选组仍经保存"（P3/S2 改写）。

#### 4.5.5 编辑

- 编辑器与阅读的正文同宽、同位置，进出编辑时页面不跳。

- **对比与冲突视图照旧等宽**（`W/editor/text-diff.tsx:390-397` 与编辑器共用主题；看空白的差异要等宽），只换配色。
- **"保存"按钮保留，但只在有未保存的修改或保存失败时显出**：已经自动保存（M5），⌘S 照旧立即保存；保存失败时它就是重试（自动保存只在下一次修改、⌘S 或离开时重试，`W/editor/autosave.ts:10-12`，窄屏的触屏用户需要它）。它拿着焦点时不消失：有未保存的修改时显出，显着的时候焦点在头一行右边那一组里（状态、"保存"、开关、"完成"），它就一直留着，焦点离开那一组、又没有未保存的修改时才隐去；没有修改时焦点走进那一组，藏着的它不显出；不显出时它照旧占着位置、不可聚焦，头一行的行数不随它变（状态因此离开关约 70 px，样稿是 8 px，记成偏离）；拿着焦点、没东西可存时按它不做事（保存失败一定伴随未保存的修改）；窗口失焦（换窗口、换应用）不算焦点离开。原来"它拿着焦点时消失、焦点交给编辑器"（主持者的决定 745）让键盘用户刚到它上面就赶上自动保存完成，接下来按的 Enter 或空格打进了正文（[04-P4](04-P4-reading.md) 决定 885、894、895、896 改判）。点"保存"的 vitest（`W/pages/page/page-edit.test.tsx:286`、`page-autosave.test.tsx:327`、`page-asset-upload.test.tsx:365,387,434,449,660,691`、`conflict.test.tsx:79`）都是在有修改时点的，P4/S3 逐个核对；`page-autosave.test.tsx:327` 是闲置退出的焦点目标，按钮不显时另定去处。e2e 的 `saveEdit` 按 Mod+S（`e2e/fixtures/wiki-pages.ts:228-231`），不变。
- **编辑时的右栏**：照旧显示今天编辑时显示的（反向链接、属性、版本，`W/pages/page/page-versions.test.tsx:403-409`），另加大纲。编辑时的大纲来自编辑器的语法树（标题节点，去掉 frontmatter 范围里的），点按跳到那一行；编辑时不标"当前节"（v0.2 清单"编辑时没有大纲"，第 7 节"移交的落实"）。它与阅读时的大纲一样有上限（至多 `listedUpTo` 个，并说还有多少，13.2 第 25 条）；不在每次按键时重算整棵树，进编辑时先算一次，之后停手（去抖）再算。CodeMirror 自己的后台解析停在可见范围之后 10 万个字符（`@codemirror/language` 的 `MaxParseAhead`），不会自己"完成"，所以大纲以 20 ms 一片补完解析（`ensureSyntaxTree`），补完再算；补的途中文档又变了才重来，只换了选区或别的状态时接着补（主持者的决定 745；[04-P4](04-P4-reading.md) 决定 876）。

### 提交说明

照 M12（`docs/README.md` "Git 工作方式"）：

- **代码**：`<范围>: <说明> (M13/P<n>/S<m>)`，范围是部件（`web`、`e2e`、`docs`、`tools`，多个用逗号），例如 `web: the design tokens and the amber accent (M13/P1/S1)`。
- **文档**：直接进 `m13-ui-refresh` 的写 `docs: <说明> (M13/P<n>)`，M 级的写 `(M13)`；Step 的分支上的每个提交写 `(M13/P<n>/S<m>)`。
- **审查的修复**：合并之前的写到 Step；修复的核对写第几轮 `(M13/P<n>/S<m> fix check <k>)`；收尾 `(M13 closeout)`。
- **合并**：Step 合并回 `m13-ui-refresh`：`Merge branch 'm13-p<n>-s<m>': <说明> (M13/P<n>/S<m>)`；收尾的修复：`Merge branch 'm13-closeout': <说明> (M13 closeout)`；M13 合并进 `main`：`Merge branch 'm13-ui-refresh': <说明> (M13)`。正文都经 `git merge --no-ff -F <文件>`。`Merge m13-ui-refresh into <分支>: <一句说明>` 与 `Merge main into m13-ui-refresh: <一句说明>` 不带后缀。
- **旁支**：分支 `m13-<slug>`（从 `m13-ui-refresh` 拉出）；修的是更早的 M 的故事时写 `(M<k> story, found in M13)`。
