# M6/P8 软换行：架构设计 & 实施规划

日期：2026-10-08。状态：进行中。

## 1. 背景

阅读视图按 CommonMark 渲染：段落里的单个换行是软换行，显示为空格（`<p>第一行\n第二行</p>`）。Obsidian 的阅读视图在"严格换行"关闭时（它的默认）显示为换行。M6 的文档此前没有定过这一点。负责人 2026-10-07 准备输入法清单时看到，决定与 Obsidian 一致；M6 的 Codex 评审把它列为不计的已知事项，并在 D1 里列了实施时要钉住的语义（[评审记录](reviews/M6-codex-review.md)第 5 节）。

## 2. 范围

- 只改阅读视图的 HTML，即服务端的渲染（P6A）。段落、列表项、引用、callout 的正文、脚注里的软换行都渲染为 `<br>`。
- callout 的标题到第一个换行为止，不带 `<br>`（`obsidian/callout.go` 清掉标题最后一段文字的换行标记，照旧）。
- 不变的部分：
  - 编辑器：它照原文显示各行。
  - 提取结果：链接、标签、任务的字节范围，属性。
  - `PlainText`、`ShownText` 仍把换行读成空格，所以标题的锚点 id、图片与属性链接的文字都不变。
  - 提取器的版本不变，不需要重建索引；反链的上下文也不变。

## 3. 设计

- `platform/markdown/render.go`：goldmark 的 HTML 渲染器加 `gmhtml.WithHardWraps()`。
  - 软换行的标记在每行最后一个文字节点上；行尾是链接、强调、代码时，goldmark 另加一个空的文字节点承载它。
  - 没有自定义的渲染器接管文字节点。
- 自己的行内节点在行尾时，换行的标记要留在树上，逐一测试：
  - 标签、wikilink、嵌入、注释、高亮、行内公式；
  - 表格的 `harden` 改写文字的地方。
- 下面两种 goldmark 渲染为 `<br>`，与 Obsidian 核对：
  - 两行的 setext 标题（`a\nb\n===`）；
  - 跨行的链接文字（`[a\nb](x)`）。
- 硬换行（行尾两个空格、反斜杠）仍是一个 `<br>`。

## 4. 与 Obsidian 核对

- 新增渲染样例 `tools/md-fixtures/render/`：每个样例有原文，以及每个块里按 `<br>` 分开的各行文字。
- 同一份期望由两边核对：
  - 服务端：渲染的测试；
  - Obsidian：`obsidian/verify-render.mjs`，在隔离的 Obsidian 1.12.7 实例里打开阅读视图读 DOM，与 `verify.mjs` 一样经 CDP，不碰本机的仓库。

## 5. 成本

- 每个软换行多出 `<br>`。一字一行时，输出最多约为原文的 3 倍，在 `CheckSize` 的上限（64 倍加 4 MB）之内。
- `markdowntest` 的病态样本加"很多短行"一种，由 `CheckCosts`、`CheckSize` 守住。

## 6. 测试

- 渲染：
  - 第 2、3 节的各种块；
  - 行尾的各种行内节点；
  - CRLF、BOM；
  - 硬换行；
  - callout 的标题与正文；
  - 标题的 id 不变。
- e2e：阅读视图的故事里加一处：两行的段落显示为两行。
- 反向对照：
  - 去掉选项；
  - callout 不清标记；
  - 自己的行内节点丢掉行尾的标记。
