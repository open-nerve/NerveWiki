## 0. 梳理

作者读了编辑器（`editor/registry.ts`、`extensions.ts`、`source-editor.tsx`）、页面的外壳（`pages/page/page-layout.tsx`）、事件的处理（`events/handlers.ts`、`app/event-stream.tsx`）、P5 的契约（`api/modules/linking.yaml`）、构建检查（`build/out-of-main.ts`）与 `@codemirror/autocomplete` 6.20.3 的源码（它已在依赖树里，随 `@codemirror/lang-markdown` 来）。

- **编辑器的扩展**同步返回 CodeMirror 的扩展；注册表由 `main.tsx` 静态导入，只许引用 CodeMirror 的类型。补全要构造运行时的对象，所以要先改契约（总设计 4.13）。
- **构建检查**把编辑器的入口写死为 `source-editor.tsx` 与 `conflict-view.tsx`：别的模块经动态导入到达，照样跟进去，会报"编辑器进了主包"。扩展的模块要算进编辑器的入口。
- **`@codemirror/autocomplete`** 已经处理输入法的一部分：组合中输入的文字会激活补全（`input.type.compose` 也是 `input.type`）；组合改了文字又移了光标时，结束后它自己重新开始补全。组合进行中弹出，要我们自己挡。`CompletionContext` 带 `view`，补全的来源能看到 `view.composing`。
- **页面的外壳**是一列：面包屑与标题、阅读视图或编辑器、子页。右栏要在外壳里加一栏。
- **事件**：`links` 带 `targets`（反链变了的页），P6 的处理还没有用；`pages` 带写过的页与 revision。
- **测试的组合根**：`test/render.tsx` 的 `renderApp` 已经能注入编辑器的扩展（M5 加的）。

- 右栏：布局（第 7 节）、大纲（第 8 节）、反链（第 9 节）、属性（第 10 节）；事件与重连时的重读（第 11 节）。

不做：

- `[[页面#标题` 与 `[[页面^块` 的补全：Obsidian 有，总设计没有要求（第 15 节）。
- 编辑时的大纲：总设计 4.12 交给 M12。
- 反链之外的"没有链接的提及"：总设计第 2 节不做。

## 2. 编辑器扩展的 `load`

**契约**（`editor/registry.ts`）：

```ts
type Build = (context: EditorContext, controls: EditorControls) => Extension;
export type EditorExtension =
  | { name: string; extension: Build }
  | { name: string; load: () => Promise<Build> };
```

- 带 `load` 的扩展，`load` 动态导入编辑器 chunk 里的一个模块，答出它的 `Build`。那个模块可以导入 CodeMirror 的运行时值；注册表本身仍只引用类型。
- 编辑器在造视图之前等全部的 `load`（`editor/extensions.ts` 的 `loadExtensions`，按注册表缓存一份 promise），再按注册表的次序组合。`SourceEditor` 用 React 的 `use` 等它，`PageEdit` 已有的 `Suspense` 显示"载入中"。
- 一个 `load` 失败的扩展照"构造时抛错"处理：写控制台，留在外面，别的照常（`composeExtensions` 现在的做法）。
- 这是改 M4 扩展点的契约（总设计第 8 节已写明）。M5 的三个扩展不变。

**构建检查**（`build/out-of-main.ts`）：编辑器的入口加 `src/editor/loaded/` 下的模块（`.ts` 与 `.tsx`，审查 r1-14）。约定：带 `load` 的扩展，它导入的模块放在 `editor/loaded/`。`lazyLeak` 的测试加一例：主包动态导入的 `editor/loaded/x.ts` 是编辑器的，不报；它被静态导入时报。lint 的模块边界一并管到 `editor/loaded/` 这一层（审查 r3-7）。

## 3. 补全的数据

`EditorContext` 加：

```ts
/** linkTargets reads the notebook's link targets (listLinkTargets): its pages, each with its link and aliases. */
linkTargets(): Promise<readonly LinkTarget[]>;
/** tags reads the notebook's tags (listTags), each with how many pages have it. */
tags(): Promise<readonly TagCount[]>;
```

- `PageEdit` 给出，经页面树的 store 调 `LinkingService` 的新方法 `linkTargets`、`tags`。
- **每个 `[[` 或 `#` 读一次**：同一处开始的补全 10 秒之内用同一次读到的数据，补全开着时按 `validFor` 在本地过滤（输入法每次确认都重新开始补全；查询没有匹配时 CodeMirror 每键作废结果：审查 r1-9、r3-1）。
  - 失败的不留，下一次再读；显式要的补全（Ctrl+Space，macOS 上另有 Option+\` 与 Option+I：Ctrl+Space 常被系统拿去切换输入法）重新读。
  - 别处开始的补全再读：别的标签页刚建的页、刚加的标签照样看得到，不需要事件去失效缓存。
  - 10 秒之内撤销重写、删掉重写拿到的是同一次的数据（核对 c1-4，接受）。
- 代价：一个 `[[` 读一次整个笔记本的目标。一万页约 1 MB；写进第 15 节（负责人可以改判：按事件失效的缓存）。
- 读失败：这次补全不弹出，不报错（写控制台）。

## 4. `[[` 补全

扩展 `linkCompletion`（`editor/loaded/link-completion.ts`），登记在 `editorExtensions` 的最后（M5 的三个之后）。

- **何时**：光标之前、同一行里最后一个 `[[`，其后到光标没有 `]`、`[`、`|`、`#`、`^` 与换行。那段文字是查询。`[[` 之前有奇数个反斜杠时是转义，不补全；反斜杠从 `[[` 往回数，不用正则（核对 fc6-c1-2）。
- **选项**：
  - 每页一项：显示标题，`detail` 是 `link`（与标题不同时：重名的页写的是路径）；
  - 每个别名一项：显示别名，`detail` 是"→ link"（审查 r1-12）。
  - 别名里有 `[`、`]` 或换行的不列（写出的不是链接）；表格里有 `|` 的也不列；frontmatter 里，页的链接或别名有 YAML 在引号里写不出的字符（`[`、`]`、制表符之外的控制字符、U+2028、U+2029、U+FFFE、U+FFFF）的不列（M6 Codex 评审 R1 及其修复核对）。`![[`（嵌入）只列页面：嵌入的显示文字是尺寸。
- **过滤**：CodeMirror 自己的模糊匹配，页面项按 `link`（标题，重名时是路径），别名项按别名。页面项显示标题，命中的字在标题里高亮（`getMatch`，按标题在 `link` 里最后出现的位置映射）。中文逐字匹配。
- **插入**（与 Obsidian 相同）：
  - 页：把 `[[` 之后到光标换成 `link]]`；
  - 别名：换成 `link|别名]]`；表格里别名的分隔写 `\|`（规则 3，同服务端的改写；审查 r1-1）；
  - 光标落在已闭合的链接里：只写过目标余下的部分（`^` 算目标的，服务端只认 `#` 开始锚点），锚点与显示文字留着，选别名时换掉显示文字（审查 r1-2）；
  - 光标落在 `]]` 之后。
- **不弹出**：在代码里（lezer 的 `InlineCode`、`FencedCode`、`CodeBlock` 及其子节点）；原始 HTML（`HTMLBlock`、`HTMLTag`、注释）、Markdown 链接的地址、自动链接里；只读时；组合进行中（第 6 节）。
- **frontmatter** 里只有紧跟字符串开引号的 `[[` 补全：属性链接是一个字符串的整个值；不带引号的 `[[x]]` YAML 读成嵌套的列表（审查 r1-4）；字符串之中、纯量、块的文字与注释里没有属性链接，别名写进去还可能让 YAML 失效（M6 Codex 评审 R1 及其修复核对）。
  - `openingQuote`（`editor/loaded/yaml-quotes.ts`）从 frontmatter 的第二行读到 `[[` 之前，读法照服务端的 YAML 库（`go.yaml.in/yaml/v3`）：引号里的字符串跨行与转义、键与值、流式集合、锚点、标签与别名、块标量与纯量的续行（以节点的列为准）、注释、YAML 的四种换行。`[ ]` 里单独的 `?` 之后紧跟 `]` 时，库的读法与 YAML 不一致，从那里起不补（只会漏补，负责人可改判）。
  - 写入按所在的字符串：单引号里 `'` 写两次，双引号里 `\` 与 `"` 转义。
  - 照服务端的 `frontmatterSpan`：第一行正好是 `---`，到后面一行 `---` 为止，`...` 不算结尾，`--- ` 不算开头；载入的内容没有 BOM（`line-breaks.ts`），粘贴到开头的不管（接受；核对 c1-2、fc3-c1-3）。
  - 编辑器把 frontmatter 当 Markdown 解析，它的 YAML 里却没有代码、原始 HTML 与表格：已闭合的 frontmatter 里不看这些节点。空行之后缩进的值、块标量里的围栏照样补全；表格里的别名不写 `\|`：双引号里的 `\|` 是 YAML 不认的转义（核对 fc3-c1-1、fc4-c2-3）。
  - 还没闭合的（服务端在闭合之前照正文读）从第二行到第一个空白行（只有空格与制表符）算正在写的 frontmatter：照正文写下的链接与标签闭合之后什么也不是（核对 fc2-c1-1）。其中的代码与原始 HTML 照正文不补全（代价：还在写的块标量里的围栏或 `<!--` 之后不补全；核对 fc4-c2-2）；表格不算（正在写的是在写 YAML，`\|` 会让它闭合之后失效；代价：以分隔线开头、紧跟一张表格的页，单元格里引号之后选别名写出 `|`，服务端切开单元格；核对 fc5-c2-2）。
  - 代价：以分隔线 `---` 开头、紧跟一段文字的页，那一段照 frontmatter 补全；正在写的 YAML 里有空白行（键之间、块标量的段落），过了它就照正文补全；`...` 结尾的旧式 frontmatter（服务端照正文读）到第一个空白行之前不补全不带引号的链接。
- **代价**：一行里很长的一串反斜杠，按键时与它的长度成正比；以 `---` 开头、没有闭合的长文档，每次补全照行扫到文末（线性，用文本自己的行迭代；核对 fc6-c1-3）。

## 5. `#` 补全

同一个扩展的第二个来源。

- **何时**：`#` 在行首，或前面是空白（含全角空格）；`#` 之后到光标都是标签的字符：Unicode 字母、组合用字符、数字、`_`、`-`、`/`（样例集规则 9，与服务端的 `isTagRune` 相同）。
  - 规则 9 还认紧跟在行内元素之后的 `#`（`**x**#tag`）与块的开头（`>#t`、表格单元格开头的 `|#t`），补全不认：要解析行内的结构，得不偿失（第 15 节）。JS 的 `\s` 与 Go 的 `IsSpace` 差 U+FEFF、U+0085（审查 r1-7，接受）。
  - 行首的 `# ` 是标题：一打空格就不再是标签，补全随之关掉。
- **选项**：`listTags` 里正文能写出的标签（标签的字符，不全是数字，不全是 `/`；审查 r1-5），`detail` 是页数。
- **插入**：把 `#` 之后到光标换成标签，并写过光标所在标签余下的字符（审查 r3-5）。
- **不弹出**：同第 4 节；frontmatter 里不补全（YAML 读成注释）。
  - 行内有没闭合的 `[[` 时不补全（那是锚点）：只认偶数个反斜杠之前、不在代码与原始 HTML 里的 `[[`（核对 c1-3）。表格里只看光标所在的单元格：最后一个前面不紧挨反斜杠的 `|` 之后，同 goldmark，`\\|` 也不分格（GFM 与 lezer 会分）；"表格"取的是编辑器 lezer 的判断。
  - `%%` 注释里的 `[[`、`$…$` 里的、Markdown 链接的文字里的照样挡住，接受（核对 fc2-c1-3）。

## 6. 输入法

- **组合进行中不弹出**：补全的来源在 `context.view.composing` 时答 `null`；`compositionstart` 时关掉已开着的补全。
- **组合中按回车不误选**：不另写键位，用补全自带的（审查 r1 对原设计的修订）。
  - CodeMirror 的视图在组合进行中不把按键交给键位（`InputState.ignoreDuringComposition`），Safari 在 `compositionend` 之后 100 毫秒之内的第一个按键也忽略。
  - 补全刚弹出 75 毫秒之内的回车也不接受（`interactionDelay`）。补全自带的键位没有 Tab：Tab 照旧缩进。
- **组合结束之后**：`@codemirror/autocomplete` 在组合改了文字、移了光标时自己重新开始补全（经输入的 100 毫秒去抖），这时来源照常答（中文标题的 `[[`、中文标签的 `#`）。
- **实测**（审查 r1、r3，核对 c1，Chromium，CDP）：组合中不弹出，确认之后列出，组合中的回车只确认输入法。两道防护缺一不可：去掉 `compositionstart` 时的关闭，或去掉组合中不答，L5 第二个故事都失败（笔记本里有一页能匹配组合中的拼音）。Safari、Firefox 靠人工清单。
- 列表的样式用应用的颜色（亮暗；审查 r1-3）；选项的文字与说明之间有读屏听得到的停顿（字号为 0 的 `", "`，留在文字流里；审查 r3-4、核对 c1-5）。
- 输入法清单加第 16–18 步（第 14 节）。

## 7. 右栏的布局

- `PageShell` 的正文（阅读视图或编辑器，子页）与右栏并排：`xl` 及以上两栏，右栏 15rem，靠上粘住（`sticky`），超出时自己纵向滚动；窄于 `xl` 时右栏排在正文之后。
  - `xl`：左边的工作区栏 15rem，`lg` 时正文只剩约 460px，太窄。
  - 右栏自己滚动时留出焦点环的边（审查 r2-6）。`overflow-anchor: none` 留作防护：右栏在正文之后，审查实测多半不承重。
- 右栏是 `<aside>`，名称"页面信息"（i18n）。三节：大纲、反链、属性，各是 `<details open>`，`<summary>` 里是节的标题 `<h2>`（读屏按标题跳转；审查 r2-10），字号在 `summary` 上；没有内容的节显示一句说明（大纲没有标题时整节不显示）。
- 编辑时：大纲不显示（总设计 4.12），反链与属性照旧。

## 8. 大纲

- 来自阅读视图读到的 HTML：与阅读视图用同一个读取（`page-view.ts` 的 `usePageView`，同一个键 `["page-view", notebook, page]`），SWR 去重，大纲不多读（审查 r2-9、核对 c2-4）。解析进 `<template>`，取文章里带 `nw-` id 的 `h1`–`h6`，从列出的标题里最高的一级起按级缩进。
- 文字是标题的文字（公式是原文，同服务端写的），去掉脚注的编号与图片的地址；脚注里的标题不列（审查 r2-7）。
- 至多列前 1,000 个标题，多的只计数（没有文字的不算；只有脚注编号或图片地址的照算），在列表之后写"……另有 N 个标题"：一页的标题在 5 MiB 之内可以有一百多万个，每个一条链接会把标签页的内存撑满（核对 fc6-c1-1、fc7-c1-1）。求最高的级别不把标题展开成参数：一次调用的参数有上限，约 12.5 万个标题时整页换成错误页（核对 fc5-c1-2）。
- 它随阅读视图的读取重渲，不随右栏：笔记本列表重读时给出的同一个笔记本按 id 认（`memo`）；编辑时大纲不挂载，离开编辑时重新解析整份 HTML。
- 点击经路由去 `#id`：与文章里的 `[t](#h)` 同一条路，阅读视图的锚点处理让标题拿到焦点、滚到那里（P6 第 6、9 节）。
  - 去折叠的 callout 里的标题：阅读视图先打开它所在的、关着的 `details` 再给焦点（审查 r3-6）。正文里指向别的锚点的链接同样；指向地址里已是的锚点的链接是浏览器自己的导航，Chromium 里同样打开，其他引擎待人工确认（核对 c2-9）。
- 是 `<nav>`，名称"大纲"。

## 9. 反链

- `listBacklinks`，SWR 键 `["backlinks", notebook, page]`，第一页 50 个。
- 每项：出发页的标题（取自已加载的树，链接到那一页），链接数大于 1 时写"N 处"（1000 写"1000+ 处"），然后每行上下文（纯文字，原样，不保留缩进，`…` 是服务端加的）。
  - 树里还没有的出发页（别的标签页刚建的，树还没重读）先不显示，树重读之后出现。第一页的出发页都不在树里、还有下一页时，不说"没有"（审查 r2-8）。
- **"更多反向链接"**读下一页（`next_cursor`），接在读它时那一页之后（按游标认）。
- **重读**（事件、重新聚焦、重连、回到这一页）读缓存里此刻的页数，从第一页起（审查 r2-1；核对 c2-2、fc2-c2-2）。
  - 加页时有读在路上（这一个视图的，或回到这一页时新挂载的那个的：看缓存里 SWR 的状态；SWR 会丢掉它），再读整个列表（审查 r2-3、核对 fc3-c2-3）。
  - 代价：读了很多页之后每次重读都读那么多页（经 refresher 与 SWR 的聚焦限频，回到这一页也是）；其中一页失败，整次作废，按 SWR 的重试再读（核对 c2-6，第 15 节）。
- **焦点**：读到最后一页、"更多"消失时，焦点去它加的第一个显示出来的项；它加的都不显示（还不在树里），去列表里最后一个显示的项；一项都不显示，去这一节的标题。不滚动（`preventScroll`：新项就在按钮原来的位置）。审查 r2-2，核对 c2-1、fc2-c2-1、fc3-c2-4、fc3-c2-6、fc4-c2-1、fc5-c2-1。
  - 条件：读取中读者什么也没做，焦点还在"更多"上或哪里都不在（Safari、macOS 上的 Firefox 鼠标点按钮、iOS 的轻点、读屏的浏览模式可能不给按钮焦点）。
  - "做了什么"是滚动、点击、触摸、按键，与阅读视图同一组 `readersInput`（`readers-input.ts`）。在"更多"上再按一次不算，那不是去了别处：Enter、空格、Escape、Shift、Ctrl、Alt、Meta，主键的按下、触摸的轻点、双击。别的键（滚动的键在内）、中键与右键的按下、在它上面滚动照算。
  - 读者在读取中做了什么、或把焦点放到了别处（别的链接、编辑器），焦点与滚动都不动。读屏的情形待人工确认（M12）。
- 没有反链：一句说明。
- 代价：读了上万项之后，每按一次"更多"、每次重读都在 0.3–0.5 秒量级（整张列表重渲；逐项 memo 归 M12，核对 fc7-c1-3）。

## 10. 属性

- `getPageProperties`，SWR 键 `["page-properties", notebook, page]`。
- 每个属性一行：键，值。
  - 字符串照写；数字、布尔照写；`null` 写空；列表逐项；列表里的列表、对象写成 JSON。
  - 属性链接（`links` 里有这个路径：标量是键本身，列表的项是 `键.序号`）：解析到页面的写成链接，只去页面（`PropertyLink` 没有锚点）；解析不到的照写，带未建的样式。
- **链接按路径给值**（审查 r2-5，核对 c2-3、fc2-c2-3、fc3-c2-2）：
  - 一个路径上只有一个字符串时，那个路径的链接就是它的（服务端就是这样配的，与形状无关）。
  - 几个值共用一个路径时（键 `a.0` 与列表 `a` 的第一项，极少），那个路径的链接按书写的次序依次给其中像链接的值；对象里的链接照样占位。
  - "像链接"照服务端的形状（规则 10），只在共用的路径上起作用：wikilink 一致（有目标，整值是一个）；Markdown 链接是近似（服务端按正文解析）：文字里没有未转义的方括号，地址在 `<>` 里或不以 `<` 开头、没有空白（括号至多一层），可有标题；地址不是别处（scheme、`//`），目标不空。
  - 差异的值在共用的路径上会拿错链接或显示原文，接受（核对 fc4-c1-2；M12：`PropertyLink` 带值的序号）。跨行的字符串（块标量、跨行的引号字符串）与别名展开出的值，服务端不记路径，客户端照样数，也分不出，接受。
- **链接的文字**：wikilink 照服务端的 `wikilink.shown()`：显示文字，或目标与锚点，" > " 隔开，去两端的空格与制表符，`\|` 结束目标。Markdown 链接的文字照写，不解转义、字符引用、强调，与阅读视图的属性表不同（审查 r2-4、r3-8，接受；M12：`PropertyLink` 加 `text`）。
- **代价**（核对 fc3-c2-1、fc4-c1-1、fc5-c1-1）：
  - 正则里相邻的空白不能分给两段，wikilink 的去空白从两端往里走：平方的回溯曾让特意写的长值卡住读者的标签页。
  - 共用的路径只在有链接的路径上数。
  - 路径长于 1,024 个 UTF-16 码元的属性链接不配对，在右栏显示原文（阅读视图的属性表里仍是链接；同一个列表的项可能一半是链接一半是原文）：浏览器的 Map 对很多超过 16,383 个字符的串要平方的时间，Node 里看不出。
  - 每次挂载、每个答复算一次，进入、离开编辑与树变时的重渲不重算。
- frontmatter 不合法：一句说明。没有属性：一句说明。
- 阅读视图顶部 M4 的属性表照旧（总设计 4.12）。

## 11. 事件与重读

`events/handlers.ts`：

- `links`：
  - `targets` 里的每一页读反链；`null` 读笔记本里显示着的全部反链；
  - `pages` 里的每一页读属性（属性链接的解析变了）；`null` 读全部。
- `pages`：写过的每一页（`pages` 里的）读属性；`null` 读全部。没有修订号可比；本标签页编辑时自己的保存也会让属性重读（经 refresher，至多 5 秒一次）。
- 都经 refresher（同阅读视图的重读，合并、限频），只为读过的页请求（缓存里有它的键；正在第一次读的也算：SWR 挂载时就写下键）：refresher 为每个请求过的键留一项，点名笔记本里所有页的事件不能让它一直长（核对 fc7-c1-4；`links` 事件的阅读视图一并照此）。
- 频率：每保存一次链到这一页的页，就有一个 `links` 事件点到这一页；反链至多每 5 秒重读一次已读的那么多页；目标超过 20 个时事件给 `null`。
- 重连时（`app/event-stream.tsx` 的 `refreshedOnConnect`）：`backlinks`、`page-properties` 与 `page-view` 同一层：已删的页在树重读时离开，不读右栏。笔记本删除、页面编辑中留着时，右栏读到 404，保留原来的内容；C4 的预期随之加两条 404。
- 补全的数据不经事件：每个 `[[` 或 `#` 都读（第 3 节）。

## 15. 与总设计的出入、负责人可以推翻的决定

- 补全的数据每个 `[[` 或 `#` 读一次，同一处的补全 10 秒内不重读（显式要的重读），不按事件失效（第 3 节）。
- `[[页面#标题` 的补全不做（Obsidian 有）。
- `#` 补全不认紧跟在行内元素之后的标签，也不认块的开头（第 5 节）。
- 还没闭合的 frontmatter 到第一个空白行算正在写的（第 4 节）。
- 编辑器的 Markdown 不认 frontmatter：YAML 块标量里没闭合的围栏或 `<!--` 让 lezer 把之后的整篇正文当代码，正文不补全（高亮也错）；根治是让编辑器认出 frontmatter（M12）。
- 补全的"表格"照 lezer（GFM：表头与分隔行格数相等），服务端的 goldmark 宽一些（表头少于分隔行也算，表头里的 `\\|` 不分格）：这时选别名写出不转义的 `|`，服务端切开单元格（核对 fc3-c1-2，少见，M12 对齐）。
- 右栏在 `xl` 以上才在旁边（第 7 节）。
- 大纲至多列 1,000 个标题（第 8 节）。
- 反链的重读读已读的页数，不设上限（第 9 节）：可以改为设上限（比如 5 页，多的收起）。
- 属性链接只去页面；Markdown 属性链接的形状是近似，文字照写；路径长于 1,024 个码元的不配对（第 10 节）。
