# 编辑锁与链接改写

M5 的编辑锁（[M5 总设计](../../M5-collab-editing/00-M5-design.md)第 4.1、4.4 节）：一页有活着的编辑会话时，不带这个会话的正文写都被写入守卫拒绝（409 `page.locked`），别的账户删除这一页或它的上级页同样被拒；改名、移动照常。

M6 的链接改写是写入单元的参与者追加的正文写（总体设计 4.5、12.4）。它不带持锁的会话，所以：

1. **改名或移动一页时，若引用它的某一页正被人编辑，参与者追加的改写被守卫拒绝，整个改名回滚**。负责人确认过改名、移动在有人编辑时照常（M5 总设计第 11 节第 2 项），M6 要在下面几种做法里选一种，并在 M6 的设计里写明：
   - 被锁的页跳过改写，之后补改：例如锁释放时（会话的结束订阅者）或由后台任务，期间链接经节点 id 仍能解析；
   - 守卫放行"链接改写"这一种写（经写入选项标明），持锁的编辑器接收外部更新：这时才需要总体设计 9.3 的"只替换差异、不进撤销历史"，M5 没有做它（M5 总设计第 2 节；[M4/P6 编辑器移交](../../M5-collab-editing/handoffs/M4-P6-editor.md)第 2 项：撤销恢复的换行写法要复核，组合中收到更新不打断组合）；
   - 改名被拒，说明哪一页正被谁编辑：最简单，但违背负责人的决定，要先问负责人。
2. **持锁的编辑器里的未保存修改**：若选第二种，外部更新与编辑器里没保存的修改要合并，而不是覆盖。
3. **测试**：不管选哪一种，在整个程序上加一个"改名时引用它的页被锁"的行为测试。
