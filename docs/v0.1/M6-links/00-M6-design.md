## 1. 目标

M6 结束时：

1. **方言**：`[[…]]`、`![[…]]`、`#标签`、callout、`==高亮==`、`%%注释%%`、数学公式在阅读视图里按 Obsidian 的样子显示（总体设计 4.1）。
   - 它们是 `Parse` 的语法树上的节点，提取与渲染出自同一次解析；
   - 样例集 `tools/md-fixtures/` 的提取期望（链接、标签、属性链接）第一次由 Go 测试全部核对。
2. **索引**：每条写入路径都在同一个事务里维护链接、标签、属性与别名的索引，并按总体设计 4.4 解析链接：
   - 新建、改名、移动、删除节点，改写正文（含改了别名），都重新解析受影响的链接；
   - 阅读视图按索引显示每条链接是否解析到页面，链接状态变了的页面经事件流重读。
3. **改写**：改名或移动一页（连同子树）时，按字节位置改写受影响的链接，与改名或移动在同一个变更集里原子完成。
   - 需要改写的页面里只要有一页正被编辑（包括自己在编辑），整个操作答 409，列出这些页面与编辑者。
4. **接口**：反链、标签、标签下的页面、页面属性、补全用的链接目标；`nervewiki reindex` 重建全部索引。
5. **前端**：
   - 阅读视图：链接与标签在应用内跳转（包括普通 Markdown 的本站链接）；点未建的页时，写者确认之后新建；
   - 数学公式用 KaTeX，`mermaid` 代码块用 mermaid，都按需加载；
   - 编辑器：`[[` 补全页面与别名，`#` 补全标签；
   - 页面的右栏：大纲、反链、属性。

## 2. 范围

做：

- 服务端：Obsidian 方言的语法扩展；链接索引模块 `linking`；链接解析与重新解析；链接改写的参与者；链接状态变化的事件 `links`；反链、标签、属性、链接目标的接口；`nervewiki reindex`。
- 平台：
  - `==` 加进加固过的强调游程；
  - 表格包一层可滚动、可聚焦的区域（M4 留下的宽表格）；
  - 解析预算移到平台，由组合根共享；写入路径只带提取结果，不带语法树。
- 前端：阅读视图的链接跳转、标签页、KaTeX、mermaid；改名与移动被拒时的说明；编辑器的补全；右栏。
- 样例集：
  - 补上解析样例 `resolve/`，以及树与路径的改写样例 `rename/`；
  - `obsidian/verify.mjs` 扩展到解析与改写，与 Obsidian 1.13.7 核对。

不做：

- 嵌入整篇页面（v0.1 显示为链接，总体设计 4.1）。附件的嵌入属于 M7；M7 之前没有附件节点，`![[x.png]]` 显示为解析不到的嵌入。
- 块引用 `^id` 的校验、锚点是否存在的校验（总体设计 4.4）。
- "没有链接的提及"（Obsidian 反链面板的 unlinked mentions）与关系图。
- 编辑器接收正文的外部更新（第 4.6 节：被锁的页不改写，所以编辑器用不到）。
- 歧义链接的 lint：M6 在索引里记下歧义，lint 本身属于 M10。

3. 每条写入路径（新建、改名、移动、删除子树、写正文、勾选任务、笔记本删除）都有整个程序上的行为测试：索引随之更新，`links` 事件到达流；组合根不登记时失败。

## 4. 关键决定

### 4.1 方言在平台里：`platform/markdown/obsidian`

- 语法扩展是纯粹的语法：wikilink、嵌入、标签、callout、高亮、注释、数学公式。
  - 它放在 `platform/markdown/obsidian`，与 M5 的 `platform/markdown/tasks` 并列；
  - goldmark 仍然只在 `platform/markdown` 之下导入，archtest 的 `markdownLibrariesStayInMarkdown` 不必改；
  - 它可以用 `internal/harden` 的链接状态（`inLinkLabel`），处理"链接文字里的 wikilink"（样例 030、040）：两条链接都计入，渲染时里面那条不做成 `<a>`，避免嵌套的链接。
- 需要数据库的部分不在平台里：渲染时按页取链接状态的 `Fetch` 由 `linking` 模块给出，组合根把它交给 `obsidian.Extension(fetch)`，照 `markdownExtensions()` 登记。
- 分隔符式的 `==` 加进 `internal/harden/emphasis.go` 的游程（`*`、`_`、`~` 之外），配对规则与 `~~` 相同；它是平台的改动，不是扩展能做的（M4/P3 移交第 2 项）。
- `%%` 注释只影响显示，不影响提取（样例集规则 6）。语法树照常解析注释里的内容，一个变换把注释范围里的节点标为隐藏，渲染时跳过。
- 数学公式是原始内容（规则 4、5），解析器整段吃下。
  - 行内 `$` 的结束位置按段落预先算一遍，保持线性；
  - 渲染为带 TeX 原文的占位元素，前端用 KaTeX 渲染。
- callout 是一个变换：把第一段以 `[!type]` 开头的引用块改成 callout 节点。
  - 带 `-`、`+` 的可折叠，渲染为 `<details>`；
  - 其余渲染为 `<div>`，类型写在 `data-callout`。
- 每种节点都有渲染函数；元素、属性与 class 登记在 `Markup`（`nw-` 前缀），由 `CheckHTML` 核对。
- **样例先行**（13.3 第 2 条）：语法细节以 `cases/` 为准，P1 的 Phase 文档逐条列出实现与规则的对应。

### 4.2 提取结果

`obsidian` 扩展的 `Extract` 给出：

- **链接**：`{Kind, Target, Anchor, Display, Key, Range}`，与样例集 JSON 的字段一一对应（README"提取结果的格式"）。
  - `Kind` 是 `wikilink`、`embed`、`link`、`image`；
  - 属性链接的 `Key` 是属性路径（`sources.0`），正文里的为空。
- **标签**：每一次出现，`{Name, Range}`；frontmatter 的 `tags` 由索引从属性里取。
- 属性链接要字节位置，现在的 YAML 解析没有保留位置（`yaml.go`）。
  - P1 改为从 `yaml.Node` 的行列换算成字节偏移；
  - go-yaml 的列按字符计，换算要按 UTF-8 字节；
  - 由样例 060 守住。

Markdown 链接与图片现在由核心的 `marks` 渲染，`ast.Link` 不带目标的字节位置。提取改为在 `internal/harden/links.go` 做链接时记下目标的范围（作为节点的属性），引用式链接的范围取自定义（规则 8，`LinkReferenceDefinition`）。

### 4.3 链接索引：`linking` 模块

新模块 `server/internal/modules/linking`（总体设计 7.2），布局照现有模块：

- `domain`：解析规则、最短写法、改写的字节替换；
- `app`：索引的观察者、改写的参与者、查询；
- `adapter/postgres`、`adapter/http`。

表（迁移 00019，归 linking；都是派生数据，没有 `deleted_at`）：

| 表 | 列（要点） |
|---|---|
| `indexed_pages` | `node_id`（主键）、`notebook_id`、`revision`（索引所依据的正文版本）、`frontmatter_valid` |
| `page_links` | `id`、`notebook_id`、`source_id`、`kind`、`property_key`、`target`、`anchor`、`range_start`、`range_end`、`target_key`（目标最后一段的标题键，用来找候选）、`resolved_id`、`ambiguous` |
| `page_tags` | `source_id`、`notebook_id`、`tag`（第一次出现时的写法）、`tag_key`（标题键）、`count` |
| `page_properties` | `source_id`、`notebook_id`、`key`、`value`（`jsonb`） |
| `page_aliases` | `source_id`、`notebook_id`、`alias`、`alias_key` |

- 跨模块的外键（`source_id`、`resolved_id` 指向 `nodes`，`notebook_id` 指向 `notebooks`）一律 `ON DELETE RESTRICT`（13.1 第 6 条）。
- 索引行只指向活着的节点：
  - 删除子树时，删掉被删页面自己的行；指向被删节点的链接在同一个事务里重新解析；
  - 删除笔记本不经写入单元（M4/P3 移交第 10 项），linking 注册笔记本删除事件，在同一个事务里删掉这些笔记本的全部索引行；
  - 所以页面的清理不会被挡住，linking 不需要清理器。总体设计 12.4"笔记本删除事件"的注册者加上 M6。
- 恢复（M8）是一次正文与树的写，经观察者重建索引。
- 新表写进 `deploy/runtime-grants.sql`；`sqlc.yaml` 加一条。
- 索引不是权威，可以随时重建（第 4.10 节）；读取时以 `indexed_pages.revision` 与正文的 revision 是否相同判断它是否可用（第 4.7 节）。

### 4.4 解析

解析规则是 `linking/domain` 的纯函数：输入链接、出发的页面与候选节点（名称、标题键、父节点、深度、祖先），输出解析到的节点与是否有歧义。总体设计 4.4 是起点，P2 用 `resolve/` 样例与 Obsidian 核对之后定稿。已知要核对的三处：

1. **路径**：4.4 写的是"按路径精确匹配"。Obsidian 的"尽量短"写法会写出 `[[x/note]]` 这样的**路径后缀**；从 Obsidian 导入的笔记里，这种写法很常见。所以路径按后缀匹配，从笔记本根起的完整路径是后缀的特例。
2. **相对路径**：wikilink 与 Markdown 链接里的 `./`、`../` 按出发页面导出后的位置解析（导出映射见总体设计 3.5：页面 `A` 是 `A.md`，它的子节点在 `A/` 下）。
3. **别名**：4.4 让 `[[别名]]` 解析到有这个别名的页面。Obsidian 只在补全时用别名，插入的是 `[[标题|别名]]`，`[[别名]]` 本身不解析。这是总体设计已定的偏离，保留，在样例里标为 `nerve-defined`。

其余照 4.4：

- 名称按标题键比较；页面去掉 `.md` 再匹配；附件按带扩展名的文件名匹配。
- 匹配到多个时，先选同一父节点下的，再选路径最短的，再按 id，并标记歧义。
- 链接只在笔记本内部解析。

### 4.5 何时重新解析：索引的观察者

linking 注册为页面领域事件的观察者（12.4"页面领域事件与写入单元的参与者"），每个写入单元在提交之前调用一次，拿到合并后的全部变更（`Event.Changes`）：

1. **正文变了的页**（`Change` 带 `Revision`）：按提取结果替换它的链接、标签、属性与别名行，并解析它的每条链接。
2. **树变了的节点**（新建、改名、移动的整棵子树、删除）与**别名变了的页**：重新解析可能受影响的链接。候选是：
   - 目标的标题键是这些节点旧名、新名或别名的；
   - 解析到这些节点的；
   - 出发页在移动的子树里的（相对路径与同一父节点的偏好会变）。
3. 只更新解析结果真的变了的行，并收集两组页面，在同一个事务里发一次 `links` 事件（第 4.8 节）：
   - 链接状态变了的出发页（不含本单元正文变了的页，它们已在 `pages` 事件里）；
   - 反链变了的目标页。

不读整个笔记本的树：按候选的标题键查节点，再查它们的祖先链。前后都空的变更（M9 的批量里建了又删的节点，[M9 移交](../M9-mcp/handoffs/M4-P2-unit-merge.md)第 2 项）不做任何事。

**并发**：

- 同一笔记本的两次正文写只持笔记本行的 `FOR SHARE`，可以同时进行。例如一页加了别名 `x`，另一页同时写了 `[[x]]`，两个事务都看不到对方，索引会停在"解析不到"。
- 所以观察者在开始时取 linking 自己按笔记本的一把锁，同一笔记本的索引维护串行。在 READ COMMITTED 下，后来者等到先来的提交之后，它的语句能看到先提交的行。写法（事务级的 advisory lock，或 linking 自己的一行）在 P2 定。
- 这把锁是单元最后取的锁，在页面正文的行锁与笔记本行之后，不会成环。树的单元本来就持笔记本行的 `FOR NO KEY UPDATE`，与正文写串行。

### 4.6 改写：参与者，被锁时整个拒绝

linking 注册为写入单元的参与者，在改名与移动之后调用（`Participate(ctx, Step, Appender)`）。

1. **保住原来的指向**：改名或移动之后，凡是解析结果会因此改变的链接，都改写成仍指向原来节点的最短写法。包括：
   - 指向被移动子树的入链；
   - 子树里出发、因位置变了而指向别处的出链（相对路径、同一父节点的偏好）；
   - 本来指向别处、改名之后会被这个节点"抢走"的链接。

   这比总体设计 4.5 第 1、2 条更宽：4.5 只说了入链与相对路径的出链，"被抢走"的链接按同一条原则一起处理。只有原来就解析不到的链接，改名之后解析到了，不改写。
2. **最短写法**：
   - wikilink 依次试名称、更长的路径后缀，取第一个只匹配原节点、没有歧义的；
   - Markdown 链接保持原来的写法（相对或从根起），重新算路径；
   - 别名、锚点、显示文字与引号风格照 `rename/` 样例的规则保留。
3. **字节替换**：只替换 `Range` 那一段（4.5"按字节位置精确替换"）。替换之后的正文经 `Parse` 得到新的提取结果，随追加的正文写交给守卫与观察者。
4. **锁**：
   - 先算出需要改写的页，一次查出其中活着的编辑会话；
   - 有一页被锁，整个单元答 409 `page.links_locked`，problem 带 `locks: [{page_id, user_id, display_name}]`，列出全部页面与编辑者（M5 的 `lock` 成员只能带一页）；
   - 本人的锁同样拒绝：本人在别处编辑的那一页如果被改写，编辑器里的正文就过时了，下次保存会冲突；
   - 负责人确认（第 11 节第 1 项）。追加的写照旧经过编辑锁的守卫，作为最后一道防线。
5. **次序与一致性**：
   - 改名、移动是树的单元，持笔记本行的 `FOR NO KEY UPDATE`，正文写在它提交之前进不来；
   - 追加的写以当前 revision 为 base，按节点 id 升序（`unit_content.go` 的约定）。
6. **关闭改写**：`Options.UpdateLinks` 为假时（M9 的 `move update_links=false`），参与者不改写，只由观察者重新解析。网页总是改写。

### 4.7 解析预算与内存

改写一次可能追加很多页的正文写。现在每个写入路径把完整的语法树（`*markdown.Document`）放在 `Change.Parsed` 里，直到单元结束交给观察者，同一单元的语法树会同时占着内存（最坏约正文的 300 倍）。改为：

- 写入路径解析之后只保留提取结果：`Parsed` 是 `markdown.Facts`（frontmatter、各扩展的提取结果，不含语法树与原文）。语法树在提取之后即可回收。任务项的勾选在写之前要用提取结果，照旧。
- 解析预算从 `page.Module` 移到平台（`platform/markdown.Budget`），由组合根建一个，交给 page 与 linking。
  - 参与者逐页取预算、解析、提取、归还；
  - 取不到时照现在的规则等 `page.parse_max_wait`，然后整个单元答 503 `server_busy`。
- 阅读视图的 `Fetch` 先读 `indexed_pages` 与这一页的链接行：
  - 索引的 revision 与读到的正文相同时，按字节位置取状态；
  - 不同时（读正文与读索引之间有写），按当前的树即时解析，与总体设计 4.3 对历史版本的做法一致。

### 4.8 链接状态的事件 `links`

- 照 [M5 的事件移交](handoffs/M5-events.md)第 1–3 项注册：
  - 按笔记本过滤；
  - 载荷 `{pages, targets}`，都是页 id 的数组，多于 20 页时为 `null`（照 `pages` 的退化）；
  - 在观察者里、调用方的事务中发布。
- 这个类型按笔记本过滤，不是工作区级的，所以移交第 4 项（不发 `access` 的路径）与它无关。
- 前端的 `eventHandlers` 加 `links`：
  - 重读 `pages` 里各页的阅读视图与 `targets` 里各页的反链；
  - `null` 时重读这个笔记本里挂着的全部阅读视图与反链；
  - 连上时的整体刷新（`refreshedOnConnect`）把反链加进阅读视图那一层。

### 4.9 渲染：地址由前端给

- 链接节点渲染为 `<a>`：
  - 解析到的带 `data-nw-node`（节点 id），解析不到的带 `class="nw-unresolved"` 与 `data-nw-target`；
  - Markdown 链接与图片的链接若解析到笔记本里的节点，同样带 `data-nw-node`；
  - 嵌入照链接渲染，另带 `nw-embed`；
  - 标签是 `<a class="nw-tag" data-nw-tag>`；
  - 属性表里的属性链接同样渲染为链接。
- `href` 由前端的增强设置：服务端不知道工作区的 slug（`markdown.Page` 只有笔记本与页面），而阅读视图的 HTML 只给前端用。
  - 增强按 `ReadingContext` 的工作区、笔记本写出应用内的地址，点击经路由跳转；
  - 修饰键与中键照浏览器的默认行为，地址是真的；
  - 普通 Markdown 的本站链接同样经路由跳转（[M4/P3 移交](handoffs/M4-P3-markdown-extensions.md)第 11 项）。
- 解析不到的链接（第 11 节第 2 项）：
  - 能写的人点击时问"新建页面「x」？"，确认之后在当前页的同一父节点下新建并打开；
  - 目标带路径而路径的父页存在时，建在那里；不是合法标题、或父页不存在时，只说明页面不存在；
  - 只能读的人点击时说明页面不存在。
- 数学公式的占位元素由增强用 KaTeX 渲染（`trust: false`），`mermaid` 代码块由增强用 mermaid 渲染（`securityLevel: 'strict'`），两者都是单独的 chunk，用到时才加载。
  - CSP 现在的 `style-src 'self' 'unsafe-inline'` 与 `font-src 'self' data:` 已经容纳它们；
  - P5 实测，不需要 `unsafe-eval`，不放宽 `script-src`（总体设计 4.6"具体写法在 M6 确定"）。
- 表格由渲染器包一层 `<div class="nw-scroll" tabindex="0">`，横向滚动从整个阅读视图移到这一层。
  - 可访问的名称由前端的增强补上，可聚焦的代码块一起补（M4 收尾的修复核对 MN-3）。

### 4.10 `nervewiki reindex`

- 子命令照 `workspaces` 的样板，经 `bootstrap` 组合，不起 HTTP 与后台任务。
  - 可选 `--notebook <id>`；
  - 不带时逐个笔记本处理。
- 每个笔记本一个事务，持笔记本行的 `FOR NO KEY UPDATE`（与改名同级，正文写在此期间等待）。
  - 先按当前的 Unicode 数据重算节点的标题键（总体设计 3.5）；
  - 再逐页取预算、解析、写索引；
  - 最后解析全部链接。
- 升级到 M6 之前已有的页面没有索引：开发库与负责人冒烟用的库在升级之后运行一次（写进 README 的开发一节）。v0.1 还没发布，没有要迁移的生产数据。

### 4.11 接口

见第 5 节。补全的数据来自 `GET …/link-targets`：

- 每个节点给出它的标题、种类、别名，以及从笔记本任何地方都没有歧义的最短写法 `link`；
- 最短写法与改写用的是同一个函数，前端不重算标题键（JavaScript 没有完整的大小写折叠）。

### 4.12 右栏

- 页面的外壳在宽屏上加一栏 `<aside>`，窄屏时排在正文之下，各节可以折叠。
- **大纲**：阅读视图的标题（`h1`–`h6` 的 `nw-` id），点击滚动到那里。编辑时隐藏：编辑器里的标题要另做解析，v0.1 不做（留给 M12 的打磨）。
- **反链**：链接到这一页的页面，每页给出链接所在的那一行作上下文，分页。
- **属性**：这一页的 frontmatter 属性（索引里的值），属性链接可以点击。

### 4.13 编辑器的补全

- 编辑器扩展 `linkCompletion`，经组合根的 `editorExtensions` 登记（12.4"编辑器扩展管线"）。
  - `@codemirror/autocomplete` 改为直接依赖，只在编辑器的 chunk 里；注册表照旧只引用类型（`build/editor-out-of-main.ts` 守住）。
- `[[` 之后补全页面（标题与最短写法）与别名：
  - 选页面插入 `[[link]]`；
  - 选别名插入 `[[link|别名]]`，与 Obsidian 相同。
- `#` 之后补全标签，规则与标签的识别一致（样例集规则 9），在代码里不弹出（lezer 判断）。
- `EditorContext` 加笔记本的补全数据（M4/P6 移交第 2 项"M6 的补全要页面树，各自加"）。
- 输入法：组合进行中不弹出、不接受补全。输入法清单加第 16–18 步：中文标题的 `[[` 补全、中文标签的 `#` 补全、组合中按回车不误选。

## 8. 本 M 建立与注册的扩展点

注册（总体设计 12.4）：

- Markdown 解析与渲染扩展：`obsidian.Extension(fetch)`。
- 页面领域事件的观察者（索引）与写入单元的参与者（改写）。
- 笔记本删除事件：删掉索引行。
- 实时推送的事件类型：`links`。
- 阅读视图的交互增强：链接跳转、标签、KaTeX、mermaid、表格与代码块的名称。
- 编辑器扩展管线：`linkCompletion`。

建立：无新的扩展点。M10 的 lint 读 linking 的索引（歧义、属性），M9 的 `backlinks`、`index`、`move` 调 linking 的查询与 `Options.UpdateLinks`，都是对模块的调用，不是扩展点。

## 9. 测试策略

- **样例集是规范**（13.3 第 2 条）：
  - `cases/` 的提取、`resolve/` 的解析、`rename/` 的改写各有一个读样例的 Go 测试；
  - 样例与 Obsidian 的核对用 `verify.mjs`，它在独立的数据目录启动 Obsidian，不碰本机已有的库。
- **成本**：新语法的病态输入：
  - 不闭合的 `[[`、`==`、`$`、`%%`；
  - 深层嵌套的 callout；
  - 很多的标签与嵌入；
  - 每行一个 `$` 的长段落。
  全部经应用实例的 `CheckCosts`。
- **模糊测试**：
  - `FuzzRender` 加带扩展的实例；
  - 改写的模糊测试：随机的正文与改名，改写之后再解析，每条链接仍指向原来的节点，范围之外的字节不变。
- **交错**（13.1 第 18 条的做法）：
  - 改名与正文写；
  - 改名与开启会话（会话开在需要改写的页上）；
  - 两次改名；
  - 删除与正文写（链接指向被删的页）。
- **最后一跳**（13.1 第 21 条）：
  - 索引、改写、事件、扩展、补全、事件处理各有一个经组合根的测试；
  - 组合根交空时失败。
- **e2e**（L 系列）：
  - L1：wikilink 跳转，解析不到的显示为未建；改名之后链接仍然跳到那一页；
  - L2：写者点未建的页，确认之后新建；读者只看到说明；
  - L3：改名时引用它的页被别人编辑，改名被拒并说明是谁在编辑哪一页；
  - L4：标签跳到标签页；数学公式与 mermaid 渲染出来；
  - L5：`[[` 与 `#` 补全；
  - L6：右栏的大纲、反链、属性，别的标签页加了链接，反链实时出现。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 解析规则与 Obsidian 不一致，导入的笔记链接解析不到 | P2 的 `resolve/` 样例与 Obsidian 核对（路径后缀、相对路径）；有意的差异写明理由 |
| 改写一个被很多页引用的页面很慢：同一事务里逐页解析，持笔记本的锁 | 逐页取预算，只保留提取结果；P3 测量一次改写 500 页的耗时与内存，写进 Phase 文档；超出时考虑分批（v0.1 不做） |
| 改名被锁挡住的频率 | 负责人已接受（第 11 节第 1 项）。409 列出全部编辑者，管理员可以强制解锁，闲置 30 分钟也会释放 |
| 抢走链接的判断漏掉某种情形，改名之后链接悄悄指向别处 | 第 4.6 节的原则做成模糊测试的不变量：改名前后，每条原来解析到的链接仍指向同一个节点 |
| KaTeX、mermaid 的体积与 CSP | 单独的 chunk 按需加载；P5 在 CSP 下实测，必要时调整 `style-src` 的写法并记入 4.6 |
| Unicode 数据升级改变标题键 | `nervewiki reindex` 先重算标题键，再重建索引 |
