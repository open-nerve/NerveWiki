# 负责人的决定与偏好

从 Claude 在负责人笔记本上的记忆提炼出来。原话加引号，带日期。各 M 的产品决定的全文在各 00 号设计的第 11 节，这里只是索引与工作方式。

## 1. 沟通

- **用中文汇报**，简短。在一个 M 收尾、或被要求停下的时候汇报：
  - 做完了什么；
  - 审查的结论；
  - **负责人可以改判的决定**，一条一行，带理由；
  - 还欠负责人的事。
- **不要总停下来。** 2026-09-30："你不用总是停下来,除非有重大的架构决策冲突, 或者意外情况才需要停下来找我汇报确认"。重大冲突的例子：设计与现实矛盾、一个决定要改总体设计的边界。意外的例子：外部服务不可用、要做破坏性的操作。
- **从 M10 之后起**（2026-10-26）：项目交给 Codex 推进，"仅在 M 级别做完之后，我们来审核"。
- **每个新的 M 开始之前要负责人点头。** M1 起每个 M 都是负责人说了"可以开始"才开工；产品问题在那时问，给推荐的选项。
- **体验上的小问题留到 v0.1 之后统一打磨。** 2026-10-03："有些优化体验上的小问题,不够不要紧, 全部v0.1 收官之后,到时候再统一精修打磨细节"。
  - 打磨的清单在 `docs/v0.1/M12-release/handoffs/M5-polish.md`，按条追加。
  - 真的缺陷（丢数据、错的行为、审查标出的可访问性失败）仍在它的 M 里修。
- **人工清单最后统一验收。** 2026-10-13："IME 清单,我最后 统一验收就可以了"。MCP 客户端清单同样在 v0.1 的最后做。不要因为它们阻塞任何 M。
- **额度或时间紧时**，负责人会说"做完某个单元就停"（2026-10-25："P1-S2 干净收官 就暂停一下"）。照做：干净地收尾那个单元再停，不做一半。

## 2. 质量

- **生产级。** SOLID，照代码库已有的端口与适配器，不过度设计；每一层都有测试（单元、真库的适配器、整个程序、e2e）。
- **独立审查用最强的模型。** 2026-09-30："我们拉起的 子 subAgent 跑的也是 opus 5.5 的模型吧, 不要自行降级"。对 Codex 的意思是：审查者、实施者都用你可用的最强的模型，不为省事降级。
- **审查是对自己项目的深度代码审查。** 不是攻击别人的系统。写给审查者的说明用"our own open-source project in development"一类的说法，免得被误判为安全攻击。

## 3. Git 与推送

- **推送由执行者自己做。** 2026-10-14："其实你自己控制 push 节奏就好了，比如每做完一个 Phase 验收收官 合流之后就可以 push"。
  - 只推完成并核对过的 `main`：合并加文档，CI 绿。
  - **从不强推 `main`**，从不推做了一半的东西。
  - 每次推送之后看 `main` 的 CI。
- **提交与合并的写法**：见 [02-workflow.md](02-workflow.md) 第 5 节。

## 4. 不能碰的

- **负责人自己的客户端配置。** 从不改、也不对着它们运行 MCP 客户端：`~/.claude.json`、`~/.claude/`、`~/.codex/`、任何项目里已有的 `.mcp.json`。远程开发机上同样，除非是你自己为测试新建的临时目录。
  - 整个程序的测试与 e2e 里有自己的 MCP 客户端（官方 Go SDK、TypeScript SDK），够用。
  - 真实的 Claude Code、Codex 只在负责人的人工清单里跑。
- **兄弟项目 Nerve**：只读参考。远程开发机上没有它。
- **别人的进程与容器**：只停自己起的，按 PID；不用 `pkill`/`killall`，不重启 Docker。
- **不下载语料。** 负责人的笔记、Obsidian 的 vault 从不读。量性能用合成的数据或仓库里的 Markdown。下载依赖与工具链是正常的开发准备，不在此列。

## 5. 各 M 的产品决定（索引）

- **M5**：没有按账户的推送连接上限（交 M12）；服务端不设编辑会话的空闲上限（交 M9）。
- **M6**：改名或移动时链接改写碰到被锁的页，整个拒绝（409，列出每页与编辑者）；写者点一个解析不到的链接，先确认再建页。
- **M8 搜索**（2026-10-14）：单个汉字只搜标题；拉丁文字 3 个及以上按子串（三元组），1–2 个按整词；结果的数目是约数。
  - 2026-10-17 的 Codex 评审 R1（计时的旁路）：每本笔记本各自的搜索键。负责人接受了这些代价：`page_search` 约是正文的 5 倍，索引任务约每秒 125 页，跨上千本笔记本的搜索约慢一倍。
- **M9 MCP**（2026-10-17）：
  - agent 对历史只读：撤销、还原、恢复是网页上的人做的，但 `batch` 的变更集要能在网页上整组撤销；
  - MCP 的写碰到编辑中的页答 `page.locked`，不接管；
  - 根下的 `AGENTS` 页是说明（约 32 KB 截断），没有时用内置的短说明；
  - `grep` 之外另有 `search`；
  - 显示 MCP 地址的网页界面等打磨。
- **M10 LLM Wiki**（2026-10-24）：
  - 来源写一次之后只读：网页上"粘贴或上传为来源"，agent 用一次 `write`；只有笔记本管理员能改名、移动、删除来源；与已有来源字节相同的新来源被拒，并指出那一份在哪里；
  - `type`、`summary` 只由 lint 检查，不拒绝写入；
  - 模板随建的人的界面语言（中文或英文），三份 playbook 是英文；
  - 健康度面板能读笔记本的人都看得到，两种模式都有，打开时算。
