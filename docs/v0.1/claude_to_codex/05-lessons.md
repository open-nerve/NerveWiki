# 经验教训（M0–M10）

每一条都出过真问题，出处在各 Phase 的审查记录里。按主题排。

## 1. 测试能不能失败

- **每个新的断言都要证明它会失败。** 写一个变异去跑它。见过的失败方式：
  - 一个假的排版器写的是文本节点，`> :first-child` 从来匹配不到；
  - 比较两个空集合；
  - 夹具的 Markdown 没有扩展，任何正文都解析成同样的事实（M10/P1/S1 的 A-M3）。
- **先在没改过的树上跑一遍变异的命令。** 有一次一个测试从第一次就失败，十个变异都是对着它量的。
- **"等价的变异"要在审查者的语料上核对。** 有一个只有在另一处修好之后才不等价。
- **性质测试的下限**要数"变异会显出来的那种情形"出现的次数，不是"规则触发了"的次数；生成器要真的到得了它要的形状；换几组种子再信它。
- **一个反例只钉住一种形状。** 模板的段落对应一开始只有"块数"的反例，标题级别、列表项数、围栏、段落行数各要一个（M10/P1/S1 的 A-M1）。
- **整个程序的测试要走到最后一跳**：把组合根交的注册者换成空，测试必须失败。
- **日志检查只读自己子测试开始之后的行。**
- **测试准备不能超过 4 秒的请求期限**（CI 的竞态检测下约慢 1.7–2 倍）；大的种子用 SQL，或用生产的期限。
- **限时的测试**：不要库的、按时间判的测试在 `-short` 下跳过，在 `test-go-costs` 或 `test-go-guards` 里有它自己的一行（带 `-v`）。界线取本机的三倍，并对照 CI 在竞态下的时间。

## 2. 替身（fake）

- **替身要在真东西会失败的地方失败**：拒绝表的检查会拒的行（M10/P1/S1 的 A-N2）；失败时答零值；签名器签它真会签的东西。
- **测试文件不要导入它要测其注册的东西**（图片编码器会注册解码器）。
- **`vi.fn` 会给它返回的 promise 挂处理器**，未处理的拒绝因此不会冒出来。要探查时用普通的函数。

## 3. 交错与锁（PostgreSQL）

- **交错用确定的办法逼出来**：持住双方都要的行，等对方在等锁（`pgtest.WaitForLockWaits`），再放开。不用 sleep。
  - 两个请求之间的先后，要在一个共用的日志里断言，否则交换它们的变异能活下来。
  - "等到 N 次读"不是"流已连上"的信号：用一个直通的路由先挂住流，等放过的读都答完。
- **持有者在提交时才放的行锁不排队**：一个新请求可以在等着的工作之前拿到它。
- **唯一的持有者从不排在等待者之后。** 同一事务里重入一行的锁不会等。所以 M10/P1/S1 的那个子测试钉住的是 PostgreSQL 的行为，不是我们的锁序。
- **`SKIP LOCKED` 的语句的测试要有上下文的期限。** 等 `ctx.Done()` 的测试要给等待设界，并断言是谁停下的；否则一个变异会挂住整个包。

## 4. PostgreSQL 的计划与代价

- **pgx 的语句缓存让服务端在第 5 次之后换成通用计划**，之后 `SET LOCAL enable_*` 不起作用。引导计划的测试要设 `plan_cache_mode = force_custom_plan`，并核对计划真的被采纳了。要确定地看计划模式，可以查 `pg_prepared_statements.generic_plans/custom_plans`。
- **`pg_stat_get_xact_*`** 累计一个连接的事务，约 1 秒才上报一次。在事务里取两次读数的差。
- **PG18 的 B-tree 跳跃扫描会用非前导列**：钉住索引的定义（`pg_get_indexdef`），不要只看名字。
- **不到 30,000 行的表会被整表分析**，计划是确定的；在这样的测试里关掉这张表的 autovacuum，"没有统计"的状态才保得住。
- **改一个计划要量多种形状**：几种数据分布（含一个文件夹占了大部分行），乘三种状态（没有统计、分析过、清理过），再乘自定义与通用两种计划，然后才选。
- **全局的库设置**（比如为一条语句关掉 JIT）要在每条热路径上量过再定；数据显示只有几条语句需要时，取窄的改法。
  - 加一个启动参数会弄坏连接池，改用连接之后 `SET`。
- **代价的界线只盖住列为"病态"的那些输入。** 每个节点都会调用的帮手要有它自己的密集输入。

## 5. 上限与解析

- **上限要在它要防的工作之前检查**，不是在一次本该被它阻止的读之后。
- **约束库真正收到的东西**（它的输出，或它清洗之后的标签），不是源文本：每一个只看文本的检查都被绕过过。
- **给一个库做预读，要与它的读法一模一样**（例如 archive/zip 的 zip64 检查），并把它拒绝或试探的那部分也算进读的上限。
- **手写一个库的非标准读法会追着越来越罕见的形状跑**（YAML 扫描器跑了三轮以上）。改为设一条安全的边界：宁可不做（只漏、不写错），并以审查者对着真库做的差分为证据。
- **V8 对 ≥16,383 字符的字符串按长度哈希**，许多长的不同键的 Map/Set 在 Chromium 里是平方级的，在 Node 里却不是。要在 Chromium 里计时。

## 6. 前端

- **焦点**：
  - Chromium 在下一次渲染时才做 HTML 的焦点修正，jsdom 从来不做；
  - Safari 不让点过的链接获得焦点，`focus()` 的滚动也在下一次渲染；
  - 焦点与滚动的修复要在三种 Playwright 引擎里探查，套件本身只跑 Chromium；
  - 一处改了焦点的规则会波及别处：对照空闲退出、未读的内容、portal 里的对话框逐一核对。
- **SWR**：默认的比较对相等的数据保留旧对象，按答复挂的计时器因此不动了，用 `compare: Object.is`；挂上之后约 5 秒内焦点触发的重读被节流。
- **MobX**：每个 action 一个 reaction，加上 React 的合批，只有最后一条通知会渲染出来。把一轮的通知经 `setTimeout(0)` 合起来。
- **可读的名字**：
  - jsdom 会去掉 `sr-only` 里开头的空格，真的空格放在它外面；
  - Playwright 给块级的子元素补空格，后缀用括号起头，例如 `raw (source area)`；
  - 可读的名字在 Chromium 里由 e2e 按确切的名字核对（M10/P1）。
- **e2e 的"安静的控制台"能抓到事件驱动的读与登出的竞态。** 不需要流的故事就把流挂住。
- **`page.unroute()` 去掉一页的最后一个路由会关掉拦截**，正在那一刻发出的请求就挂住了。保留路由，用 `fallback`。
- **审查者不要在 `node_modules` 链回仓库的副本里跑 pnpm 或 vitest。** 给他们一个自己的副本，`pnpm install --frozen-lockfile --prefer-offline`。

## 7. CI

- **新的推送会取消同一分支上正在跑的 CI**（concurrency group）。等最新的那次跑完，不要连着推。
- **作业日志要认证才能读**；失败的作业的 annotations（`/check-runs/<job id>/annotations`）与每一步的时间是公开的。Playwright 在 CI 上用 `github` reporter，e2e 的失败因此读得出来。
- **testcontainers-go 在 `go test ./...` 的所有包之间共用一个 Ryuk 会话**；一次连接失败会让后来的包丢掉 Postgres。所以 CI 的 Test 一步设了 `TESTCONTAINERS_RYUK_DISABLED=true`。
- **CI 的 Linux 回环在套接字缓冲小于 64 KiB 的 MSS 时被限到约 3 MB/s。** 只在 Linux 上失败的测试，在 `golang:1.27.1-trixie` 容器里复现（`--cpus=2`、`-race`）。
- **同一棵树上，CI 的同一份测试可以差三成**（第一份 4:59–7:39）。判断挪不挪分份界线时，取两次运行的平均。
- **CI 的 lint 失败会盖住数据库变异归到哪个测试**：变异的分支也要过 lint（例如 `_ = x`）。
- **`make image-smoke` 会因为只被用户的全局 gitignore 忽略的文件报 `modified=true`。** 先看 `git -c core.excludesFile=/dev/null status --porcelain`。

## 8. 流程

- **修复的核对每一轮都要做，做到干净为止。** M5–M7 里，核对一再找到上一轮修复自己引入的回归（焦点、锚点、滚动）。
- **删掉一个"看不出效果"的守卫之前，先试交错**：双击、按住的键、失败的路径。M4 删过一个，结果它是看得出的。
- **日志写事实（大小、计数），不写推断出的原因。** 同一个结果可以有相反的原因。
- **审查者的探针**（穷举、新旧实现的差分）是最强的证据，要请他们做，并留下它们。
- **在改坏代码的时候不跑 `make gen*`。**
- **复原改坏的文件不用 `git checkout --`**，它会连没提交的改动一起丢掉；从备份复原。
- **`oxlint` 的退出码要单独看。** 接一个 `| tail` 的管道藏住过一个警告，结果被推了上去。
- **在工具的输入里写 `\uXXXX` 会被当成 JSON 转义变成字符**（Claude 的工具的毛病，Codex 未必有）。Go 的测试里要转义时，事后用 Python 的 `chr(92)` 补；新的测试文件 lint 之前扫一遍非 ASCII 的字符。
- **只改契约的说明也要 `make gen`**，然后 `make gen-check`。生成物在提交之后才一致。
