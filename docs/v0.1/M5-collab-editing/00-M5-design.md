## 1. 目标

M5 结束时：

1. **编辑锁**：一页同时至多一个活着的编辑会话，锁就是这个会话（总体设计 3.9"锁是会话的排他"）。
   - 拿不到锁就停在阅读视图，显示"某某正在编辑"；
   - 自己在别处持锁时可以接管；笔记本的管理员可以强制解锁；
   - 退出编辑、关闭标签页、闲置 30 分钟时释放，崩溃、断网由租约兜底。
2. **锁与写入**：
   - 不带持锁会话的正文写（PAT、MCP、阅读视图的勾选）答 409 `page.locked`，答复里带持锁人；
   - 删除这一页或包含它的上级页，在别人持锁时同样答 409；
   - 改名、移动照常；删除笔记本、工作区照删，结束其中的会话。
3. **自动保存**：停顿约 2 秒保存；输入法组合中不保存，组合结束后补存；`Ctrl+S` 立即保存。
4. **事件流**：
   - 一个浏览器一条 SSE，推送页面树、正文与锁的变化；
   - 阅读视图、页面树与"某某正在编辑"随之更新；
   - 访问范围变化、令牌到期、凭证撤销、笔记本删除时关闭，客户端重连之后整体刷新。
5. **任务项**：阅读视图里勾选任务项，按字节位置写回正文（瞬时写入）。
6. **扩展点**：
   - 注册 M4 建立的：会话的否决者与订阅者、写入守卫、页面领域事件的观察者、Markdown 扩展（任务项）、阅读视图的增强（任务复选框）、编辑器扩展管线（自动保存、失锁时只读）。
   - 注册 M3 建立的：可见性变化事件与笔记本删除事件（关闭事件流）。
   - 建立：实时推送的事件类型（总体设计 12.4，M6、M10、M11 注册）。
7. **移交**：收到的六份，逐项落实或说明理由（第 7 节）。

## 2. 范围

**做**：第 1 节各项，以及它们的接口描述、页面与端到端故事。

**不做**：

| 事项 | 理由与去处 |
|---|---|
| 多人同时改一页（CRDT、操作变换） | v0.1 不做（总体设计 1.2）：锁是排他的 |
| 编辑器接收别人的外部更新（总体设计 9.3 的"只替换差异、不进撤销历史"） | 持锁期间没有别人的正文写（第 4.4 节），M5 用不到。M6 的链接改写要改一个被锁住的页时由 M6 决定，这时才需要它（[M6 的移交](../M6-links/handoffs/M5-locks.md)） |
| "某某正在编辑"在页面树、笔记本首页上的标记，在线状态 | 只在页面本身显示。其余随 v0.1 收官之后的统一打磨（负责人，2026-10-03；[M12 的移交](../M12-release/handoffs/M5-polish.md)） |
| 事件补发（`Last-Event-ID`） | 总体设计 3.11：重连之后整体刷新 |
| 移出成员时立即结束他的会话（[M4/P4 移交](handoffs/M4-P4-edit-sessions.md)第 3 项） | 不做。他被移出或看不到笔记本之后心跳答 404，降为阅读者之后答 403，编辑器随之停止心跳，锁至多再留一个租约（120 秒，第 4.6 节），管理员也可以强制解锁。立即结束要给 `edit_sessions` 加 `workspace_id` 并注册工作区的成员身份结束，只换来提前至多两分钟 |
| 删除与新建之后的导航（[M4/P6 移交](handoffs/M4-P6-editor.md)第 7 项） | 并入 v0.1 收官之后的统一打磨（[M12 的移交](../M12-release/handoffs/M5-polish.md)）：只在删除的答复与树的重读之间（几百毫秒）用户又导航时出现，不丢数据 |
| 多实例部署的验证 | v0.1 单实例。LISTEN/NOTIFY 本身支持多实例（总体设计 3.11），M12 的部署文档写明 |

## 4. 关键决定

### 4.1 锁就是活着的编辑会话

- **活着**：`ended_reason IS NULL AND expires_at > 时刻`，时刻取应用的时钟。心跳、结束、`writersSession` 锁住会话之后的核对、否决者、守卫、读锁、告诉订阅者，全用这一个定义（第 4.3 节的墓碑不活着）。
- **一页至多一个活着的会话**：开启会话时，在这一页正文行的锁（`FOR NO KEY UPDATE`，M4 的开启本来就取）下：
  1. 先删掉这一页已过期的行（含过期的墓碑）。这样，一个用较早的时刻发出、晚到的心跳续不上刚过期的会话，只会找不到它；
  2. 否决者查这一页活着的会话，有就答 409 `page.locked`，带持锁人。同一账户的也一样，除非请求要接管（第 4.2 节）。
- **正文的写按会话，不按账户**：持锁人自己的其他客户端（另一个标签页、PAT、MCP）不带这个会话的正文写同样被拒，答复的持锁人是他自己，前端说"你正在别处编辑"。锁的意思是"这一页的正文现在只经这个编辑器改"：自己的另一个标签页或自己的 MCP 代理写进来，编辑器里没保存的修改一样会撞上，与其事后冲突，不如事前拒绝。删除按账户，见第 4.4 节。
- **不加唯一索引**："活着"取决于时刻，部分唯一索引表达不了。排他由正文行的锁把开启与开启、开启与保存串行起来，交错测试守住（第 9 节）；`checkPages` 加"每页至多一个活着的会话"。
- **放在哪里**：`edit_sessions` 归 page 模块，sqlc 按模块（总体设计 13.1 第 24 条），锁的查询只能在 page 里。
  - page 的模块根给组合根一个 `page.NewEditLock(pool, names)`，它同时是会话的否决者与写入守卫，经 `pageRegistrants(pool)` 登记（`names` 取持锁人的显示名，组合根交 identity 的目录）。
  - 挂在组合根上的只是"否决与守卫"这一项策略：M4 的扩展点由它第一个注册，M11 的冻结可以排在它旁边。
  - 接管与强制解锁要写会话、告诉订阅者，否决者做不到（它只能返回错误），所以是 page 自己的用例（第 4.2 节）。组合根交空时，它们照样生效，只是不再有人被拒。

### 4.2 接管与强制解锁

- **接管**：`openEditSession` 加一个可选的请求体 `{take_over: true}`，经 `SessionOpening.TakeOver` 交给否决者。在正文行的锁下：
  - 持锁的是同一账户：把那个会话标为被接管（第 4.3 节），告诉结束的订阅者（原因 `taken_over`），再开新会话；
  - 持锁的是别人：照样 409 `page.locked`。接管不越过别人，只有管理员能强制。
  - 同一账户的任何客户端都能接管，包括令牌与 MCP 代理（负责人的决定 1"网页与令牌"）。M9 决定它的工具是否给出这个选项（[M9 的移交](../M9-mcp/handoffs/M5-locks.md)）。
- **强制解锁**：`DELETE /api/v0/pages/{page_id}/edit-lock`，笔记本的管理员（有效角色）。
  - 走写入单元的加锁与判定：不改树，以 `FOR SHARE` 锁笔记本行；
  - 在单元里先锁正文行，再把这一页活着的会话标为被解锁，告诉订阅者（原因 `unlocked`，带执行者）。这是总体设计 13.1 第 5 条"强制解锁先取正文行、再动会话"的次序；
  - 没有人持锁也答 204。
- **读锁**：`GET /api/v0/pages/{page_id}/edit-lock`，能读这一页的人都能读。
  - 答复：`{holder: {user_id, display_name} | null, expires_in}`，`expires_in` 是剩余的秒数。不用到期时刻：客户端的时钟可能不准（照 M1 令牌的做法）。
  - 阅读视图据此显示"某某正在编辑"，过了 `expires_in` 秒再读一次（租约过期不是事件，第 4.6 节）。
  - 不放进阅读视图的答复：读锁很便宜，阅读视图要解析正文、占解析预算。

### 4.3 会话为什么结束：墓碑与码

M4 的会话一结束就删行，编辑器遇到心跳的 404、保存的 409 `page.edit_session_ended` 就悄悄重开。有了锁之后，悄悄重开会把强制解锁抢回去，也会让两个标签页互相接管。所以：

- **墓碑**：被接管与被解锁的会话不删行，记下 `ended_reason`（`taken_over` 或 `unlocked`）、`ended_by_id` 与 `ended_at`。
  - 按第 4.1 节的定义，它从这一刻起不再活着；
  - 保留至少一个租约：`expires_at` 取它原来的值与"结束时刻加一个租约"中较晚的，之后与过期的会话一起删除（这一页下一次开启或强制解锁时，或后台的清理）；
  - 不把 `expires_at` 改小，所以 `expires_at > created_at` 的检查照旧成立；
  - 并发的心跳：它的 `UPDATE` 带 `ended_reason IS NULL`，在行锁上等到接管提交之后，按新版本重判，不会把墓碑续成活的。
  - 迁移 00018 加这三列与检查（三者同为空，或同不为空；结束不早于开启）。`ended_at` 取结束时刻与 `created_at` 中较晚的：单元在取正文行之前读时钟，可能早于在它之前开启的会话（M5/P1 审查 I1）。
  - 本人结束、删页、删笔记本仍删行。
- **码**：
  - 带着会话保存：先照 M4 核对本人、同一客户端、同一页，不符的照旧答 `page.edit_session_ended`（同一个码问不出会话属于谁，总体设计 13.1 第 4 条）；
  - 符合而它是墓碑：答 409 `page.edit_session_taken_over`，或 409 `page.edit_session_unlocked`。后者带 problem 的 `ended_by` 成员（第 4.5 节），C3 的"说明是谁解除的"由此而来；
  - 心跳：本人的墓碑同样答这两个 409（会话是调用者自己的，说出原因不泄露别人的什么），但先照活着的会话判定笔记本：没有角色了答 404，只能读答 403，被移出笔记本的人不从 `ended_by` 得知管理员（M5/P1 审查 m2）；不是本人的照旧答 404；
  - 结束：墓碑也答 204，并删掉它；
  - 其余情形照 M4（`page.edit_session_ended`、`page.edit_session_not_found`）。
- **编辑器的规则**：
  - 只有 `ended`、`not_found`（过期了或不见了；心跳的 404 只有这一种）才重开，而且重开不带 `take_over`：锁已被别人拿走就切为只读；重开因暂时的原因（网络、5xx）失败时下一次心跳再开（M5/P4 审查 A-I1）；
  - `taken_over`、`unlocked` 不重开，切为只读并说明（第 4.9 节）。
  - 墓碑被清理之后（一个租约加上至多一个清理间隔），一个一直没出声的旧标签页会得到 `not_found`。锁若仍空着，它就悄悄拿回。这时它已沉默两分钟以上、也没有别人在用这一页，接受。

### 4.4 锁与写入：守卫

`page.NewEditLock` 的写入守卫看每个操作算好的改动（M4 的 `Step`）：

| 操作 | 规则 |
|---|---|
| 写正文 | 这一页有活着的会话，而写入带的会话不是它：409 `page.locked`。带着持锁会话的写由 M4 的 `writersSession` 核对过本人、客户端、页与租约 |
| 删除 | 子树里任一页有**别的账户**活着的会话：409 `page.locked`，带被锁的页与持锁人（`Subtree` 按层返回，取第一个）。本人的会话随删除结束（原因 `page_deleted`），编辑器显示页面已不在（第 4.9 节） |
| 新建、改名、移动 | 放行（负责人，2026-10-03）：不碰正文 |

- **删除按账户**：负责人的决定 2 说的是"别人正在编辑"。一个崩溃的标签页留下的本人的锁，不该挡住本人的删除两分钟。删除是对树的明确操作，编辑器随之显示页面已不在，不像自动化的正文写那样悄悄撞上未保存的修改（作者的判断，负责人可以改判）。
- 时刻取 `Step.At`，与 `writersSession` 相同。
- **守卫的读是一致的**：
  - 写正文时，单元持着这一页正文行的 `FOR NO KEY UPDATE`；
  - 删除时，单元持着笔记本行的 `FOR NO KEY UPDATE`；
  - 开启会话则以 `FOR SHARE` 锁笔记本行、再以 `FOR NO KEY UPDATE` 锁正文行，在这两把锁上都要排队。
  - 所以守卫不加锁地读 `edit_sessions` 就看得到每个已提交的开启，不改总体设计 13.1 第 5 条的次序。
- **不经守卫的**：
  - 与当前正文相同的写（M4/P4 审查 Q2）：什么也不写，锁不必拒；
  - 删除笔记本、工作区：它们不是写入单元。照删，删掉会话，告诉订阅者（原因 `page_deleted`），持锁的编辑器经事件或心跳得知。
- **之后的 M**：M6 的链接改写、M8 的还原与整组撤销、M9 的写与 batch 都经守卫，页面被锁时被拒，一个单元里的一处被拒会让整个单元回滚。
  - M6 的链接改写是参与者追加的写：改名一页时，若引用它的页正被人编辑，整个改名会被拒。M6 要在"跳过被锁的页、之后补改""守卫放行改写、编辑器接收外部更新""改名被拒（要先问负责人）"之间选（[M6 的移交](../M6-links/handoffs/M5-locks.md)）。
  - M8、M9 各有一份移交（[M8](../M8-history-search/handoffs/M5-locks.md)、[M9](../M9-mcp/handoffs/M5-locks.md)）。

### 4.5 409 带持锁人：problem 的扩展成员

- 契约的 `Problem` 加两个可选成员（`api/common.yaml`、`httpserver.Problem` 与它的契约测试）。M4 把"409 附带持锁人"留给第一个需要它的 M（[M4 总设计](../M4-pages/00-M4-design.md)第 2 节）。
  - `lock: {page_id, user_id, display_name}`：只有 `page.locked` 带；
  - `ended_by: {user_id, display_name}`：只有 `page.edit_session_unlocked` 带。
- 平台照 `httpserver/apierrors.go` 现有的可选接口（`problemFields`、`retryAfter`）：领域错误实现一个"附加成员"的接口，平台把它写进 problem。名称由 identity 的目录给（`identity.NewDirectory`，notebook 已有的先例）。
- 这是总体设计 6.1"响应里关联别的资源只给 id"的又一个例外，与读锁的 `display_name` 一起写进 6.1。
- 前端的 `errorText` 给 `page.locked` 带名称的文案："某某正在编辑「页」"；是自己时说"你正在别处编辑「页」"。

### 4.6 租约改为 120 秒；后台标签页

- **为什么改**：浏览器对隐藏超过 5 分钟的标签页的链式计时器每分钟只唤醒一次（Chrome 的 intensive throttling），20 秒的心跳会变成约 60 秒一次，赶不上 60 秒的租约，锁会被别人拿走（[M4/P4 移交](handoffs/M4-P4-edit-sessions.md)第 6 项）。租约改为 120 秒，心跳仍是 20 秒，被节流时还有一倍的余量。
- **心跳同时只有一个在外**，其间要的合并成它之后的一个；一个心跳间隔没答复就放弃，不让一个挂住的请求挡住之后的心跳（M5/P4 审查 A-m3）。
- **代价**：崩溃、断网等没来得及释放的锁最多留 2 分钟。关闭标签页有主动释放（第 4.7 节），管理员也可以强制解锁。
- **重新可见时**：标签页重新可见就立刻心跳；会话已过期就按第 4.3 节重开，锁空着就拿回，被别人拿了就只读。
- **被冻结、丢弃的标签页**（Chrome 的内存节省）同样由租约兜底。
- **"某某正在编辑"怎样消失**：租约过期不是事件（M4：过期不告诉订阅者），客户端按读锁答复的 `expires_in` 再读（第 4.2 节）。持锁人的心跳不发事件，所以有人在编辑时，看着这一页的客户端约每两分钟读一次锁。
- 后端的 `EditSessionLease` 与 API、README 里的 60 秒随之改写。前端只有心跳的常量（M4/P4 的约定），不变。

### 4.7 释放：退出、关闭标签页、闲置

- **退出编辑**：照 M4，先保存再结束会话。
- **关闭标签页、刷新、离开站点**：在 `pagehide` 里同步地发出带 `keepalive` 的 `DELETE /api/v0/edit-sessions/{id}`。
  - `sendBeacon` 不能带 `Authorization`，也不能用 `DELETE`；
  - 这个请求不能经过异步的认证中间件。做法是 services 里一个专用的方法，用 `session/` 给出的、不挂认证中间件的客户端，带上令牌管理器新加的同步方法给出的、当前仍有效的访问令牌（总体设计 13.2 第 6 条）；
  - 令牌已过期就不发，由租约兜底；
  - P4 的 C6 页面版本核实请求真的到达。
- **退出登录**：先经这一代的客户端结束这一代的编辑（含还在开启的），未保存的先经编辑器悄悄保存（编辑器先只读，没有未保存的也一样），保存至多等 1.5 秒，整个退出至多等 2 秒，再登出。同一登录别的标签页的编辑同样先保存再结束：退出的标签页经频道请它们关闭，有编辑的在 100 毫秒之内答复，退出的标签页等它们关完，算在这 2 秒之内（M4–M5 Codex 评审 R1、R2；原来由租约兜底，没保存的文字随换代丢失）。不用 `keepalive`：它与登出同时在途，服务端先处理登出时结束被拒，锁留到租约过期。保存不了的（冲突、失锁、网络不通、1.5 秒内没答复，以及收到请求时主线程被占住、100 毫秒内没答复的标签页的）随退出丢失，见 [M12 的体验移交](../M12-release/handoffs/M5-polish.md)。
- **从 bfcache 回来**（`pageshow` 的 `persisted`）：先对旧会话心跳。还活着（离开时的请求没发出去，如 Safari、令牌过期）就接着用；已结束就按第 4.3 节处理。不先心跳就重开，会被自己的旧会话锁住。
- **闲置**：编辑器 30 分钟没有输入（文本没变）就自动保存、退出编辑模式、结束会话，阅读视图说明"长时间没有输入，已退出编辑"（负责人，2026-10-03）。
  - 这是前端的常量，不进配置；
  - 隐藏的标签页同样计时，计时器被节流时至多晚一分钟；
  - 服务端不判断闲置，心跳只说明标签页还开着；
  - 组合中不离开，等过组合的离开在组合结束时留下（结束组合就是输入）；正文没读到的编辑同样计时；离不开（冲突、保存失败）时不挪焦点，30 分钟后再试（M5/P5）。

### 4.8 自动保存

- **形式**：编辑器扩展管线的第一个注册者。文本停顿 2 秒之后经 `controls.save()` 保存，而 `controls.save()` 本来就等输入法组合结束（M4/P6）。保存的队列照 M4：同时一个在途，其间要保存的合并成最新的一份。
- **组合的两个边角**：
  - 编辑器在组合中被销毁时，排队的动作改为以失败结束（M4/P6 修复的核对 nt-3），不再永远等着；
  - 浏览器始终不发 `compositionend` 时（M4/P6 审查 Q4），状态栏的"未保存"照常显示，不另做提示。
- **离开时**：有未保存的修改仍先问（M4）。有了自动保存，这个窗口只剩约 2 秒。
- **冲突**：自动保存撞上冲突（失锁之后别人写过）时面板照样出现，焦点留在原处，状态栏说明；只有用户要的保存把焦点移到冲突的标题（M5/P5）。
- **测试**：
  - 自动保存是注册进去的扩展。vitest 的 `renderApp` 默认不注册，测试它的用例自己注入（`renderApp` 加编辑器扩展的参数，[M4/P6 移交](handoffs/M4-P6-editor.md)第 5 项）；
  - e2e 用实际的 2 秒。M4 数写入次数的断言里受自动保存影响的（PG7）改为等状态"已保存"与落库的结果；PG9、PG10 的不改（P5 3.9）。

### 4.9 失锁时的编辑器

- **统一的状态**：编辑器只读，正文留着可以复制，横幅说明原因，并给出"回到阅读"。
- **原因**：
  - 被接管（"你在另一处继续编辑了这一页"）；
  - 被解锁（"某某解除了你的编辑"）；
  - 页面或笔记本已不在（别的账户删不了被锁的页；剩下本人在别处删、删笔记本、删工作区）；
  - 失去访问：降为阅读者时心跳答 403。被移出笔记本或工作区时心跳与重开都答 404，与页面不在分不开（服务端以 404 隐藏它是否存在），横幅说页面已不在；
  - 会话过期而锁已被别人拿走。
- **没保存的修改**：自动保存之后至多约 2 秒，横幅写明"这里有没保存的修改"。
- **页面已不在时**：外壳留住最后的树节点，直到用户离开（[M4/P6 移交](handoffs/M4-P6-editor.md)第 6 项）；笔记本不在时同样留住最后的笔记本。没有未保存的修改时照 M4：显示 404，本标签页删的去父页。工作区不在时（被移出或被删）同样留住最后的工作区，按 id 留住：之后又有同名（同 slug）的新工作区，也等编辑结束才换过去；本标签页删除或离开的除外（M4–M5 Codex 评审 R3；P4 原来不留住）。

### 4.10 事件流：服务端

- **路由**：
  - `GET /api/v0/events`（`text/event-stream`）写进契约（新模块 events 的 `api/modules/events.yaml`），但不经代码生成（`Makefile` 的 `API_MODULES` 排除 events 整个模块）。
  - 由模块经平台导出的 `API.LongLived` 挂载（[M0/P1 移交](handoffs/M0-P1-sse-proxies.md)第 4 项）。它按"请求信息 → 认证之前的失败闸门与认证 → 按凭证的限流 → 解除期限"的次序组合；认证与限流在 `server.request_timeout` 之内，处理器不设请求期限（P2 审查 F-M2）。解除写期限放在最后，因为整体测试用 `ResponseRecorder` 调用它，在那里解除写期限会失败。
  - 契约测试与"每个操作都接受 PAT"的测试，对标了 `x-long-lived` 的操作只看答复头，不读到结束。
- **认证**：
  - 访问令牌与 PAT 都接受（总体设计 12.5：PAT 能做的完整）；
  - 平台的认证结果带凭证的到期时刻（identity 现在丢掉了它）。流在到期时以 `reset`（原因 `expired`）结束；
  - 每次心跳重新认证一次这个凭证（不经失败闸门：凭证已经认证过一次）。撤销、退出登录、停用都在一个心跳之内关闭流，不为它们另建扩展点。本标签页退出登录时，前端自己立刻关流。
- **心跳**：`events.heartbeat_interval`，默认 20 秒，配置校验限在 5–50 秒之间（要短于 nginx `proxy_read_timeout` 默认的 60 秒）。流的第一帧 `hello` 把间隔告诉客户端，前端的阈值都由它推出，不另写死（总体设计 13.1 第 15 条）。
- **新模块 events**（没有表）：
  - 流的路由与连接的登记（hub）；
  - 可见的笔记本：workspace 与 notebook 的模块根各导出一个只读端口（所在的工作区与角色、一个工作区里看得到的笔记本），组合根接线。照总体设计 13.1 第 3 条，加"列表的结果等于逐项判定"的测试；
  - 发出 NOTIFY；
  - 扩展点的注册者（第 8 节）；
  - 流只要认证，不加动作、不进规则表：事件按可见性过滤，没有资源的判定；规则表也没有"任何登录的账户"一级（P2 文档 3.12）。权限矩阵整模块豁免。
- **连接的建立**：先在 hub 登记，再计算可见集合。计算期间收到的事件先排着（至多 1024 条）；其中有涉及本账户或这些工作区的 `access`、`notebooks_deleted`，就直接 `reset`。先算后登记会有一个窗口：可见性在两步之间变化，这条连接就带着旧的集合活下去。计算受 `server.request_timeout` 约束。
- **NOTIFY**：平台的 `postgres.Notify(ctx, channel, payload)` 在调用方的事务里执行 `pg_notify(channel, payload)`，events 用 `nwiki_events`。
  - 载荷只带 id（JSON），总长受 8000 字节限制，超出时退化为整体刷新（见下表）；
  - 通道名不与 River 的（`river_insert`、`river_leadership` 一类）冲突；
  - 同一事务里载荷相同的通知会被 PostgreSQL 合并，所以每条通知的载荷要带区分它的内容：例如接管时的"结束"与"开启"带各自的会话 id。
- **每个事务可以有几条**：总体设计 3.11 原来写"每个事务最多发一条"，理由是带 NOTIFY 的提交在全局的锁上串行。
  - PostgreSQL 在提交时，为有待发通知的事务取一次这把锁（PG 13–18 的 `async.c` 的 `PreCommit_Notify`：`LockSharedObject(DatabaseRelationId, …, AccessExclusiveLock)`，持到提交结束），与一个事务里发几条无关。条数只影响写队列的临界区长短；
  - 所以 M5 允许一个事务发几条（接管时一条结束、一条开启，停用跨几个工作区），不做事务内的合并，修订 3.11；
  - 这把锁只在 `COMMIT` 内部持有，测不出取锁的次数。P2 的文档引用 PG 18 的源码（测试固定在 18.6），风险表写"升级 PostgreSQL 大版本时复核"。
- **事件**：

  | 事件 | 来源 | 带什么 | 客户端做什么 |
  |---|---|---|---|
  | `hello` | 连接建立 | 心跳间隔 | 推出各个阈值 |
  | `pages` | 页面领域事件的观察者，一个写入单元一次 | 笔记本 id；`tree`（是否改了树）；`pages`：写了正文的页与新的 `revision`，多于 20 页时是 `null` | `tree` 为真就重读这本笔记本的树；正文：当前缓存的阅读视图 `revision` 小于它就重读；`null` 时当作当前页也变了 |
  | `lock` | 会话的订阅者：开启、结束、接管、解锁 | 笔记本 id、页 id | 重读这一页的锁 |
  | `reset` | 可见性变化、笔记本删除、凭证到期、心跳时重新认证失败、LISTEN 连接重连、连接的缓冲满了 | 原因 | 服务端随即关闭；客户端立刻重连并整体刷新。流的最后一帧；可见性、删除、重连与缓冲满了的，写在缓冲里已有的事件之后 |

  - 心跳：每个间隔一行注释；`X-Accel-Buffering: no`，`Cache-Control: no-store`。
  - 每一帧在一个心跳之内写出：停止读取的客户端（冻结的标签页）不占住处理器（P2 审查 A-I1）。流也会不带 `reset` 就结束（停机、心跳时认证服务出错、写超时），客户端同样重连并刷新。
  - 别的 M 加自己的事件类型（第 8 节）：载荷带笔记本 id 的按笔记本过滤，带工作区 id 的按工作区。
- **可见性与删除**：
  - 可见性变化事件（M3）的订阅者发 `{access, workspace_id, user_ids, reached}`。hub 对 `user_ids` 里的账户，以及 `reached` 时这个工作区里的所有连接，发 `reset` 并关闭（总体设计 3.11"立即关闭，重连时重新计算"）；
  - `user_ids` 超出载荷时整个工作区一起关闭；
  - 笔记本删除事件的订阅者发 `{notebooks_deleted, workspace_id, notebook_ids}`，对看得到它们的连接发 `reset`；超出载荷时整个工作区一起。
  - 代价：在开放的笔记本里新建一本时，这个工作区的流都重连一次。团队规模下可以接受，换来的是不在连接上维护会过期的可见集合。
- **hub**：
  - 每个进程一个；
  - 平台的 `postgres.Listener` 占一条专用连接。照 River 的做法从池里取出再 `Hijack`，不占 `database.max_conns`；安静 30 秒就 `Ping`，悄悄断掉的连接由此发现（P2 审查 A-m2）；断开之后按退避重连，重连之后向所有连接发 `reset`；
  - LISTEN 还没生效时（启动中、重连中），流答 503 `not_ready`（带 `Retry-After`），不让一条连接漏掉它订阅之前的事件；
  - 每个连接一个有界的缓冲（64 条），满了就 `reset` 并关闭：慢的客户端不拖住别人，也不悄悄丢事件；
  - 启动：Listener 在 HTTP 开始服务之前启动；
  - 停机的次序：HTTP（`LongLived` 的 context 在停机开始时取消）→ Listener → 后台任务 → 连接池。
- **多实例**：每个进程各自 LISTEN（总体设计 3.11）。v0.1 只验证单实例。

### 4.11 事件流：前端

- **一个浏览器一条流**：每一代（`loginId`）一个 `EventHub`，登录之后由 `RootStore` 建，换代时中止它的请求、放掉锁、关闭频道。它只经 service 调用接口：流的读取不受总体设计 9.4"答复头到达时核对换代"的保护，换代时要自己中止。
- **选持有者**：同一账户的标签页选一个持有连接：
  - 有 Web Locks 时用锁 `nwiki.events.<loginId>`；
  - 非安全上下文用 localStorage 里带续期的租约，这是新写的部件。持有者每收到一帧（事件或心跳）就续期：网络任务不受计时器节流，后台的持有者照样续得上；过期取心跳间隔的 3 倍。抢占时写入、等待、读回。M1 的 `leaseLock` 是一次性的短锁，不能直接用。
- **转发与存活**：持有者把事件、服务端的心跳，以及自己的状态（"正在重连"）经 `BroadcastChannel("nwiki.events")`（消息带 `loginId`）发给别的标签页。持有者自己的连接 3 个心跳间隔没有一帧就放弃、重连：只有一个标签页时，断网留下的半开连接没有跟随者来接手。
- **换持有者**：
  - 持有者在 `pagehide`、`freeze` 时让出（租约立刻删键）；`pageshow`、`resume` 时重新加入，沉默从这时算起；
  - 看得见的标签页在心跳间隔的 3 倍之内没听到持有者的任何消息（事件、心跳或"正在重连"），就以 `steal` 抢过 Web Lock：被冻结的持有者不放锁（Nerve 的 `refresh-lock.ts` 记下过这一点）。持有者在重连时照样报"正在重连"，服务端重启或断网时两个可见的窗口不会互相抢。
- **连接**：
  - 经这一代的接口客户端（`parseAs: "stream"`、`AbortSignal`），401 时续期一次；
  - 服务端的 `reset` 或断线之后立刻重连，失败时退避，上限 30 秒；
  - 连上之后整体刷新，由外向内一层一层：工作区的列表、笔记本的列表、已加载的页面树、当前页的阅读视图与锁；看不到了的先离开，里面的不读成 404。
- **收到事件**：
  - 页面树：已加载的那本笔记本的树重读（`PageTreeStore.load`，照 M4 的重叠规则）；
  - 正文：当前缓存的阅读视图 `revision` 小于事件的（或第一次读还在外）就重读。SWR 的 `mutate` 保留旧的直到新的到，不闪成"加载中"；
  - 正文的重读要合并：有人编辑时每次自动保存都发事件，看着这一页的每个标签页若都立刻重读，服务端每 2 秒要为每个读者重新解析一次。可见的标签页每 5 秒至多重读一次（取最后一次），隐藏的等到重新可见再读；
  - 锁：先重读这本笔记本的树，再重读这一页的锁（删除正在编辑的页时 `lock` 先到）；
  - 正在编辑一页的标签页不处理这一页的正文事件：持锁期间只有自己的保存。
- **接线**：`<EventStream/>` 组件放在 `AppProviders` 里，把 hub 的事件接到这一代的 SWR（`useSWRConfig().mutate`）与 store。全局的 `mutate` 碰不到按代的缓存。
- **目录**：新目录 `src/events/` 放解析、hub 与选举，`.oxlintrc.json` 给它一条目录规则（只导入 services 的类型与 `session/` 的 `SessionChangedError`，不导入页面与 store）。

### 4.12 任务项

- **服务端**：基础的解析已经有 goldmark 的任务项解析器与渲染器（`harden/parser.go` 与 `render.go` 注册的），它们的节点不带位置。M5 在 `platform/markdown` 里用自己的任务项扩展替换它们，在 `markdownExtensions()` 里组合，放在 `platform/markdown` 之下，不必改架构规则。
  - `Extract` 按正文的次序给出每个任务项标记 `[ ]`、`[x]` 里那个字符的字节位置（goldmark 把脚注定义挪到文档最后，树的次序不是正文的）。位置按正文的字节计：frontmatter 原地替换为空白，位置不变；
  - 渲染器给复选框加 `data-task="<位置>"`，登记进 `Markup`，`CheckHTML` 与样例集（`tasks` 字段）随之更新；
  - 位置是 UTF-8 字节，前端原样传回，不换算。
- **勾选**：`POST /api/v0/pages/{page_id}/toggle-task`，请求体 `{base_revision, offset, checked}`。码的次序：
  1. 判定（不加锁的同一判定，404、403），与写正文相同。
  2. 读出正文。`base_revision` 不是当前版本时答 409 `page.revision_mismatch`。
  3. 取解析预算（503），解析，确认 `offset` 是一个任务项的标记，否则答 422（`offset`，`out_of_range`）。409 排在 422 之前是总体设计 13.1 第 4 条的例外：位置只在它所依据的版本里有意义。
  4. 已经是那个状态时答 200，不写；其间有人写过（读到的页已不在 base 上）答 409 `page.revision_mismatch`。这一步在守卫之前，与写入相同的正文一样（4.4）。
  5. 把标记里的字符换成 `x` 或空格，其余字节不变；新正文在那个位置上没有那个状态的任务项（`- [ ]: /u` 勾上之后成了链接引用定义）答 422（`offset`，`not_allowed`），不写。经写入单元写正文，守卫在：有人持锁答 409 `page.locked`。答复带新的 `revision`。
- **前端**：
  - 阅读视图的增强，交互增强里第一个会写入的；
  - 能写的人的复选框可用，各以它那一项的可见文字为名称；
  - `ReadingContext` 加 `toggleTask(offset, checked)`（只给能写的人）与 `report(error)`，因为增强渲染不了 React；勾选的拒绝照"编辑"被拒那样说，锁的拒绝由锁的说明说是谁；
  - 同一页同时一个在途，由页面树 store 按页把住（跨视图；在外超过一分钟的不再挡住）；答复之后重读阅读视图，焦点回到同一位置的复选框，只在它仍是同一项时（文字相同，状态相同或是视图自己刚改的），不滚动。

### 4.13 编辑的前端

- **先拆出会话**（[M4/P6 移交](handoffs/M4-P6-editor.md)第 8 项）：`stores/edit-session.ts` 的 `EditSession` 管开启、心跳、可见时心跳、结束、`keepalive` 的释放、从 bfcache 回来，以及会话为什么结束。`PageEditing` 持有它，只管正文、保存的队列与冲突。
- **进入编辑**：先开会话、拿锁，拿到了才读正文、挂编辑器；被别人锁着就停在阅读视图，显示持锁人，自己在别处就给"在这里编辑"。M4 的"读正文与开会话同时进行，开会话失败照样编辑"随之改掉。
- **编辑器的控制**：加 `leave()`（闲置退出用）与会话的状态（只读的原因），`EditorContext` 不变。
- **两个编辑器扩展**：自动保存（第 4.8 节），以及失锁时只读（第 4.9 节，经 `controls.setReadOnly`）。
- **冲突**：持锁时别人写不进来，冲突只在失锁（过期）之后、别人写过时出现，照 M4 的差异对比处理。

## 6. 从 Nerve 借鉴

Nerve 没有实时推送、编辑锁与自动保存：它的 v0 去掉了 Plane 的协作服务。借鉴的是周边的部件：

- **LISTEN 的连接**：照 River 的 notifier。从池里取出再 `Hijack`；一个协程阻塞在 `WaitForNotification` 上，定时打断去 `Ping`；断开之后按退避重连；缓冲满了丢弃并告警。M5 改为 `reset`，因为没有轮询兜底。
- **跨标签页**：锁与租约的写法（`refresh-lock.ts`），以及"被冻结的标签页不放 Web Lock"这一条；测试替身（`fake-browser.ts` 的 `SharedStorage`、`RecordingLock`），每个标签页的测试在 Web Locks 与租约两种下各跑一遍；e2e 删掉 `navigator.locks` 走租约。
- **令牌**：令牌的取用与续期。e2e 用短的访问令牌测到期重连。

  - M5 用测试替身证明一个新类型从发布到前端的处理表走得通。
- **problem 的扩展成员**：领域错误经可选接口给 problem 加成员。M5 有 `lock` 与 `ended_by`，之后的 M 照这个形状加，每加一个就改契约。

## 9. 测试策略

- **交错**（总体设计 13.4 第 4 条）：45 起。
  - 两个开启（两种先后）：第二个答 `page.locked`；
  - 接管与旧会话的保存：保存要么先完成，要么答 `taken_over`，不会写进新会话的变更集；
  - 强制解锁与保存：同上，答 `unlocked`；
  - 心跳与接管、心跳与强制解锁：心跳在行锁上等到之后，不把墓碑续成活的；
  - 晚到的心跳与开启：开启先删掉过期的行，心跳答 `not_found`；
  - 别人的删除与开启：删除先持笔记本行，开启答 `page.not_found`；开启先，删除答 `page.locked`；
  - 不带会话的写与开启：写先提交时正文改了，开启照常；开启先时写答 `page.locked`。
  - 交错 42（M4 的两个开启）的两个子测试改为第二个答 `page.locked`。
- **锁的时刻**：注入的时钟推到租约的边界前后各一次（119、120 秒），墓碑的保留同样。
- **事件流**：
  - hub 的单元测试用假的 Listener 与连接；
  - Listener 用测试数据库：`pg_terminate_backend` 断开它的连接，看到重连与 `reset`；
  - 流的处理器用 `httptest` 的真实服务与假时钟：心跳、到期、撤销；
  - 每条触发路径的行为测试在整个程序上开一条流，做写，读到事件（或 `reset`）。
- **前端**：
  - 流用 `ReadableStream` 的假答复，测试持有控制器，自己推帧、关闭；
  - `BroadcastChannel` 与锁由依赖注入；
  - 跨标签页的测试在 Web Locks 与租约两种下各跑一遍（照 Nerve）。
- **端到端**：
  - 另一账户的标签页用 `anotherPage(tokens)`；同一账户的第二个标签页用同一个浏览器上下文的新页，加一个受监视的夹具；
  - 流与锁的 4xx 在 `expectConsole` 里声明；
  - 不用 `networkidle`：流永远不空闲；
  - 短的访问令牌用 `nervewikiWith`。
- **权限矩阵**：`getEditLock`、`releaseEditLock`、`toggleTask` 用笔记本级的列；`streamEvents` 整模块豁免（按可见性过滤，没有资源的判定），不进规则表。

## 10. 风险

| 风险 | 应对 |
|---|---|
| "一个事务几条 NOTIFY 只取一次全局锁"依据的是 PG 13–18 的源码 | 论证见 4.10（PG 18 的 `async.c` 的 `PreCommit_Notify`）；升级 PostgreSQL 大版本时复核（[M12 的移交](../M12-release/handoffs/M5-performance.md)第 5 项） |
| `pagehide` 里带 `keepalive` 的请求在某些浏览器上发不出去（Safari） | 租约兜底，最多 2 分钟；从 bfcache 回来先心跳；人工清单里记一笔 |
| 被冻结的持有者与 `steal` 的行为在 Safari、Firefox 上没有自动验证 | 人工清单里加多标签页的一步；最坏是隐藏的标签页收不到事件，重新可见时持有者重连并刷新 |
| `reached` 的可见性变化让整个工作区的流一起重连 | 团队规模下可以接受；M12 的压测看重连与刷新的代价 |
| 访问令牌每 15 分钟到期，每个浏览器重连一次并整体刷新，阅读视图要重新解析 | 一个浏览器一条流、一页一次解析，团队规模下可以接受；M12 的压测一并看 |
| 阅读视图更新时整个替换 HTML：代码高亮闪一下，焦点丢失 | 任务复选框的焦点回到同一位置上的同一项（文字与状态相同），不滚动；其余随 v0.1 收官之后的统一打磨 |
| M6、M8、M9 的写碰上被锁的页 | 各写一份移交（第 4.4 节） |
