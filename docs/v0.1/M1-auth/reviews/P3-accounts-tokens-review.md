## 发现与处置

| # | 级别 | 发现 | 处置 |
|---|---|---|---|
| M1 | Minor | 交错一守不住账户行锁：让 `CredentialLock` 换成不加锁的读取，交错一、交错三照样通过。改密码的 `UPDATE users` 本身就等登录持有的锁，READ COMMITTED 下随后的撤销又看得见登录刚建的会话。显式锁真正防的是两个并发改密码的丢失更新（审查者的探针：去掉锁之后两个都答 204，后者的哈希覆盖前者，而它的当前密码是对旧哈希校验的），没有测试 | 加交错四：两个改密码，后者用 PAT（不被前者撤销）；前者持锁停在撤销之前，后者等锁，放行之后后者发现哈希变了、当前密码对新哈希不成立，答 422，哈希是前者的。<br>交错一的注释与设计 3.9 改为它守的是"改密码撤销的范围包括登录刚建的会话"。<br>反向对照：只让改密码与创建 PAT 的锁换成不加锁的读取（登录照旧加锁），交错四失败（哈希是后者的），交错一通过 |
| M2 | Minor | `password_user` 的"按账户"没有测试守住：测试的假认证永远给同一个会话，键改成凭证之后全部测试通过。回归之后，持有多个凭证的人按凭证数倍增猜密码的次数 | 假认证另认得同一账户的 PAT 与另一个账户的会话；限流测试依次用会话、PAT、会话创建令牌，第三次答 429，另一个账户照常。<br>反向对照：键改成凭证，测试失败 |
| M3 | Minor | 名称放过行分隔符与双向控制字符：`unicode.IsControl` 只覆盖 Cc，U+2028、U+2029 与 U+202E（RLO）、U+2066–2069 都能写入。M2 把显示名展示给工作区的其他成员，RLO 可以把名字倒着显示冒充别人。注释说"会让显示或日志断行"，而名字从不进日志 | `CheckName` 另拒绝 Zl、Zp 与 `Bidi_Control`（U+061C、U+200E/F、U+202A–202E、U+2066–2069），错误码不变；连接符（ZWJ、ZWNJ）保留：emoji 序列与波斯文等需要它们。同形字不在服务端的职责之内。注释改为说明拒绝的理由。<br>测试：六个新的拒绝用例，emoji 序列与波斯文单词通过。反向对照：只挡 Cc，六个用例失败 |
| N1 | Nit | 失败的 PAT 消耗失败闸门，只有桩测试守住：把 authn 改成凡是 `nwk_pat_` 的失败都退还名额，全部测试通过 | A14 的闸门故事用一个已撤销的 PAT 作为两次失败之一。反向对照：失败的 PAT 退还名额，A14 失败 |
| N2 | Nit | "尽力而为"的 `last_used_at` 写入会等行锁：另一个事务持有 PAT 的行时，认证被拖了 5 秒（与 Nerve 相同） | 条件更新改为 `WHERE id = (SELECT … FOR NO KEY UPDATE SKIP LOCKED)`：被持有的行跳过，下一次使用再写。仓储测试：持有行时 2 秒期限内返回、不写，放开之后写入。反向对照：去掉 `SKIP LOCKED`，测试以期限超时失败 |
| N3 | Nit | 持锁测试的握手 `<-holding` 没有期限：第一个事务在持锁之前出错时测试挂到 go test 超时 | 仓储测试加 `awaitHolding`：持锁、事务先结束、超时三者择一，后两者立即失败。实测让 `ShareAccount` 出错，1.1 秒失败 |
| N4 | Nit | `password_user` 的 429 日志只有 IP，运维看不出哪个账户正被猜密码；README 没提这个桶的日志 | 模块的桶拒绝时，调用方已登录就另记 `user_id`；限流测试断言它。README 补上 |
| N5 | Nit | "停用一个会话也不保留"的单元测试只用 PAT 身份调用，SessionID 本来就是空 | 顺序测试对会话与 PAT 两种身份各跑一次 |
| N6 | Nit | 组合根里停用的锁经 `password.Lock` 取得：停用不依赖当前密码，是隐性耦合；`New` 约 95 行，P4 还要加用例 | 先构造 `lock`，分别交给当前密码与停用。用例装配的辅助函数留到 P4 加管理用例时（写进 P4 的设计） |

审查者另记两点，不列为发现：
- `ShareActiveAccount` 在事务之外调用时锁随语句结束，只有注释提醒。M2 的增长路径是否检查上下文中有事务，由 M2 取舍（写进 M1→M2 的移交）。
- 引导步骤的 CHECK 违反一律译成"至多 32 步"：领域的正则与 CHECK 若不一致，格式错误会被报成数量超限。两者现在一致，领域先检查格式；设计 3.5 写明这一前提。

## 对有意决定的判断

| 决定 | 判断 |
|---|---|
| PAT 格式 `nwk_pat_` 加 32 字节 base64url；存整个令牌的 SHA-256，不用慢哈希；严格解析，不查库 | 同意 |
| 撤销是软删除，"已撤销"只进调试日志；列表用部分索引 | 同意 |
| 期限按 UTC、微秒截断之后比较与存储 | 同意（实测带偏移、纳秒的输入与库、列表一致） |
| 创建 PAT 要求当前密码，任何凭证都可以，包括 PAT | 同意；配合 `password_user` |
| 列表不分页、不设个数上限，已过期的也列出 | 同意：要密码且限速，规模由用户自己决定；日后可考虑软上限 |
| 撤销是一条条件更新；不存在、已撤销、别人的都答 404 | 同意 |
| `last_used_at` 每分钟至多写一次，失败只记 warn，不改 `updated_at` | 部分同意：写入会等行锁（N2，已修复） |
| 过期的 PAT 不退还失败闸门的名额 | 同意；测试缺口见 N1（已补） |
| `CredentialLock`：第一条语句锁账户行，锁下复核凭证；全局加锁顺序 `users → auth_sessions → api_tokens` | 同意（22 轮并发探针的不变量全部成立）；测试缺口见 M1（已补） |
| `CurrentPassword`：事务外按快照校验、准备只做一次、锁下比较、至多再试一次、答 422 而非 401 | 同意（交错三也抓得住快照比较的缺失，补上了 P2 审查 N4 的缺口） |
| 登录与 `CurrentPassword` 的循环各自保留 | 同意：登录没有调用方的凭证可复核，还有哑哈希的分支 |
| `password_user` 按账户，HTTP 适配器每个请求取一个单位 | 同意；测试缺口见 M2（已补） |
| `updateMe` 空补丁不写库；`recordOnboardingStep` 一条语句，个数由 CHECK 裁决 | 同意（40 个并发中恰好 32 个成功；同一步骤并发只存一个） |
| 改密码：会话调用保留本会话，PAT 调用撤销全部，PAT 不受影响 | 同意 |
| `RevokeReason` 类型与批量撤销；续期、退出仍在 SQL 中写原因 | 同意 |
| 停用不要求密码；一个事务：锁 → 否决者 → 写入 → 订阅者 | 同意：可由管理员恢复，被盗令牌的持有者也随之出局 |
| 注册者只凭连接池构造；类型在 `app`，模块根以别名公开；M2 经 bootstrap 适配 | 同意 |
| 不变量：停用撤销全部会话，续期不读 `is_active`（P2 审查 N3） | 同意（SQL 重新启用之后旧会话仍答 401） |
| `ShareActiveAccount` 用 `FOR SHARE`，答 403 或 404 | 同意（比 Nerve 返回三元组由调用方判断的端口更窄） |
| runtime 的例外按导入者判断；参数用例加"至少一个"的守卫 | 同意 |
| 偏差：新增"会话在途结束"的测试 | 同意：不复核时交错二答 422 而非 401，真正插入令牌的是这个测试；设计第 5 节第 1 项改写 |
| 偏差：`CreateAPIToken` 的仓储查询在 S1 加入 | 同意：S1 的认证测试要用它插入令牌 |
| 偏差：持锁测试的释放等待都有期限 | 部分同意：握手 `<-holding` 仍没有期限（N3，已修复） |
| 偏差：引导步骤的 CHECK 违反映射为 `ErrTooManyOnboardingSteps` | 同意：领域保证格式，CHECK 负责并发下的计数 |
| 偏差：停用的拒绝也记日志（带码） | 同意：否决是有业务意义的事件；401 不记是对的 |
| 偏差：注册与改密码共用一个 `NewPasswordRules()` | 同意：每次构造都要切分名单，而规则不可变 |

## 文档与代码的不一致

2. 设计第 5 节第 2 项与 3.9"交错一守住账户行锁"：改为交错四（M1）。
3. 设计 3.1 的文件：`FOR SHARE` 的交错在 `deactivate_test.go`；名称的规则在新文件 `domain/name.go`；`domain/errors.go` 另有 `ErrTooManyOnboardingSteps`。已补。
4. 设计的状态"未开始"：改为已完成。
5. 设计 3.4"每次尝试先取一个单位"：改为每个请求在 HTTP 层取一个单位，先于任何校验，答 422 的也计数。
6. 设计 3.9 把"写失败时仍然通过"列在集成测试下：它由用例的单元测试守住，已改。
7. M1 总设计第 8 节写 `AccountDeactivated{…}` 事件与 `VetoDeactivation(ctx, account)`：改为同一个 `Deactivation{UserID, Email, At}` 值交给否决者 `VetoDeactivation(ctx, d)` 与订阅者 `AccountDeactivated(ctx, d)`。
8. README 的桶日志没提 `password_user`：已补（N4）。
9. `domain/name.go` 的注释：已改（M3）。
10. M0/P4 移交第 4 项的进展与设计第 7 节：已补。
