## 1. 目标

M4 结束时：

1. **节点树**：笔记本的编辑者与管理员新建页面、改标题、移动与排序、删除整棵子树；阅读者只读。标题遵守 `shared.CheckTitle`，同一父页下按标题键（`NFC(fold(NFC(s)))`）唯一；层级不超过 10；路径由祖先推算。
2. **正文**：原样的 Markdown，逐字节保存（换行风格、BOM 都不变），读写带 `revision`，写入带 `base_revision`，不一致答 409。
3. **变更集与版本**：从第一次树操作起，每次写入都属于一个变更集，记执行者与客户端；树操作记前后的父页、标题与次序，正文每个变更集每页一个版本。
4. **编辑会话**：进入编辑模式开启会话，会话有租约与心跳；一次会话是一个变更集，其中的多次保存只更新同一个版本。
5. **阅读视图**：唯一的解析入口 `Parse`（frontmatter 先替换为空白），服务端渲染 CommonMark + GFM、frontmatter 的属性表，代码块带语言、由前端高亮；用户写的原始 HTML 严格清洗；渲染的耗时预算与耗时模糊测试。
6. **前端**：页面树侧栏（拖拽移动与排序，另有"移动到…"）、面包屑、子页面列表、快速切换（`Ctrl+O`）、阅读视图、源码编辑器（高亮、快捷键、列表续行、查找替换、`Ctrl+S` 保存、冲突时的差异对比）。
7. **扩展点**（总体设计 12.4）：
   - 建立：页面领域事件与写入单元的参与者、写入守卫、编辑会话、变更集的客户端字段、Markdown 解析与渲染扩展、阅读视图的交互增强、编辑器扩展管线。
   - 注册 M2、M3 建立的：笔记本删除事件（软删除节点与跟随的行）、清理注册表（页面的表，含自引用的父指针）、笔记本的活动（正文的字节数与最后写入）、权限规则表（页面的操作）。
8. **移交**：M0/P1、M2/P4、M3/P1、M3 的四份移交，每项落实或说明理由（第 7 节）。

## 2. 范围

**做**：第 1 节各项，以及它们的接口描述、页面与端到端故事。

**不做**：

| 事项 | 理由与去处 |
|---|---|
| 编辑锁（会话的排他）、强制解锁、"XX 正在编辑"、beacon 释放、自动保存、实时推送 | M5。M4 的会话彼此不排他，并发的保存由 `base_revision` 判出冲突；M4 只有 `Ctrl+S` 与离开编辑模式时的保存，未保存就离开时提醒 |
| wikilink、标签、callout 等 Obsidian 方言，链接索引、改写与跳转，KaTeX、mermaid，大纲与反链 | M6。M4 的 `Parse` 只有 CommonMark + GFM、脚注与 frontmatter；`[[…]]` 按普通文字显示 |
| 附件节点、附件面板、`![[…]]` 嵌入 | M7。节点的 `kind` 列从 M4 起就有，M4 只有 `page`；相对地址的图片在 M7 之前渲染为链接 |
| 版本列表、diff、还原、撤销、回收站、全文搜索与三元组索引 | M8。M4 只记录变更集与版本；删除之后到 M8 之前，页面上没有恢复的入口（运维可以从数据库恢复）。三元组索引随搜索在 M8 加（M8 的 CJK 搜索移交可能改变做法） |
| 跨笔记本移动页面 | v0.1 不做（负责人确认，2026-10-02）：链接只在笔记本内解析，权限、历史与变更集都按笔记本；需要时导出再导入（M7） |
| 右栏（大纲、反链、属性、页面信息） | M6、M8。M4 的属性表在阅读视图的正文之上 |
| MCP 的写入与路径寻址、自动补建父页面、batch | M9（写入单元已为 batch 留好形状，第 4 节） |
| problem 的扩展成员（如 409 附带当前版本、持锁人） | 第一个需要它的 M5 设计（平台、契约、前端一次做完）。M4 的冲突由客户端重新读取正文得到当前版本：差异对比本来就要读 |

## 3. 完成标准

- 本 M 的故事全部通过（本地 `make e2e` 与持续集成），之前各 M 的故事仍然通过：

  | 故事 | 内容 | 版本 |
  |---|---|---|
  | PG1 新建页面 | 编辑者在根下与某页下新建页面；网页的默认标题是界面语言的"未命名"，重名时加序号；阅读者没有入口，接口答 403。落库：节点、空正文（版本 1）、变更集（客户端 `web` 或 `api`）、条目与正文版本 | 页面、PAT 接口 |
  | PG2 标题与改名 | 改名；不合规则答 422；同一父页下标题键相同答 409 `page.title_taken`（`Straße` 与 `STRASSE`、NFC 与 NFD）；改名不改正文。落库：条目的前后标题 | 页面、PAT 接口 |
  | PG3 移动与排序 | 拖拽排序与换父页，"移动到…"；移进自己的子树答 409 `page.cycle`，超过 10 层答 409 `page.too_deep`。落库：条目的前后父页与次序 | 页面、PAT 接口 |
  | PG4 删除子树 | 删除页面连同全部子页面（确认对话框写明子页面数），之后谁都看不到。落库：子树的节点与跟随它们的行以同一时刻软删除，它们的编辑会话被删除 | 页面、PAT 接口 |
  | PG5 阅读视图 | 表格、任务列表、删除线、自动链接、脚注、代码块的语言（页面上高亮）、frontmatter 的属性表；frontmatter 不被渲染成分隔线或标题；HTML 带所依据的 `revision` | 页面、PAT 接口 |
  | PG6 渲染安全 | 正文里的 `<script>`、事件属性、`style`、`javascript:` 与 `//外站` 的链接、原始 HTML 的 `<img>` 都不出现在 HTML 里，没闭合的行内标签不越出所在的块；页面不执行任何脚本，没有 CSP 违规；外部图片显示为链接、不发出请求 | 页面、PAT 接口 |
  | PG7 编辑与保存 | `Ctrl+E` 进入编辑，`Ctrl+S` 保存，回到阅读视图看到新内容；同一次会话的两次保存只有一个变更集、一个正文版本。落库：`revision`、`content_hash`、`byte_size` | 页面、PAT 接口 |
  | PG8 保存冲突 | 编辑期间别人（PAT）先写了：保存答 409 `page.revision_mismatch`，编辑器读出当前正文、给出差异，可以保留自己的（覆盖）或放弃。落库 | 页面、PAT 接口 |
  | PG9 字节保真 | CRLF、只用 `\r`、混合的换行、BOM、行尾空白、NFD 的文字，经编辑器在行尾、行首、BOM 之后改动之后，其余字节不变 | 页面、PAT 接口 |
  | PG10 编辑会话 | 心跳维持会话；离开编辑模式结束会话；租约过期的会话写入答 409 `page.edit_session_ended`，编辑器开启新会话后保存成功，没有丢字 | 页面、PAT 接口 |
  | PG11 导航 | 页面树、面包屑、子页面列表、`Ctrl+O` 快速切换；接口版本核对 `GET /pages/{id}` 的祖先链 | 页面、PAT 接口 |
  | PG12 页面的权限 | 阅读者只读（页面上没有编辑、新建、移动、删除的入口，接口答 403）；看不到笔记本的人答 404；经 `workspace_access = editor` 得到编辑者的成员可以写 | 页面、PAT 接口 |
  | PG13 删除笔记本连带页面 | 删除笔记本、删除工作区、删除无主笔记本都以笔记本的删除时刻软删除它的页面；保留期之后清理任务一次运行就物理删除，多层子树也清完，任务没有错误 | 页面、PAT 接口、后台任务 |
  | PG14 笔记本的活动 | 无主清单的大小是页面正文的字节数之和，最后更新是最晚的页面写入 | 页面、PAT 接口 |

- **对等验收的例外**（总体设计 10.1）：PG13 的清理只由后台任务完成，只有那一个版本。
- **人工验收**：真实输入法在 Chromium、Safari、Firefox 上的验证清单（第 7 节 M0/P1 移交第 1 项）在 P6 完成时由负责人执行通过，结果写进 P6 的审查记录（负责人确认，2026-10-02）。
- 本 M 建立的扩展点已建好，并有测试证明注册者能挂上去（第 8 节）；本 M 注册的扩展点，经每条触发路径各有整个程序上的行为测试（M3/P1 移交、M3 移交第 5 项）。
- 权限矩阵覆盖每个新操作，用 M3 的笔记本级的列（第 9 节）。
- 满足总体设计 12.5 的其余各项；四份移交全部处理（第 7 节）。

## 4. 关键决定

| 决定 | 选择 | 放弃的方案及原因 |
|---|---|---|
| 模块 | 新模块 `page`：节点树、正文、变更集与版本、编辑会话。它经端口读笔记本（所属的工作区、锁住笔记本行）与工作区（锁住工作区行），由组合根接上；判定经 `shared.Authorizer` 的笔记本级。Markdown 的解析与渲染在平台包 `platform/markdown`（goldmark、`x/net/html`、YAML 库都是第三方库，`domain`、`app` 只用标准库，13.1 第 12 条），页面的 `app` 经端口使用 | 解析放进 page 的 `domain`：违反依赖规则；放进 M6 的 linking 模块：M4 还没有它，而渲染是 M4 的 |
| 写入单元 | 页面的一次写是 `page/app` 里的一个写入单元。开始时定下笔记本、执行者、客户端、写入选项、变更集的作用域（单次写入新建一个；会话用会话的；M9 的 batch 与 M7 的导入一个单元多个操作）与锁模式（含树操作的单元从一开始就取笔记本行的 `FOR NO KEY UPDATE`，不在事务里升级），然后加锁、判定。单元里的每个操作经校验、守卫、写入，记条目与版本，累积进单元的改动集。参与者（M6 的链接改写）在操作之后经单元追加正文写，同样经守卫、加 `revision`、记进同一变更集、并进改动集；改写页的解析结果由参与者给出。单元结束时把整个改动集作为一次页面领域事件交给观察者（M5 的 `NOTIFY`、M6 的索引），然后提交。在 `FOR SHARE` 下写多页正文的，按节点 id 升序锁正文行。写入选项在 M4 只有 `update_links`（网页与 REST 恒为真，M9 的 MCP 可以关，4.5 第 4 条）。M4 的用例都是一个操作的单元；测试替身证明一个参与者与一个两操作的单元挂得上 | 以用例为单位的管线：M6 的改写、M7 的导入、M9 的 batch 只能改 M4 的用例，或得到 N 个变更集与 N 次事件；同一事务里先正文写、后树写是锁升级，两个 batch 之间会死锁 |
| 加锁 | 页面的写先以 `FOR SHARE` 锁工作区行（`Workspaces.ShareByID`），再锁笔记本行，然后判定：含树操作（新建、改名、移动、排序、删除，M8 的恢复）的单元取 `FOR NO KEY UPDATE`，在同一笔记本内串行；只改正文与开启会话的取 `FOR SHARE`，彼此不挡。按页面或会话寻址的，先不加锁读出所属的笔记本与工作区，锁住之后重读，锁的语句带 `deleted_at IS NULL`。节点与跟随它的行接在 `notebooks → notebook_members` 之后。例外：心跳与结束是只碰本人会话行的单条语句，判定按读、不取工作区行与笔记本行（13.1 第 5 条"其余"），失去编辑权限之后心跳失败，会话在一个租约之内过期；过期会话的清理用 `SKIP LOCKED`。修订总体设计 8.3、13.1 第 5 条 | 只锁笔记本行（M3 第 8 节原来的写法）：判定读的工作区成员关系与角色不在锁下，移出工作区或降为访客与他的页面写交错时，写在移出提交之后才提交；锁父节点与祖先链防环：并发的移动要锁住整条祖先链，祖先链在锁前读出又可能变 |
| 一页之内的行锁 | 正文的写与会话的开启以 `FOR NO KEY UPDATE` 锁这一页的正文行（一页的闸门），比较 `base_revision` 与写入都在它之下；带会话的写随后以 `FOR UPDATE` 锁本人的会话行（设变更集、记本会话上次写出的 `revision`）。次序：`nodes → page_contents → edit_sessions`；正文的写不碰节点行。M5 开启会话的否决者在正文行的锁下判断"别人有没有活着的会话"，两个开启不会都通过 | 只靠 `FOR SHARE` 的笔记本行：两个开启、两次保存都不互斥 |
| 树操作在笔记本内串行 | 防环（A 移到 B 下与 B 移到 A 下）、层级上限（移动把子树推深与在子树底部新建）、删除子树与在其中新建，都靠笔记本行的独占锁在锁下判断；正文的写与它互斥，只在树操作的几毫秒内等待 | 只串行移动（总体设计 8.3 原文）：新建与删除同样改变层级与可达性 |
| 标题键 | `shared.TitleKey(s) = NFC(fold(NFC(s)))`，完整的大小写折叠用 `golang.org/x/text/cases.Fold`；M6 的链接解析用同一个函数。键存在 `nodes.name_key`（`COLLATE "C"`），唯一索引 `(notebook_id, parent_id, name_key) NULLS NOT DISTINCT WHERE deleted_at IS NULL`（根下的页面 `parent_id` 为空，也要唯一）。`shared` 的依赖加上 `x/text/cases`，修订 13.1 第 12 条 | 数据库的 `lower()` 或 ICU 排序规则：随 locale 变化，3.5 已定由应用计算 |
| 父页的约束 | 父页必须在同一个笔记本：复合外键 `(notebook_id, parent_id) → nodes (notebook_id, id)`，由数据库守住；自引用外键 `RESTRICT`。层级与防环在应用里、锁下判断 | 只在应用里检查：缺陷会造出跨笔记本的子树，权限按笔记本判定，后果是泄露 |
| 次序 | `sort_order` 是浮点数。接口不收次序值，收位置：`after_id`（放在这个兄弟之后；`null` 为最前，省略为最后）；服务端在锁下取前后两个兄弟的中间值，间隔小于阈值时在同一事务里把这一组兄弟重新均匀编号。重排不记条目：M8 判断"当前状态仍是这个变更集写的"时比较父页、标题与相对位置（排在哪个兄弟之后），不比较原始的次序值 | 接口直接收浮点数：客户端的取值与并发的插入相撞；字符串的分数索引（lexorank）：v0.1 的树写都在笔记本锁下，浮点数加重排足够 |
| 新页面的标题 | 接口的 `title` 必填，重名答 409 `page.title_taken`。网页的"新建页面"在已加载的页面树上取界面语言的"未命名"、"未命名 2"……中第一个空着的，409 时取下一个再试（至多三次）。修订总体设计 3.5 | 服务端在缺省时起名：服务端不知道界面语言，给英文界面的人起中文名；对接口与 agent 静默加序号又出乎意料 |
| 变更集 | 每个写入单元属于一个变更集：REST 的单次写入自成一个；带 `edit_session_id` 的写入属于会话的变更集（会话的第一次写入时创建）。变更集记笔记本、类型（M4 只有 `edit`）、客户端、可选的说明、执行者、时刻；每个（变更集、节点）一行条目，记树的前后状态（父页、标题、次序；新建与删除的标记），同一变更集里同一节点的多次操作合并为最早的"前"与最新的"后"；正文的版本另记在 `page_revisions`，每个（变更集、页面）一行，记所依据的 `base_revision` 与写出的 `revision`，会话里的再次保存更新这一行。会话两次保存之间夹进了别人的写（M5 有锁之前，或"保留我的"覆盖），这一页当前的 `revision` 已不是本会话上次写出的：会话的下一次保存另起一个变更集，每个版本行的"前"与"后"之间因此没有别人的改动 | 每次保存一个版本：自动保存（M5）之后一次编辑会产生几十个版本；夹进别人的写时仍原地更新：版本不再单调，M8 的 diff 与撤销失去依据 |
| 客户端字段 | 适配器决定客户端，用例只记录：HTTP 一侧按凭证，会话的访问令牌是 `web`，PAT 是 `api`；M9 的 MCP 适配器给 `mcp:<客户端名>`，命令行给 `cli`。值是写入单元的字段，不进 `Actor` | 前端在请求头里自报：任何调用方都能冒充 |
| 正文 | `page_contents` 一页一行：原样的 `content`、`revision`（新建为 1，每次写入加 1）、`content_hash`（SHA-256）、`byte_size`。必须是合法的 UTF-8、不含 NUL（PostgreSQL 的 `text` 存不了），不超过 5 MiB（5,242,880 字节，422 `content`）；大小与 NUL 在事务之前、`Parse` 之前检查。正文写入与带正文的新建两个路由放宽请求体上限（按 5 MiB 正文在 JSON 里最坏的转义长度；模块根的 `BodyLimits()`，与 `RequestTimeouts()` 并列，平台在配置校验里核对），期限另加 `server.read_timeout`，给请求体传完的时间（P4 审查 P3）；JSON 里孤立的代理项（`\ud800`）答 400，不被换成 U+FFFD。`base_revision` 不一致答 409 `page.revision_mismatch`，客户端重新读取正文得到当前版本（第 2 节） | 以 `text/markdown` 原样传正文、`If-Match` 带版本：与其余接口不一致，412 也不是总体设计定的 409 |
| 编辑会话 | `edit_sessions`：页面、笔记本、账户、客户端、变更集（第一次写入时设上）、本会话上次写出的 `revision`、开始时刻、`expires_at`。开启要求编辑权限；租约 60 秒，心跳每 20 秒把 `expires_at` 推到当前加 60 秒（3.9 的数字，原定 M5，挪到 M4：会话的生死决定变更集在哪里结束，M4 没有它就只能靠一个随意的空闲期限）；前后端各有一份常量，注释互指、各有测试钉住（13.1 第 15 条）。结束即删除行。码按服务端分得清的情况：带会话的正文写，会话没有、已过期、是别人的、别的客户端开启的或别的页的，一律 409 `page.edit_session_ended`（同一个码，问不出会话属于谁；客户端要相同，变更集才记得对写的客户端，P4 审查 D1）；心跳与结束（会话在地址里），没有、已过期、是别人的，一律 404 `page.edit_session_not_found`；编辑器把这两个码都当作"重开会话"，结束答 404 当作已结束。会话的结束经各条路径调用同一组订阅者，值里带原因：本人结束、页面被删除（删页、删子树、删笔记本）；M5 加强制解锁。过期不是事件（是否活着按 `expires_at` 判断），定时清理不调用订阅者。M4 的会话彼此不排他，M5 在开启的否决者与写入守卫上加锁；M11 的冻结同样可以否决开启。修订 3.9、12.2 的 M4、M5 两行与 12.4 | 会话在 M4 只有显式结束：关掉标签页的会话永远开着，变更集也不结束 |
| 解析时机 | 正文写入在开启事务之前、不加锁的判定之后调用一次 `Parse`（总体设计 4.3：提取不在持锁期间；判定在前，只有能写的人让服务端解析），同时解析、渲染的正文字节数受全局的解析预算约束（`page.parse_budget_bytes`，取不到答 503 `server_busy`，阅读视图同样；P4 审查 P1、P2），解析结果随页面领域事件交给观察者，M6 的索引与 M10 的模式不变量在事务里只用它；读取阅读视图时再调用同一个 `Parse` 并渲染，不缓存 HTML。解析结果在页面的 `app` 里是不透明的值，交给别的模块的注册者时在组合根转换（13.1 第 11 条的做法） | 订阅者在事务里自己解析：5 MB 的页面持锁数百毫秒 |
| 渲染与清洗 | goldmark（CommonMark + GFM + 脚注）的语法树渲染成 HTML。用户写的原始 HTML（HTML 块与行内 HTML）每个节点单独经排版类的白名单清洗（`x/net/html` 的分词器上自己的白名单：bluemonday 不配平、不挡 `//host`、保留 `img`，P3 实测）：去掉 `id`、`class`、`style`、`data-*` 与事件属性；不放行 `img`（外部图片的决定同样适用）；用户在一个叶子块里打开的行内元素在这个块结束时补上闭合，没闭合的 `<a>`、`<b>` 不会被 HTML 解析器重建进后面的块、包住渲染器的标记。渲染器自己的标记（标题与脚注的 id 带固定前缀、代码块的语言 class、任务项、属性表）在清洗之外生成。所有地址（用户 HTML、Markdown 链接与图片、扩展的输出）经同一份白名单：`http`、`https`、`mailto` 与本站的相对地址；按解析出的主机判断，`//host`、`/\host` 算外站（样例集规则 8）。代码块输出 `language-*` 的 class，高亮在前端：P5 的交互增强在 Web Worker 里运行 highlight.js，超时即终止，代码照常显示、只是不着色（负责人确认；chroma 普通代码只有 0.2–1 MB/s，回溯的正则几十字节就让一次匹配卡到 250 ms 的超时，过不了"耗时预算"一行）。测试期的不变量：按词元读一遍最终的 HTML，只许出现白名单与渲染器（含已注册扩展）的标记，地址都经白名单，结束标签关闭最内层开着的元素；HTML 不超过正文的 64 倍加 4 MiB；随样例集、耗时模糊测试与每个注册的扩展一起跑 | 整页 HTML 一次清洗：要么删掉渲染器的标记，要么放过用户伪造的同名标记 |
| 外部图片 | 正文里指向外站的图片渲染为链接（显示替代文字与地址），不加载；页面 CSP 的 `img-src` 保持本站，附件里的图片（M7）照常内联（负责人确认，2026-10-02）。相对地址的图片在 M7 之前同样渲染为链接（否则会去取 `index.html`）；`data:` 的图片不放行。修订总体设计 4.6 | 允许加载：放宽 CSP，任何能写正文的人（含 agent 抓来的来源）都能埋跟踪像素，看到谁在什么时候读了这页 |
| frontmatter | 按样例集的规则（YAML 1.2 core schema，别名展开）解析，渲染成正文之上的属性表；解析失败或不是映射时不显示（4.2）。别名展开之后的节点数、嵌套深度与别名重复的字节数设上限，超出按解析失败处理，别名炸弹与被重复几千次的长值都不会让写入前的解析与每次阅读爆炸 | 不设上限：写一行别名就能让每次阅读耗尽内存 |
| 耗时预算 | 渲染（解析 + 渲染 + 清洗）与写入前的解析各定一个按字节的预算（P3 实测后定数，如 5 MB 不超过 1 秒），由基准测试守住；耗时模糊测试生成深层嵌套、超长行、大量未闭合的括号与强调符号、YAML 的别名与深层嵌套，单篇的耗时与分配不超过同样大小的普通文档的若干倍、输出的字节数不超过正文的若干倍，超出即失败，并修到满足（例如限制嵌套深度，超出的部分按文字显示） | 只做基准：病态输入的退化正是要防的 |
| 编辑器的字节保真 | CodeMirror 照默认把 `\r\n`、`\r`、`\n` 都当作换行，取文本时一律写成 `\n`，CRLF 的页面改一个字就整篇变了。编辑器另用一个随改动映射的状态记下每个换行原来的写法与开头的 BOM，保存时按记下的写法拼回；新插入的换行（回车、列表续行、粘贴）用文档里最多的那种。编辑时没有看不见的字符：光标不会落在隐藏的 `\r` 之后，行首退格删掉的是整个换行，BOM 不在文档里、不会被挤到字的后面。修订总体设计 9.3 | 以 `\n` 为唯一的行分隔符、`\r` 与 BOM 作为隐藏的字符：行尾打字落在 `\r` 之后，退格留下孤立的 `\r`，`Ctrl+Home` 把字插到 BOM 之前 |
| 前端的页面数据 | 一个笔记本的页面树每代按笔记本 id 一个 store（`RootStore.pagesOf(notebook)`，SWR 键 `["pages", notebook.id]`）；一页的阅读视图与正文按页面 id（`["page-view", id]`、`["page-content", id]`）。树结构的写（新建、改名、移动、删除）在一个笔记本里走同一个队列（store 的 `oneAtATime`），每次答复之后重读整棵树：不同节点的写互相改变位置，答复可能乱序到达，客户端不自己推算次序。页面挂在 `/:slug/notebooks/:id/pages/:pageId`，由笔记本的外壳渲染，左栏的页面树按笔记本 id 重新挂载（13.2 第 16 条）；页面的外壳在树里找到它才显示，删除之后去父页或笔记本首页（与工作区、笔记本相同的 `wasRemoved`）。编辑模式不进地址：刷新回到阅读视图（3.9） | 同一节点的写各自排队（`oneAtATimeById`）、按答复套用位置：顺序可以与服务端分叉 |
| 拖拽 | `@atlaskit/pragmatic-drag-and-drop`（与 Nerve 相同）加它的树形命中区（放在前、放在后、成为子页）；拖拽不是唯一的方式：每一项的菜单有"移动到…"（选父页与位置的对话框，键盘可用），满足 WCAG 2.2 的 2.5.7 | dnd-kit：树形要自己写命中区；只有拖拽：键盘与单指针用户做不了 |
| 未保存的修改 | M4 没有自动保存：编辑器有未保存的修改时，离开页面（路由内用 React Router 的 `useBlocker`，关标签页用 `beforeunload`）先提醒；退出编辑模式先保存 | 无提醒：关掉就丢 |
| 保存冲突 | 409 时编辑器保留用户的文字，读出当前正文，显示差异（`@codemirror/merge`，随编辑器分包按需加载），可以"保留我的"（以差异所依据的那次读取的 `revision` 为 `base_revision` 再存，其间又有别人写就再次 409）或"放弃我的"（载入当前正文）。M5 有锁之后冲突只来自接口的写 | 只提示"有冲突，请刷新"：用户的修改要自己复制出来；"保留我的"取 409 时的版本号：其后到读取之间的第三次写会被静默覆盖 |
| 编辑器分包 | 先评估：只用 `@lezer/markdown` 与 `lang-markdown` 的命令（列表续行），不调用会带进 `lang-html` 的 `markdown()`，靠 tree-shaking 去掉 HTML、CSS、JS 的语言包；代码块里的嵌套高亮放弃。P6 量出前后的体积写进结果，选小的那个，除非它丢掉了第 1 节的某项功能 | 不评估，接受 528 KB：编辑器每次进入编辑模式都要下载 |
| 日志 | 页面的用例只记 `workspace_id`、`notebook_id`、`node_id`（会话另记 `edit_session_id`、变更集 `changeset_id`）与不含个人信息的取值（操作的种类、`revision`、客户端）；标题与正文不进日志，与笔记本名称同理（13.1 第 10 条）。每个写用例的日志测试核对 id 在、标题不在 | 记标题便于排查：私密笔记本里的标题与名称一样是私密的 |

### 页面的表与它们的生命周期

| 表 | `deleted_at` | 由谁设 | 读取 | 清理 |
|---|---|---|---|---|
| `nodes` | 有 | 删除子树（同一时刻）、笔记本删除（事件的时刻） | 树与页面只读未删的 | 清理器在一次调用里反复执行"删叶子"的语句（`NOT EXISTS` 任何子节点，不论是否删除），每条语句各自提交、看得见前一条的删除，直到某条删不出或凑满一批；所以一本已删笔记本的多层页面树一次运行就清完，notebook 的清理器不会因外键失败 |
| `page_contents` | 有 | 随节点（同一时刻） | 只读未删的 | 自己的清理器，排在 `nodes` 之前 |
| `page_revisions` | 有 | 随节点 | 历史（M8）不按它过滤：它只标出清理的时刻，回收站里的页面照样有历史；M8 恢复时与节点一起清空 | 同上 |
| `changeset_items` | 有 | 随节点，包括删除它的那个变更集里的条目 | 同上（M8 的日志看得到这次删除） | 同上 |
| `changesets` | 有 | 笔记本删除（事件的时刻） | 日志按笔记本 | 只删已没有条目与版本的（`NOT EXISTS`），排在 notebook 的清理器之前；活着的笔记本里的变更集不删 |
| `edit_sessions` | 无（运行时的状态） | 结束、删页、删子树、删笔记本时在同一事务里删行 | 活着的会话 | 不进清理注册表，也不建外键：它的行在节点软删除的同一事务里删掉，从不指向已删的节点；建外键会让清理先后的测试要求它登记清理器，而清理器的表必须有 `deleted_at`。过期而未结束的由 page 模块的定时任务删除（`SKIP LOCKED`，`Jobs()` 与配置项，照 identity 的会话清理） |

- 有 `deleted_at` 的五张表各有部分索引 `(deleted_at) WHERE deleted_at IS NOT NULL`：清理不必扫最大的版本表与条目表。`nodes` 另有不带条件的 `(notebook_id, parent_id)` 索引，供"删叶子"的 `NOT EXISTS` 与自引用、复合外键的检查。
- 页面树的不变量（交错与级联的测试结束时核对，`checkPages`）：无环；层级不超过 10；未删的节点的父页未删、在同一笔记本；未删的兄弟标题键唯一；每个未删的页面恰有一行未删的正文，它的 `revision` 等于这一页最新的版本行写出的 `revision`；没有指向已删节点的会话。

## 5. 接口

新增 12 个操作，都在 `api/modules/page.yaml`：

| 方法与路径 | 认证 | 成功响应 |
|---|---|---|
| `GET /api/v0/notebooks/{notebook_id}/nodes` | Bearer | 200 `{data: TreeNode[]}`（整棵树，先序：父在子前，兄弟按次序） |
| `POST /api/v0/notebooks/{notebook_id}/pages` | Bearer | 201 `Page`（`parent_id`、`title`、`after_id`、可选的 `content`） |
| `GET /api/v0/pages/{page_id}` | Bearer | 200 `Page` |
| `PATCH /api/v0/nodes/{node_id}` | Bearer | 200 `TreeNode`（`name`） |
| `POST /api/v0/nodes/{node_id}/move` | Bearer | 200 `TreeNode`（`parent_id`、`after_id`；同一父页内即排序） |
| `DELETE /api/v0/nodes/{node_id}` | Bearer | 204（整棵子树） |
| `GET /api/v0/pages/{page_id}/content` | Bearer | 200 `PageContent`（`content`、`revision`、`content_hash`） |
| `PUT /api/v0/pages/{page_id}/content` | Bearer | 200 `Page`（整篇替换：`content`、`base_revision`、可选的 `edit_session_id`） |
| `GET /api/v0/pages/{page_id}/view` | Bearer | 200 `PageView`（`html`、`revision`） |
| `POST /api/v0/pages/{page_id}/edit-sessions` | Bearer | 201 `EditSession`（`id`、`page_id`、`expires_at`） |
| `POST /api/v0/edit-sessions/{edit_session_id}/heartbeat` | Bearer | 200 `EditSession` |
| `DELETE /api/v0/edit-sessions/{edit_session_id}` | Bearer | 204（删除行：会话不是软删除，6.1 的例外） |

- **结构**：
  - `TreeNode`：`id`、`notebook_id`、`parent_id`、`kind`（M4 只有 `page`）、`name`、`created_at`、`updated_at`（不叫 `Node`：生成的 TS 根类型会与 DOM 的 `Node` 同名）。
  - `Page`：`TreeNode` 的字段，加上 `ancestors`（从根到父页的 `{id, name}`，路径由它推算）、`revision`、`byte_size`、正文最后写入的时刻与执行者（id）。
- **权限**：读（树、页面、正文、阅读视图）给笔记本的三种角色；写（新建、改名、移动、删除、正文、开启会话、心跳）给编辑者与管理员；结束只要求会话是本人的。
- **模块码**：

  | 码 | 状态 |
  |---|---|
  | `page.not_found` | 404（地址里的页面与节点） |
  | `page.edit_session_not_found` | 404（地址里的会话：没有、已过期、是别人的） |
  | `page.title_taken` | 409 |
  | `page.cycle` | 409 |
  | `page.too_deep` | 409 |
  | `page.revision_mismatch` | 409 |
  | `page.edit_session_ended` | 409（请求体里的会话不可用：没有、已过期、是别人的或别的页的） |

  另外：
  - 父页、`after_id` 不是这个笔记本里未删除的节点，或 `after_id` 不是 `parent_id` 的子节点，是请求的取值问题：422，字段 `parent_id`、`after_id`（`not_allowed`）。
  - 标题不合规则是 `title` 或 `name` 的字段错误；正文不合法（非 UTF-8 由边界答 400；含 NUL、超过 5 MB）是 `content` 的字段错误。
  - 看不到笔记本的，按地址里点名的东西答：地址是笔记本的（`listNodes`、`createPage`）答 `notebook.not_found`，是页面或节点的答 `page.not_found`，是会话的答 `page.edit_session_not_found`；与不存在、已删除相同（13.1 第 4 条；notebook 对按 slug 寻址的操作答 `workspace.not_found` 是先例）。
  - **码的次序**：正文的取值（大小、NUL）在事务与 `Parse` 之前检查，它的 422 先于 404、403：与资源无关，答复问不出资源是否存在，照游标的先例（修订 13.1 第 4 条）。解析预算的 503 `server_busy` 在 404、403 之后、其余的码之前（P4）。写入守卫在领域的检查之后、写入之前：它要看算好的"之后"状态，所以它的码排在领域的码之后（P1 实现时改定，原写"守卫在领域校验之前"）。
  - 每个后端 Phase 给契约里新出现的码同步加中英文案。
- **限流**：不加新的桶。

## 6. 从 Nerve 拷贝的范围

## 7. Phase 划分

每个 Phase 按[文档约定](../../README.md)执行：写 Phase 文档 → 实现 → 测试 → 审查 → 修复 → 合并。M4 是最大的 M（总体设计第 15 节 2026-09-30 的记录），后端四个、前端两个 Phase。

## 8. 本 M 建立的扩展点与约定

**页面领域事件与写入单元的参与者**（观察者：M5 的 `NOTIFY` 推送、M6 的链接索引；参与者：M6 的链接改写）：

- 事件的值：笔记本、变更集、执行者、客户端、写入选项、时刻，以及单元里改动的节点（每个节点：新建、改名、移动、删除、正文；树的前后状态；正文的新 `revision` 与解析结果）。一个写入单元一次（3.11：每个事务最多一条 `NOTIFY`）。
- 参与者在单元的每个操作之后被调用，可以经单元追加正文写（第 4 节"写入单元"）；观察者在单元结束时被调用（13.1 第 21 条的订阅者），错误整体回滚。
- M4 没有注册者，组合根交空集合；模块根的测试证明两者经 `Deps` 到达写入单元（每个写用例共用同一个单元）。

**写入守卫**（M5：编辑锁；M10：模式不变量；M11：冻结与护栏）：

- 单元里的每个操作在锁与判定、领域的检查（422 与 409）之后、写入之前同步调用；返回 `*shared.Error` 时整个单元回滚并答出它的码（守卫的码由注册的 M 写进被守卫的操作的 `x-problem-codes`）。参与者追加的写同样经过守卫：M5 因改写目标被别人锁住而拒绝，不因被移动的页本身被锁而拒绝（3.5）。
- 值：笔记本、执行者、客户端、编辑会话（有时）、操作的种类、每个涉及节点的前后状态（与变更集条目同形：父页、标题、次序、新建与删除；移动与删除是整棵子树）、正文写入时的解析结果。

**编辑会话**（M5：锁；M11：冻结）：

- 开启时的否决者（在正文行的锁下调用；M5：别人有活着的会话时拒绝，答 `page.locked`；M11：冻结期间拒绝）与结束时的订阅者（值里带原因：本人结束、页面被删除，M5 加强制解锁；M5 据此推送锁的变化）。会话的租约、心跳、结束与过期是 M4 的。
- 收尾时写进给 M5 的移交（P4 审查 Q1–Q4）：结束的订阅者持着会话的行锁被调用，不得再锁 `page_contents`、`nodes`，强制解锁先取正文行再删会话；与当前正文相同的保存不经守卫；被移出或降级的人的会话一个租约之内过期，不告诉订阅者；会话的时刻取应用的时钟。

**变更集的客户端字段**（M9：`mcp:<客户端名>`）：适配器写进写入单元，用例只记录（第 4 节）。

**Markdown 解析与渲染扩展**（M5：任务项的字节位置；M6：Obsidian 方言；M7：附件嵌入）：

- `platform/markdown` 的扩展带 goldmark 的解析器与渲染器选项、从语法树取提取结果的一步，以及"按页取数据"的一步：读取阅读视图时，在渲染之前按笔记本、页面与解析结果取它自己的数据（M6 按字节位置取链接的解析状态，M7 取签名地址），结果只交给它自己的渲染器；这一步在调用方的读取里执行、不加锁。组合根把注册的扩展交给 `markdown.New`，页面与 M6 的 linking 用同一个实例；提取与渲染都经它，一致性由架构保证（4.3）。
- 扩展的标记不经用户 HTML 的清洗，它的地址经同一份白名单；最终 HTML 的不变量测试对每个注册的扩展一起跑（第 4 节"渲染与清洗"）。

**阅读视图的交互增强**（前端；M4：代码高亮（P5）；M5：任务复选框；M6：链接跳转、KaTeX、mermaid）：按注册顺序在服务端 HTML 挂上之后运行，拿到容器元素与页面的上下文（工作区、笔记本、页面 id、`revision`、调用者的角色、重新读取阅读视图的方法），每个返回自己的清理函数，HTML 换掉时先清理再重跑。

**编辑器扩展管线**（前端；M5：只读与自动保存；M6：补全；M7：粘贴上传）：每个扩展由页面的上下文与编辑器的控制（保存、会话的状态、只读的切换）构造出一组 CodeMirror 扩展，放在自己的 `Compartment` 里，按注册顺序组合，可以单独换掉或卸下。

**最后一跳的测试**：本 M 建立、却没有注册者的扩展点，组合根交空集合，整个程序上的行为测试写进第一个注册者所在 M 的移交（13.1 第 21 条），M4 收尾时写：页面领域事件（M5、M6）、写入单元的参与者（M6）、写入守卫（M5）、编辑会话的否决者与订阅者（M5）、客户端字段（M9）、解析与渲染扩展（M5、M6、M7）、编辑器扩展管线（M5、M6、M7）；阅读视图的交互增强在 M4 已有代码高亮这个注册者，它的整个程序测试在 P5。

**注册 M2、M3 的扩展点**：

- 笔记本删除：以事件的时刻软删除这些笔记本的节点、跟随的行与变更集（P1），删除它们的编辑会话（P4）。
- 清理注册表：页面的表，叶在前（P1）。
- 笔记本的活动：正文的字节数与最后写入（P4）。
- 权限规则表：页面的操作（P1、P2、P4）。

**全局加锁顺序**（修订总体设计 8.3、13.1 第 5 条）：

- 页面一支接在笔记本之后：`workspaces（FOR SHARE）→ notebooks → nodes → page_contents → edit_sessions`，变更集、条目与版本只插入或只改本单元自己的行。含树操作的单元持笔记本行 `FOR NO KEY UPDATE`，只改正文与开启会话的持 `FOR SHARE`。
- 笔记本删除与工作区删除的页面注册者已持笔记本行的独占锁，直接写节点。
- 页面的写不取账户行（不让账户获得新的访问），也不改成员行，M3 的 `LockHoldings` 推理不变。

**横切约定**：本 M 新建的约定（页面一支的加锁、写入单元、标题键、变更集与客户端、解析时机、渲染器标记与用户 HTML 的分界、编辑器的换行记录、按笔记本的页面 store 与树写的队列）在收尾审查对照代码之后补进总体设计第 13 节。P1 留下的：第 6 条"有自引用外键的表另写测试"点名 `TestPurgeSkipsAHeldNodeAndKeepsItsAncestors`；第 11 条的窄端口例子加 `notebook.NewNotebooks`；第 21 条的组合改为 `notebookRegistrants(pool)`、`pageRegistrants()`，注册者的例子加 `page.NewNotebookDeletion`，"两个注册者的测试"引用 `TestTheRegistrantsRunInTheirOrder`（P1 审查 D11）。P4 留下的：第 19 条的并发名额加上正文的解析预算（判定之后、按字节、取不到答 503），"事务之前"的例子加上"判定之后才做昂贵的事"。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 规模：12 个操作、14 个故事、8 个新扩展点，前端有树、拖拽与编辑器 | 在 12.1 第 4 条的上限之内；六个 Phase 各自可验证，后端四个在前 |
| 渲染安全：用户 HTML 或扩展的输出绕过清洗 | 用户 HTML 逐节点清洗并补闭合、渲染器标记在清洗之外；清洗与地址白名单的表格测试；最终 HTML 的不变量对每个扩展一起跑；页面 CSP 不放行内联脚本与外站请求，PG6 断言没有违规 |
| 病态输入让渲染或写入前的解析耗时暴涨（P3 实测：goldmark 在强调、链接目标、原始 HTML、自动链接、容器嵌套上平方级，200 KB 就到秒级） | 耗时预算与耗时模糊测试（第 4 节），含 YAML 的别名，超出即修；P3 替换或包住平方级的部件，结果与原版逐字节相同，只多四条上限：容器（含脚注定义）与内联链接目标括号的嵌套、表格的单元格不多于字节数、引用式链接的展开预算；代码高亮移到前端的 Worker |
| 字节保真：编辑器或传输改了没碰到的字节 | 编辑器的换行与 BOM 记录（第 4 节）；JSON 的孤立代理项答 400；PG9 与集成测试的往返 |
| 每次页面写都以 `FOR SHARE` 锁工作区行与笔记本行：多个持有者形成 MultiXact；一行只被共享锁住时，PostgreSQL 立即授予新的 `FOR SHARE`，持续的正文写可能让排队的树写、成员变更、工作区改名反复等待（审查者的推理，未复现） | 团队规模的写入频率下共享锁的占用很低；心跳与结束不取这两行；M12 的性能实测包含"N 个编辑者自动保存时树写的延迟"与 MultiXact 的开销 |
| 最大正文的解析与渲染占内存（病态的 5 MiB 约 1.5 GB 堆，P4 审查实测） | 判定之后才解析；按字节的全局解析预算（默认 8 MiB，最坏约 2.4 GB），取不到答 503；写入等锁时占着预算，一页的锁争用可能让别处的大页面阅读视图 503（P4 第 7 节），M12 的压测包含大页面的并发阅读与保存 |
| 浮点次序在同一位置反复插入后耗尽精度 | 间隔小于阈值时重排这一组兄弟，单元测试覆盖连续插入 |
| 浏览器对后台标签页的计时器节流（Chrome 对隐藏超过 5 分钟的页面，链式计时器约每分钟唤醒一次），心跳赶不上 60 秒的租约，会话过期 | M4 靠重开会话恢复（PG10），变更集被拆成两个；P6 写明；M5 有锁之后锁会被别人拿走，留给 M5 考虑按页面可见性调整心跳或租约（写进给 M5 的移交） |
| 大笔记本一次加载整棵树 | 沿用总体设计第 14 节：M12 实测，不达标时改为分层加载 |
| 真实输入法只能人工验证 | 清单写进 P6，负责人执行；Chromium 上的模拟组合输入进 e2e；M5 补验自动保存的部分 |
