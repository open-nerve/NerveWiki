# M4/P3/S1 病态输入的加固：实施计划

上级：[P3 文档](../03-P3-markdown.md) 第 1 节、3.4。

## 任务

1. 依赖：`github.com/yuin/goldmark v1.8.6` 加进 `server/go.mod`（精确版本），`go mod tidy`。
2. `internal/platform/markdown/internal/harden`：
   - `parser.go`：`NewParser(opts ...parser.Option) parser.Parser`：goldmark 的默认块解析器（引用块、列表、列表项包上嵌套上限）、默认行内解析器去掉强调与链接、加上替换件与包装件；段落转换用自己的链接引用定义；脚注、表格、任务列表、GFM 自动链接（包装过的）、删除线（游程）的渲染器由 S3 组装。
   - `emphasis.go`：游程的行内解析器（`*`、`_`、`~`，`~` 超过两个或前一个字符也是 `~` 时不算，同 goldmark）；语法树转换按作用域配对，`openers_bottom` 按（字符、闭合符能否开启、原长模 3）记，位置用游程的序号；余下的游程合成文字。
   - `links.go`：改编自 goldmark 的 `parser/link.go`（文件头写来源、MIT 许可与版权人）：目标的括号上限 32；`<…>` 查块内的索引；标签取值二分查找起始行；链接计数代替 `containsLink`；块结束时把余下的括号状态换回文字（实现：计数不清零，比较标签打开时的计数，见 P3 文档第 7 节）；导出"在链接标签里"给自动链接的包装件用。
   - `refdefs.go`：链接引用定义的段落转换（同上改编），一次读完开头的定义、只设一次余下的行。
   - `footnotes.go`：脚注的块解析器、行内解析器、收尾的语法树转换（同上改编）：定义按标签进表、引用查表、按序号排序一次；节点类型用 goldmark 的 `extension/ast`。
   - `guards.go`：块内的索引（反引号串、`-->`、`?>`、`>`、`]]>`、电子邮件字符串、未转义的 `>`），按块缓存在解析上下文里；代码段与原始 HTML 的前置检查；自动链接的包装件；容器的嵌套上限（32）。
3. 只用 goldmark 导出的接口；不进 goldmark 的分隔符表（包注释写明，给 M6 的约束）。

## 测试

- 核对：从模块缓存里 goldmark 的目录（`go list -m -f '{{.Dir}}'`）读 `_test/spec.json` 与 `extension/_test/*.txt`，每个例子在加固配置与原版配置（`goldmark.New` 加 GFM 与脚注）上的输出逐字节相同；固定种子的随机输入（记号表含强调、链接、图片、代码段、原始 HTML、自动链接、电子邮件、脚注、引用定义、表格、列表、引用块、转义、实体、换行）五万个，两边逐字节相同。
- 上限：32 层的引用与列表照常，33 层的那一行是文字；32 层括号的目标是链接，33 层不是。
- 每个部件的边界：不同长度的反引号串不算结束、转义的 `>` 不结束 `<…>`、`[a [b](c)](d)` 外层不成链接、跨块不串计数、`a@b.c` 与 `a.b` 的自动链接、`*[a*](b)` 不跨进链接、脚注的重复引用与未用的定义、引用定义之后接段落。
- 耗时：第 1 节表格的每一类，128 KB 与 256 KB 两种大小的耗时之比不超过 3（线性的增长在 2 左右），且不超过同样大小的普通文档的 10 倍；不带竞态检测时才断言（S4 再收进统一的测试）。
- 反向对照：配对不分作用域；去掉 `openers_bottom`；目标不限括号；不计数（实现时的反向对照，计数本就不清零）；反引号的检查不比长度；嵌套上限不检查。
